Lab 8: Safe file backup

Build a Backup-File function that copies a file with a timestamp, catches failures and writes them to a log.

Lab 8Intermediate~45 min

Tasks

Task 1

Copy a file with a timestamp

powershell · backup.ps1
function Backup-File {
    param(
        [Parameter(Mandatory)][string]$Path,
        [string]$Destination = 'backup'
    )
    if (-not (Test-Path $Destination)) {
        New-Item -ItemType Directory -Path $Destination | Out-Null
    }
    $file    = Get-Item -Path $Path
    $stamp   = Get-Date -Format 'yyyyMMdd-HHmmss'
    $newName = '{0}_{1}{2}' -f $file.BaseName, $stamp, $file.Extension
    Copy-Item -Path $file.FullName -Destination (Join-Path $Destination $newName)
    Write-Host "Backed up $($file.Name) -> $Destination/$newName" -ForegroundColor Green
}

Backup-File datasets/app.log
output · sample, yours will differ
Backed up app.log -> backup/app_20261117-101530.log

BaseName is the name without the extension (app) and Extension is .log. The timestamp makes every copy unique.

Task 2

A missing file: try alone does not catch it

powershell · console
try {
    Copy-Item datasets/nope.txt backup/
    "Still running after the error"
}
catch {
    "Caught it!"
}
output · sample, yours will differ
Copy-Item: Cannot find path '/home/you/unit5/datasets/nope.txt' because it does not exist.
Still running after the error

Most cmdlet errors are non-terminating: they print in red and the script carries on, so catch never runs.

powershell · console
try {
    Copy-Item datasets/nope.txt backup/ -ErrorAction Stop
    "Still running after the error"
}
catch {
    "Caught it: $($_.Exception.Message)"
}
output · sample, yours will differ
Caught it: Cannot find path '/home/you/unit5/datasets/nope.txt' because it does not exist.

-ErrorAction Stop turns the error into a terminating one, so control jumps to catch. Inside catch, $_ is the error.

Task 3

Add try / catch / finally to Backup-File

Replace the body of the function in backup.ps1 with this.

powershell · backup.ps1 (updated body)
    try {
        if (-not (Test-Path $Destination)) {
            New-Item -ItemType Directory -Path $Destination -ErrorAction Stop | Out-Null
        }
        $file    = Get-Item -Path $Path -ErrorAction Stop
        $stamp   = Get-Date -Format 'yyyyMMdd-HHmmss'
        $newName = '{0}_{1}{2}' -f $file.BaseName, $stamp, $file.Extension
        Copy-Item -Path $file.FullName -Destination (Join-Path $Destination $newName) -ErrorAction Stop
        Write-Host "Backed up $($file.Name) -> $Destination/$newName" -ForegroundColor Green
    }
    catch {
        Write-Host "Backup failed: $($_.Exception.Message)" -ForegroundColor Red
    }
    finally {
        Write-Host "Done: $Path"
    }
powershell · console
. ./backup.ps1
Backup-File datasets/config.json
Backup-File datasets/nope.txt

finally runs every time, whether the copy worked or failed.

Viva questions

What is the difference between terminating and non-terminating errors?

A terminating error stops the current block and can be caught by catch. A non-terminating error is printed and the command carries on.

Why do we add -ErrorAction Stop?

It makes a non-terminating error terminating, so try/catch can handle it.

When does finally run?

Always: after try succeeds, and after catch handles an error. Use it for clean-up or a closing message.

What is $Error?

An automatic list of recent errors in the session. $Error[0] is the latest one.
