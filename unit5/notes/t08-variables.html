Variables

A variable is a named box that stores a value. In PowerShell every variable name starts with $.

Topic 08~25 min
Before this:F5 Objects06 Writing scripts
Key idea

$name = value stores anything: a number, text, a date, even a whole CSV file. PowerShell picks the type for you, but you can force one with [int], [string] and so on.

Create and use

powershell
$name  = "Aarav"
$marks = 92
$name
$marks + 5
output
Aarav
97
Naming ruleExample
Starts with $$total
Letters, digits, _ are safe$max_marks2
Not case-sensitive$Name is the same as $name
No spaces or dashes (unless in ${ })${my var} works, but avoid it
Use clear names$studentCount, not $x

powershell
[int]$age = 20     # $age is now locked to int
$age = "21"        # converted to 21 automatically
$age = "abc"       # error: cannot convert "abc" to Int32

Strings

CodeOutput
"Hello $name"Hello Aarav (double quotes expand)
'Hello $name'Hello $name (single quotes are literal)
"Cost: `$5"Cost: $5 (backtick escapes $)

$( ) subexpressions

Inside double quotes, only the simple $name expands. Put anything more inside $( ).

powershell
"Length: $name.Length"
"Length: $($name.Length)"
"Next year: $($marks + 5)"
output
Length: Aarav.Length
Length: 5
Next year: 97

-f formatting

powershell
"{0} scored {1}" -f $name, $marks
"{0:N2}" -f 3.14159
output
Aarav scored 92
3.14

{0}, {1} are slots filled in order. :N2 means "number with 2 decimals".

Here-strings (many lines)

powershell
$card = @"
Name : $name
Marks: $marks
"@
$card
output
Name : Aarav
Marks: 92

@" "@ expands variables; @' '@ does not. The closing "@ must be at the very start of its line.

Automatic variables

PowerShell creates these for you. Read them, don't assign them.

$_

Current object in the pipeline (same as $PSItem).

$null

"Nothing". An empty value.

$true / $false

Boolean yes / no.

$HOME

Your home folder.

$PSVersionTable

Version details.

$PWD

Current folder.

powershell
$HOME
$PSVersionTable.PSVersion.Major
output · sample, yours will differ
C:\Users\aarav
7

Environment variables: $env:

powershell
$env:USERNAME              # Windows (Linux/macOS: $env:USER)
$env:COURSE = "CBCS"       # set one, for this session only
$env:COURSE
output · sample, yours will differ
aarav
CBCS
TipGet-ChildItem env: lists every environment variable.

Try it

  1. Store your name and age in variables and print I am NAME and I am AGE.
  2. Print the same line with -f.
  3. What does "5" + 5 give? And 5 + "5"?
  4. Load datasets/students.csv into $s and print "There are N students".
Answers
powershell
$me = "Priya"; $age = 19
"I am $me and I am $age."
"I am {0} and I am {1}." -f $me, $age
"5" + 5        # 55  (text, because the left side is text)
5 + "5"        # 10  (number, because the left side is a number)
$s = Import-Csv datasets/students.csv
"There are $($s.Count) students"    # There are 8 students

Remember

  • $name = value; names are not case-sensitive.
  • .GetType() shows the type; [int], [string], [datetime] convert.
  • "double" expands variables, 'single' does not; use $( ) for expressions.
  • $env:NAME reads environment variables.
VivaDifference between single and double quotes? Double-quoted strings expand variables and subexpressions, so "Hi $name" gives Hi Aarav. Single-quoted strings are literal, so 'Hi $name' stays Hi $name.
