Operators

Operators do maths, compare values, combine conditions and work on text.

Topic 10~25 min
Before this:08 Variables09 User input
Key idea

Maths uses symbols (+ - * /). Almost everything else is a word with a dash: -eq, -gt, -like, -and. Comparisons are not case-sensitive by default.

Biggest gotcha> is not "greater than". It is redirection: it writes output to a file. Use -gt.
powershell
5 > 3            # no output... but it created a FILE named "3" containing 5
Get-Content 3
5 -gt 3          # the right way
Remove-Item 3    # clean up
output
5
True

Case-sensitive versions: add a c

ExampleResult
"abc" -eq "ABC"True
"abc" -ceq "ABC"False
"Web01" -clike "web*"False

Every comparison has a c form: -ceq, -cne, -cgt, -clike, -cmatch, -creplace…

Patterns: -like and -match

ExampleResultWhy
"report.csv" -like "*.csv"True* = any characters
"web01" -like "web??"True? = exactly one character
"db01" -notlike "web*"Truedoes not match
"Disk at 78%" -match '\d+%'Trueregex: digits then %
"INFO" -notmatch 'ERROR'Trueregex not found

-like uses simple wildcards. -match uses regular expressions and saves what it found in $Matches.

powershell
Get-Content datasets/app.log | Where-Object { $_ -match 'ERROR' }
output
2026-11-16 08:42:57 ERROR Failed to send email to priya@example.com
2026-11-16 09:31:08 ERROR Database connection lost
2026-11-16 10:45:31 ERROR Disk full on web01

Try it

  1. Is 17 even? Use %.
  2. Check whether a mark of 55 is a pass (40 or more) and below distinction (75).
  3. Show only WARN lines from datasets/app.log that mention web01.
  4. Turn "10A-10B-10C" into "10A, 10B, 10C".
Answers
powershell
17 % 2 -eq 0                                  # False, so odd
$m = 55; ($m -ge 40) -and ($m -lt 75)         # True
Get-Content datasets/app.log | Where-Object { $_ -like '*WARN*' -and $_ -like '*web01*' }
("10A-10B-10C" -split '-') -join ', '         # 10A, 10B, 10C

Remember

  • > writes to a file; compare with -gt, -lt, -eq.
  • Comparisons ignore case; add c (-ceq) to respect it.
  • -like = wildcards, -match = regex.
  • list -contains item; item -in list.
  • -and, -or, -not combine conditions.
VivaWhy doesn't PowerShell use > and == for comparison? Because > and < are already used for redirection, as in other shells. So PowerShell uses word operators: -eq, -ne, -gt, -ge, -lt, -le.
