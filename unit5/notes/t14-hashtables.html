Hashtables

A hashtable stores key = value pairs, so you look things up by name instead of by number.

Topic 14~20 min
Before this:08 Variables12 Loops13 Arrays
Key idea

An array is a numbered list: $a[0]. A hashtable is a labelled list: $h['Name'] or $h.Name. Keys are unique and ignore case.

Create a hashtable

Use @{ }. Separate pairs with ; or new lines.

powershell
$student = @{ Name = 'Aarav'; Class = '10A'; Maths = 92 }
$student
output · key order may differ
Name                           Value
----                           -----
Class                          10A
Name                           Aarav
Maths                          92
NoteA plain hashtable does not keep the order you typed. See [ordered] below.

Get, set, add, remove

powershell
$student.Name              # get with a dot
$student['Maths']          # get with brackets
$student.Maths = 95        # set (change)
$student.Science = 85      # set a new key = add
$student.Add('English', 78)  # add with a method
$student.Remove('Class')   # remove
$student.Count
output
Aarav
92
4
Watch out.Add() fails if the key already exists. $h['key'] = value adds or overwrites, so it never fails.

Keys, Values and ContainsKey

powershell
$student.Keys | Sort-Object
$student.ContainsKey('Maths')
$student.ContainsKey('Class')
output
English
Maths
Name
Science
True
False

$student.Values gives just the values the same way.

[ordered] keeps your order

powershell
$stock = [ordered]@{
    Keyboard = 25
    Mouse    = 40
    Monitor  = 8
}
$stock
output
Name                           Value
----                           -----
Keyboard                       25
Mouse                          40
Monitor                        8

Loop with GetEnumerator()

GetEnumerator() hands you each pair with .Key and .Value.

powershell
foreach ($pair in $stock.GetEnumerator()) {
    "$($pair.Key) = $($pair.Value)"
}
output
Keyboard = 25
Mouse = 40
Monitor = 8
Tipforeach ($k in $stock.Keys) { "$k = $($stock[$k])" } gives the same result.

Hashtable to object

Put [pscustomobject] in front to make a real object. It keeps your order and shows as a table.

powershell
$obj = [pscustomobject]@{ Name = 'Aarav'; Class = '10A'; Maths = 92 }
$obj
output
Name  Class Maths
----  ----- -----
Aarav 10A      92

Objects work with Sort-Object, Export-Csv and the rest of the pipeline, like the rows from Import-Csv.

Splatting

Store parameters in a hashtable, then pass it with @ instead of $. Long commands become easy to read.

powershell
$params = @{
    Path       = 'datasets/servers.txt'
    TotalCount = 2
}
Get-Content @params      # same as: Get-Content -Path datasets/servers.txt -TotalCount 2
output
web01
web02

Try it

  1. Make a hashtable $price with Mouse = 400 and Webcam = 2200. Print the Webcam price.
  2. Add Router = 3200, then check that Router exists.
  3. Loop over it and print lines like Mouse costs 400.
Answers
powershell
$price = @{ Mouse = 400; Webcam = 2200 }
$price.Webcam                       # 2200
$price['Router'] = 3200
$price.ContainsKey('Router')        # True
foreach ($p in $price.GetEnumerator()) { "$($p.Key) costs $($p.Value)" }

Remember

  • @{ key = value }; read with $h.key or $h['key'].
  • .Keys, .Values, .ContainsKey(), .Remove().
  • Loop pairs with .GetEnumerator().
  • [ordered] keeps order; [pscustomobject] makes an object.
  • Splat with @params.
VivaWhat is splatting? Passing a command's parameters as a hashtable: build $p = @{ Path = '...'; TotalCount = 2 } and call Get-Content @p. Each key becomes a parameter name.
