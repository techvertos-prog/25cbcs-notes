Profiles

A profile is a script that PowerShell runs automatically every time it starts, so your aliases and functions are always ready.

Topic 18~15 min
Before this:06 Writing scripts15 Functions16 Scoping
Key idea

The profile is just a .ps1 file. Its path is stored in $PROFILE. It does not exist until you create it.

What happens at start-up

  • Open PowerShell
  • Run profile.ps1 files
  • Aliases, functions loaded
  • Prompt ready

Without a profile, anything you define in a session is lost when you close the window.

$PROFILE and its four variants

powershell
$PROFILE
output · sample, yours will differ
C:\Users\you\Documents\PowerShell\Microsoft.PowerShell_profile.ps1

There are actually four profiles. See them all:

powershell
$PROFILE | Select-Object *
output · sample, PowerShell 7 on Windows
AllUsersAllHosts       : C:\Program Files\PowerShell\7\profile.ps1
AllUsersCurrentHost    : C:\Program Files\PowerShell\7\Microsoft.PowerShell_profile.ps1
CurrentUserAllHosts    : C:\Users\you\Documents\PowerShell\profile.ps1
CurrentUserCurrentHost : C:\Users\you\Documents\PowerShell\Microsoft.PowerShell_profile.ps1
Length                 : 66

Length is only the length of the path text. Ignore it.

"Host" means the program running PowerShell. VS Code uses its own file, Microsoft.VSCode_profile.ps1.

Create and edit your profile

  1. Check if it exists: Test-Path $PROFILE
  2. If False, create it (and any missing folders): New-Item -Path $PROFILE -ItemType File -Force
  3. Open it: notepad $PROFILE (Windows) or code $PROFILE (VS Code, any OS)
powershell
Test-Path $PROFILE
New-Item -Path $PROFILE -ItemType File -Force
output · sample, yours will differ
False

Watch out-Force on an existing file empties it. Run New-Item only when Test-Path says False.

What to put in it

Microsoft.PowerShell_profile.ps1
# Aliases: short names
Set-Alias -Name np -Value notepad

# Functions: your own shortcuts
function Get-Unit5Files { Get-ChildItem C:\unit5\datasets }

# A custom prompt: show only the current folder name
function prompt { "PS $(Split-Path -Leaf (Get-Location))> " }

# Start in your work folder
Set-Location C:\unit5

Write-Host "Profile loaded" -ForegroundColor Green

Reload, skip, and versions

After editing, load the changes without restarting by dot-sourcing the profile:

powershell
. $PROFILE
output
Profile loaded

Start PowerShell without any profile, e.g. when a profile is broken:

powershell
pwsh -NoProfile              # PowerShell 7
powershell.exe -NoProfile    # Windows PowerShell 5.1
VersionYour $PROFILE path
PowerShell 7, WindowsDocuments\PowerShell\Microsoft.PowerShell_profile.ps1
Windows PowerShell 5.1Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1
PowerShell 7, Linux / macOS~/.config/powershell/Microsoft.PowerShell_profile.ps1
5.1 note5.1 and 7 use different profile files, so a profile made in one does not load in the other. On Windows, a profile is a script, so the execution policy must allow scripts (see 06).

Try it

  1. Print $PROFILE and check whether it exists.
  2. Create it if needed and add a function Get-Hello that prints Hello from my profile.
  3. Reload the profile and run Get-Hello. Then open pwsh -NoProfile and try again.
Answers
powershell
$PROFILE
if (-not (Test-Path $PROFILE)) { New-Item -Path $PROFILE -ItemType File -Force }
Add-Content $PROFILE "function Get-Hello { 'Hello from my profile' }"
. $PROFILE
Get-Hello            # Hello from my profile
pwsh -NoProfile      # in the new shell, Get-Hello is not recognised

Remember

  • A profile is a .ps1 file that runs at start-up.
  • $PROFILE = current user, current host. Four variants exist.
  • Test-Path $PROFILE, then New-Item $PROFILE -ItemType File -Force.
  • Reload with . $PROFILE; skip with -NoProfile.
  • 5.1 and 7 have separate profile paths.
