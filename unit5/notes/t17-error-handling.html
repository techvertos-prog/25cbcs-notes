Basic error handling

Error handling lets a script notice a problem, react to it, and carry on or stop cleanly instead of crashing.

Topic 17~25 min
Before this:03 Cmdlets11 if, else & switch15 Functions
Key idea

try/catch only catches terminating errors. Most cmdlet errors are non-terminating, so add -ErrorAction Stop to make catch run.

Two kinds of errors

Non-terminatingTerminating
What happensError is shown, the script keeps goingThe current statement stops
Typical causeA cmdlet fails on one item (missing file)throw, divide by zero, -ErrorAction Stop
Caught by catch?NoYes
powershell
Get-Content datasets/missing.txt
"Script keeps going"
output · sample, your path will differ
Get-Content: Cannot find path 'C:\unit5\datasets\missing.txt' because it does not exist.
Script keeps going
powershell
$zero = 0
10 / $zero
output
RuntimeException: Attempted to divide by zero.

-ErrorAction and $ErrorActionPreference

Every cmdlet takes -ErrorAction (short: -EA). It decides what a non-terminating error does.

ValueShows error?Keeps going?
Continue (default)YesYes
SilentlyContinueNoYes
StopYes, as a terminating errorNo: jumps to catch
powershell
Get-Content datasets/missing.txt -ErrorAction SilentlyContinue
"No error shown"
output
No error shown

$ErrorActionPreference sets the default for every command after it. Many scripts start with:

powershell
$ErrorActionPreference = 'Stop'

try / catch / finally

  • try: run code
  • error? jump to catch
  • finally: always runs
powershell
try {
    Get-Content datasets/missing.txt -ErrorAction Stop
    "This line is skipped"
}
catch {
    "Could not read file: $($_.Exception.Message)"
}
finally {
    "Done"
}
output · sample, your path will differ
Could not read file: Cannot find path 'C:\unit5\datasets\missing.txt' because it does not exist.
Done

Inside catch, $_ is the error. $_.Exception.Message is its text.

Watch outRemove -ErrorAction Stop and the catch block never runs: the error prints, then This line is skipped prints too.

Catch a specific error type

Put the exception type in [ ]. The first matching catch wins, so put the general one last.

powershell
try {
    Get-Content datasets/missing.txt -ErrorAction Stop
}
catch [System.Management.Automation.ItemNotFoundException] {
    "File not found"
}
catch {
    "Something else went wrong: $($_.Exception.Message)"
}
output
File not found
TipTo find the type name, cause the error, then run $Error[0].Exception.GetType().FullName.

throw, $Error and $?

throw raises your own terminating error.

powershell
$marks = -5
if ($marks -lt 0) { throw 'Marks cannot be negative' }
output
Exception: Marks cannot be negative

$Error lists the errors of this session, newest first. $? is True if the last command succeeded.

powershell
Get-Content datasets/missing.txt -ErrorAction SilentlyContinue
$?
$Error[0].Exception.Message
Get-Content datasets/servers.txt | Out-Null
$?
output · sample, your path will differ
False
Cannot find path 'C:\unit5\datasets\missing.txt' because it does not exist.
True
NoteSilentlyContinue hides the error but still records it in $Error. -ErrorAction Ignore does not record it.

Real example: read a config file safely

powershell
$path = 'datasets/config.json'
try {
    $config = Get-Content $path -Raw -ErrorAction Stop | ConvertFrom-Json
    "App: $($config.AppName) on port $($config.Port)"
}
catch {
    Write-Warning "Cannot read $path. Using defaults."
    $config = [pscustomobject]@{ AppName = 'Default'; Port = 80 }
}
output
App: StudentPortal on port 8080

Change $path to 'datasets/nope.json' and run it again:

output
WARNING: Cannot read datasets/nope.json. Using defaults.

Try it

  1. Read datasets/app.log inside try. Print Read OK; on error print the message.
  2. Change the file name to one that doesn't exist. Does catch run? Fix it so it does.
  3. Write a finally that prints Finished in both cases.
Answers
powershell
try {
    $lines = Get-Content datasets/app.log -ErrorAction Stop   # without Stop, catch won't run
    "Read OK"
}
catch {
    "Error: $($_.Exception.Message)"
}
finally {
    "Finished"
}

Remember

  • Non-terminating errors keep going; terminating errors stop.
  • catch needs a terminating error: add -ErrorAction Stop.
  • $_.Exception.Message is the error text inside catch.
  • finally always runs; throw makes your own error.
  • $Error[0] is the latest error; $? says if the last command worked.
VivaWhy does my catch block not run when Get-Content fails? A missing file is a non-terminating error, and try/catch only catches terminating errors. Add -ErrorAction Stop, or set $ErrorActionPreference = 'Stop'.
