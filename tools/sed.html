sed: the stream editor

sed edits text as it flows through a pipe or out of a file: substitute, delete, insert, print ranges. It is the standard tool for changing configuration files from a script (APP_ENV=production, rotate a password, uncomment a line), for reshaping CSV data and for cutting a time window out of a log. This page explains the pattern-space model first, because once you understand it every sed command becomes obvious.

s/// · d · p · a/i/c · yaddresses & rangesin-place editingDatasets: app.conf, employees.csv, access.log~60 min

Syntax

syntax
sed [OPTIONS] 'SCRIPT' [FILE...]
sed [OPTIONS] -e 'CMD1' -e 'CMD2' [FILE...]
sed [OPTIONS] -f script.sed [FILE...]
command | sed 'SCRIPT'

# a SCRIPT is one or more commands, each optionally preceded by an address:
#   [address[,address]][!]command[arguments]
sed '3d'                 # address 3, command d
sed '/^#/d'              # address /^#/, command d
sed '2,5s/a/b/g'         # range 2-5, command s with flag g
sed '/start/,/end/!d'    # NOT in the range -> delete

How it works: the pattern space

sed is a loop that you never write yourself. For every input line it does this:

  1. Read the next line into a buffer called the pattern space (the trailing newline is removed).
  2. Run the script top to bottom. Each command runs only if its address matches the current line. Commands change the pattern space (s, y), print it (p), throw it away and start the next cycle (d), and so on.
  3. Auto-print the pattern space at the end of the script, unless -n was given.
  4. Repeat until the input ends. A second buffer, the hold space, survives between lines and can be used as memory.
mental model
input line ──► [ pattern space ] ──► script: addr cmd; addr cmd; ... ──► auto-print (unless -n) ──► stdout
                       ▲   │ h/H (copy/append to hold)
                       │   ▼
                  g/G  [ hold space ]   x = swap the two

Two consequences explain most beginner confusion:

  • sed 'p' prints every line twice (once by p, once by auto-print). That is why p is almost always used with -n.
  • sed never changes the file unless you use -i. Without it, the result goes to stdout and the original stays as it was.

Basics: substitute, print, delete

s: substitute

The most used sed command. By default only the first match on each line is replaced.

bash
sed 's/development/production/' datasets/app.conf | grep APP_ENV
output
APP_ENV=production
bash
echo "a-b-c-d" | sed 's/-/+/'      # first only
echo "a-b-c-d" | sed 's/-/+/g'     # g = global, every match
echo "a-b-c-d" | sed 's/-/+/2'     # N = only the 2nd match
echo "a-b-c-d" | sed 's/-/+/2g'    # 2nd and all following (GNU)
output
a+b-c-d
a+b+c+d
a-b+c-d
a-b+c+d

Substitution flags

FlagEffect
greplace all matches on the line
N (a number)replace only the N-th match
i / Icase-insensitive match (GNU; also recent BSD)
pprint the line if a substitution was made (use with -n)
w FILEwrite the line to FILE if a substitution was made
bash
sed -n 's/=on$/=enabled/p' datasets/app.conf          # p: show only changed lines
output
FEATURE_EMAIL=enabled
bash
sed -n 's/^log_level=.*/LOG_LEVEL=warn/Ip' datasets/app.conf   # I: ignore case
output
LOG_LEVEL=warn
bash
sed -n 's/changeme/********/w changed.txt' datasets/app.conf
cat changed.txt
output
DB_PASS=********

Alternative delimiters

The character after s is the delimiter, and it can be (almost) anything. Use | or # when the text contains slashes, instead of escaping every /:

bash
sed -n 's/\/var\/log\/inventory/\/srv\/logs/p' datasets/app.conf   # "leaning toothpicks"
sed -n 's|/var/log/inventory|/srv/logs|p'      datasets/app.conf   # much clearer
sed -n 's#/var/log/inventory#/srv/logs#p'      datasets/app.conf
output
LOG_FILE=/srv/logs/app.log
LOG_FILE=/srv/logs/app.log
LOG_FILE=/srv/logs/app.log

&: the whole match

In the replacement, & stands for the text that was matched:

bash
sed -n 's/[0-9][0-9]*$/[&]/p' datasets/app.conf
output
APP_PORT=[8080]
DB_PORT=[3306]
MAX_UPLOAD_MB=[10]

macOS trapOn macOS, sed -i 's/a/b/' file takes 's/a/b/' as the backup suffix and then fails with "invalid command code". Portable scripts use sed -i.bak ... && rm file.bak, or install GNU sed (brew install gnu-sed, run as gsed).
Tip-i replaces the file with a new one (new inode). Symlinks are replaced by regular files unless you add --follow-symlinks (GNU), and file ownership can change if run as root. For critical files, test without -i first, then diff the result.

Using shell variables in a sed script

Switch to double quotes so the shell substitutes the variable, and pick a delimiter that cannot appear in the value:

bash

If the value may contain the delimiter, & or \, escape them first:

bash
escape_sed() { printf '%s' "$1" | sed -e 's/[\/&|]/\\&/g'; }
pass='p@ss&w/rd|1'
sed -n "s|^DB_PASS=.*|DB_PASS=$(escape_sed "$pass")|p" datasets/app.conf
output
DB_PASS=p@ss&w/rd|1

Without escaping, the & would be replaced by the whole matched text and the | would end the replacement early.

Use cases

Use case 1 Preparing a config file for production

Scenario: a deployment script must turn the development app.conf into a production one: set APP_ENV=production, turn debugging off, set the database password from an environment variable (never typed into the script), raise the log level, uncomment LOG_ROTATE, and add a key if it is missing. It must keep a backup and show what changed.

bash · configure.sh
#!/usr/bin/env bash
# configure.sh - harden an app.conf for production with sed
set -euo pipefail

conf="${1:?usage: configure.sh CONFIG_FILE}"
: "${DB_PASS:?export DB_PASS before running}"   # read secret from the environment

[[ -w "$conf" ]] || { echo "error: $conf not writable" >&2; exit 1; }

# escape characters that are special in the sed replacement: \ & and our delimiter |
escape_repl() { printf '%s' "$1" | sed -e 's/[\\&|]/\\&/g'; }

# set_key KEY VALUE : replace KEY=... if present (even commented out), else append it
set_key() {
  local key="$1" value
  value=$(escape_repl "$2")
  if grep -qE "^#?[[:space:]]*${key}=" "$conf"; then
    sed -i.tmp -E "s|^#?[[:space:]]*${key}=.*|${key}=${value}|" "$conf"
  else
    printf '%s=%s\n' "$key" "$2" >> "$conf"
  fi
  rm -f "$conf.tmp"
}

cp -p "$conf" "$conf.orig"                       # keep the original for diff/rollback

set_key APP_ENV     production
set_key APP_DEBUG   false
set_key DB_PASS     "$DB_PASS"
set_key LOG_LEVEL   warn
set_key LOG_ROTATE  daily                        # uncomments #LOG_ROTATE=daily
set_key DB_SSL      required                     # not present -> appended

echo "Changes made to $conf:"
diff "$conf.orig" "$conf" || true                # diff exits 1 when files differ
bash · run it on a copy
cp datasets/app.conf app.conf
DB_PASS='S3cure&Pa55|word' ./configure.sh app.conf
output

How it works:

  • -i.tmp is the portable in-place form: it works identically on GNU and BSD sed; the temporary backup is removed right after.
  • ^#?[[:space:]]*KEY= matches the key whether it is active or commented out, so the same function both changes and uncomments (#LOG_ROTATE=daily → LOG_ROTATE=daily).
  • The password contains & and |; escape_repl backslash-escapes them, otherwise & would insert the matched text and | would terminate the s command.
  • diff returns 1 when files differ; || true stops set -e from treating that as a failure.

Use case 2 Transforming and masking a CSV file

Scenario: HR wants to share employees.csv with an external auditor. Requirements: semicolon-separated output, names reduced to initials, salaries hidden (only the thousands shown as XXk), dates in Indian DD-MM-YYYY format, the internal id column dropped, and only Engineering and Finance included. A single sed script does all of it.

sed · mask.sed
# mask.sed - anonymise employees.csv
# 1. header: rename and drop the id column
1{
  s/^id,//
  s/name/initials/
  s/salary/salary_band/
  s/,/;/g
  p
  d
}
# 2. keep only Engineering and Finance rows
/,\(Engineering\|Finance\),/!d
# 3. drop id
s/^[0-9]*,//
# 4. "First Last" -> "F.L."
s/^\([A-Z]\)[a-z]* \([A-Z]\)[a-z]*,/\1.\2.,/
# 5. salary 110000 -> 110k
s/,\([0-9]*\)[0-9]\{3\},\([0-9-]*\)$/,\1k,\2/
# 6. YYYY-MM-DD -> DD-MM-YYYY
s/\([0-9]\{4\}\)-\([0-9][0-9]\)-\([0-9][0-9]\)$/\3-\2-\1/
# 7. separators, then print (we run with -n)
s/,/;/g
p
bash · run it (GNU sed)
sed -n -f mask.sed datasets/employees.csv | head -8
output
initials;department;city;salary_band;join_date
A.K.;Engineering;Delhi;110k;11-08-2023
P.S.;Engineering;Delhi;135k;27-02-2023
R.M.;Engineering;Mumbai;84k;22-11-2025
A.I.;Engineering;Pune;131k;03-05-2025
A.N.;Finance;Hyderabad;94k;24-10-2016
K.G.;Engineering;Chennai;93k;03-11-2020
R.G.;Engineering;Pune;115k;01-03-2017

Line-by-line:

  • Block 1 runs only on line 1 (the header): several substitutions, then p prints it and d ends the cycle so the data rules below never see the header.
  • Rule 2 uses the GNU BRE alternation \| with !d: delete every line that is not Engineering or Finance. (Portable: run sed with -E and write /,(Engineering|Finance),/!d.)
  • Rule 5 captures all digits except the last three, [0-9]* is greedy but must leave exactly three digits for [0-9]\{3\}.
  • Final p: the script runs under -n, so surviving data lines must be printed explicitly.
  • Order matters: commas are replaced by semicolons last, because every earlier rule relies on commas to find columns.
Check your workCount rows before and after: grep -cE ',(Engineering|Finance),' datasets/employees.csv should equal the output lines minus the header.

(c) A section extractor function. app.conf uses # Heading comments as section markers; the section ends at the next blank line:

bash · section.sh
#!/usr/bin/env bash
# section.sh - print one "# Name" section of a config file, without comments
set -euo pipefail

print_section() {
  local file="$1" name="$2"
  sed -n "/^# ${name}\$/,/^\$/{ /^#/d; /^\$/d; p; }" "$file"
}

for s in Database Logging Features; do
  echo "[$s]"
  print_section datasets/app.conf "$s" | sed 's/^/  /'
done

Notes: /^#/d inside the block also hides commented-out settings such as #LOG_ROTATE=daily, only active settings are shown. Inside double quotes, $ must be written \$ where we mean the regex anchor, otherwise the shell tries to expand $/. The sed 's/^/ /' at the end indents each line, ^ matches the empty string at the start of the line, so the substitution inserts text there.

Viva / exam questions

What is the pattern space?

The buffer into which sed reads each input line. All commands operate on it; at the end of the script it is printed (unless -n) and the next line is read.

What does sed -n '/start/,/end/p' print?

All lines from each line matching start through the next line matching end, inclusive.

Difference between s/x/y/ and s/x/y/g?

Without g only the first match on each line is replaced; with g all matches are.

How do you edit a file in place and keep a backup?

sed -i.bak 's/old/new/' file: this form works with both GNU and BSD sed.

What do & and \1 mean in the replacement?

& is the whole matched text; \1 is the text captured by the first parenthesised group.

How do you delete blank lines?

sed '/^$/d', or sed '/^[[:space:]]*$/d' to include lines with only spaces.

Why use a different delimiter like s|a|b|?

When the pattern or replacement contains / (paths, URLs), another delimiter avoids escaping every slash.

Difference between the a, i and c commands?

a appends text after the addressed line, i inserts before it, c replaces the line.

What is the hold space used for?

It is a second buffer that persists across lines, used to remember text (e.g. a heading) or accumulate lines (e.g. reversing a file with 1!G;h;$p).
