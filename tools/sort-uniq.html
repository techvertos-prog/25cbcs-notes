sort & uniq: ordering and counting

sort puts lines in order by any column, as text, numbers, human sizes, versions or months. uniq collapses or counts adjacent repeated lines. Together they make the most used idiom in log analysis: sort | uniq -c | sort -rn. comm rounds this out by comparing two sorted lists.

Commands: sort, uniq, commGNU coreutils~40 minUsed in Lab 06, 07, 11, 12

Syntax and mental model

bash · syntax
sort [options] [file...]          # reads stdin if no file
uniq [options] [input [output]]   # works on ADJACENT lines only
comm [-123] sorted_file1 sorted_file2

How sort thinks. Each line is a record. Without options the whole line is compared character by character (using the current locale's collation). With -k you choose a key: a slice of the line from a start field to an end field. Fields are separated by runs of blanks by default, or by a single character given with -t. If two keys compare equal, sort falls back to comparing the whole line (the "last-resort comparison") unless you give -s or -u.

How uniq thinks. It reads the input once and compares each line only with the line before it. So a a b a becomes a b a, not a b. That is why you almost always sort first.

How comm thinks. It walks two sorted files in parallel and prints three columns: lines only in file 1, lines only in file 2, lines in both. -1, -2, -3 hide those columns.

Viva"Why does uniq need sorted input?" Because it only compares neighbouring lines; sorting brings all identical lines next to each other so each group is one run.

LocaleSort order depends on LC_COLLATE. In en_US.UTF-8 GNU sort ignores case and punctuation at first pass (apple Apple banana); in the C locale it compares raw bytes (uppercase before lowercase). The outputs on this page use export LC_ALL=C, which is also what you want in scripts for predictable results and speed. For the lowercase datasets here both locales give the same output except where noted.

Basics

Sort lines alphabetically, remove duplicates

bash
sort -u datasets/tags.txt
output
bash
docker
git
linux
mysql
nginx
postgres
python
redis

sort -u is the same as sort | uniq but in one process. Add -r to reverse:

bash
sort -ru datasets/tags.txt | head -3
output
redis
python
postgres

uniq on unsorted input: the classic mistake

bash
uniq -c datasets/tags.txt | head -3      # WRONG: input not sorted
output
      1 postgres
      1 linux
      1 docker

Every count is 1 because no two neighbouring lines are equal. Sort first.

The frequency table idiom

bash
sort datasets/tags.txt | uniq -c | sort -rn
output
     11 docker
      8 nginx
      8 linux
      8 bash
      5 mysql
      4 git
      3 python
      2 redis
      1 postgres
  1. sort groups identical tags together.
  2. uniq -c collapses each group to one line and prefixes the count (GNU pads it to width 7).
  3. sort -rn orders by that number, largest first. Ties fall back to a whole-line reverse compare, which is why nginx comes before bash.

Only the duplicates, or only the singletons

bash
sort datasets/tags.txt | uniq -d | tr '\n' ' '; echo   # repeated tags
sort datasets/tags.txt | uniq -u                         # tags seen exactly once
output
bash docker git linux mysql nginx python redis
postgres

Numeric vs text sort

Text sort compares character by character, so 99000 beats 135000 because 9 > 1:

bash
tail -n +2 datasets/employees.csv | sort -t, -k5,5r  | head -3   # text: wrong
tail -n +2 datasets/employees.csv | sort -t, -k5,5nr | head -3   # numeric: right
output
115,Nikhil Das,Engineering,Chennai,99000,2022-05-17
107,Arjun Nair,Finance,Hyderabad,94000,2016-10-24

Keys and separators (intermediate)

-k2,2 versus -k2

-kF,F means "this field only". -kF alone means "from field F to the end of the line". The difference shows up in how ties are broken:

bash

Advanced

Stable sort with -s

A stable sort keeps equal-key lines in their input order. This lets you sort in two passes: first by the secondary key, then stably by the primary key. Here the input is first sorted by salary, then stably by department, so salary order survives inside each department:

bash
tail -n +2 datasets/employees.csv | sort -t, -k5,5nr | sort -t, -s -k3,3 | head -5
echo ---
tail -n +2 datasets/employees.csv | sort -t, -k5,5nr | sort -t, -k3,3 | head -5   # no -s
output
102,Priya Sharma,Engineering,Delhi,135000,2023-02-27
104,Ananya Iyer,Engineering,Pune,131000,2025-05-03
114,Pooja Nair,Engineering,Hyderabad,127000,2025-05-15
118,Divya Singh,Engineering,Delhi,116000,2016-03-16
109,Rahul Gupta,Engineering,Pune,115000,2017-03-01
---
101,Aarav Kapoor,Engineering,Delhi,110000,2023-08-11
102,Priya Sharma,Engineering,Delhi,135000,2023-02-27
103,Rohan Mehta,Engineering,Mumbai,84000,2025-11-22
104,Ananya Iyer,Engineering,Pune,131000,2025-05-03
108,Kavya Gupta,Engineering,Chennai,93000,2020-11-03

Without -s, equal departments fall back to the last-resort whole-line compare, which orders them by id and throws the salary order away. In practice a single multi-key sort is simpler: sort -t, -k3,3 -k5,5nr. Two-pass stable sorting matters when the first pass is something sort cannot express, such as an order produced by another tool.

One line per key: -u with -k

With a key, -u compares only the key, and keeps the first line of each group. Combine with a pre-sort to get "highest paid per department":

bash
tail -n +2 datasets/employees.csv | sort -t, -k3,3 -k5,5nr | sort -t, -s -u -k3,3
output
102,Priya Sharma,Engineering,Delhi,135000,2023-02-27
107,Arjun Nair,Finance,Hyderabad,94000,2016-10-24
123,Harsh Verma,HR,Mumbai,92000,2024-01-22
105,Vikram Verma,Sales,Hyderabad,93000,2022-10-20
125,Kunal Singh,Support,Mumbai,75000,2016-04-09

Sort a file in place

bash

sort names.txt > names.txt       # WRONG: the shell truncates names.txt first -> empty file

Use cases

Use case 1 Tag / word frequency table with percentages

You have a list of tags (or words, error codes, usernames) and want a ranked table with each item's share of the total. Normalising case and dropping blank lines first avoids counting Docker and docker separately.

bash · tag_freq.sh
#!/usr/bin/env bash
# tag_freq.sh - frequency table with percentages for a one-item-per-line file
set -euo pipefail

file="${1:-datasets/tags.txt}"
[[ -r "$file" ]] || { echo "cannot read $file" >&2; exit 1; }

total=$(grep -c . "$file")            # non-empty lines

printf '%-10s %5s %7s\n' "TAG" "COUNT" "SHARE"
tr 'A-Z' 'a-z' < "$file" |            # normalise case
  grep -v '^[[:space:]]*$' |          # drop blank lines
  sort | uniq -c |                    # count each distinct tag
  sort -k1,1nr -k2,2 |                # most frequent first, ties A-Z
  awk -v t="$total" '{ printf "%-10s %5d %6.1f%%\n", $2, $1, 100*$1/t }'
echo "distinct: $(sort -u "$file" | wc -l | tr -d ' ')  total: $total"
bash · run it
chmod +x tag_freq.sh
./tag_freq.sh datasets/tags.txt
output
TAG        COUNT   SHARE
docker        11   22.0%
bash           8   16.0%
linux          8   16.0%
nginx          8   16.0%
mysql          5   10.0%
git            4    8.0%
python         3    6.0%
redis          2    4.0%
postgres       1    2.0%
distinct: 9  total: 50

How it works. sort -k1,1nr -k2,2 sorts by count descending and breaks ties alphabetically, so the three tags with 8 hits are listed A–Z instead of reverse order. The final awk swaps the columns and computes the percentage; %% prints a literal percent sign. For free text, first split into one word per line with tr -cs '[:alpha:]' '\n' (see cut & tr).

Use case 2 Top-N report from a web access log

The daily question from operations: who is hitting the server, which URLs are hot, and how many errors? One reusable function does the count-sort-head for any column.

bash · top_report.sh
#!/usr/bin/env bash
# top_report.sh - top-N summary of an Apache/Nginx combined access log
# usage: ./top_report.sh [logfile] [N]
set -euo pipefail

log="${1:-datasets/access.log}"
n="${2:-5}"
[[ -r "$log" ]] || { echo "error: cannot read $log" >&2; exit 1; }
[[ "$n" =~ ^[0-9]+$ ]] || { echo "error: N must be a number" >&2; exit 2; }

# top <awk-field-expression> <title>: count values, print the N largest
top() {
  local expr="$1" title="$2"
  echo "== Top $n $title =="
  awk "{ print $expr }" "$log" | sort | uniq -c | sort -k1,1nr -k2,2 | head -n "$n"
  echo
}

echo "Report for $log ($(wc -l < "$log" | tr -d ' ') requests)"
echo
top '$1'  "client IPs"
top '$7'  "URLs"
top '$9'  "status codes"
echo "== Top $n IPs by bytes sent =="
awk '{ bytes[$1] += $10 } END { for (ip in bytes) print bytes[ip], ip }' "$log" |
  sort -k1,1nr | head -n "$n"
bash · run it
./top_report.sh datasets/access.log 3
output
Report for datasets/access.log (80 requests)

== Top 3 client IPs ==
     18 192.168.1.10
     14 192.168.1.15
     13 10.0.0.5

== Top 3 URLs ==
     10 /api/v1/users
      8 /index.php
      7 /images/logo.png

== Top 3 status codes ==
     55 200
      9 403
      8 404

== Top 3 IPs by bytes sent ==
418954 192.168.1.10
276896 192.168.1.15
174227 10.0.0.5

Tricky parts. The awk program is built in double quotes so $expr (a Bash variable holding the text $1) is substituted before awk runs; the call sites pass '$1' in single quotes so Bash does not expand it there. head -n "$n" closing the pipe early is fine even with pipefail here because the upstream sort has already written all its output. The bytes section shows that awk can do the summing and sort just ranks the totals.

Use case 3 Which hosts are missing from an inventory? (comm)

The SSH inventory (servers.txt) and the monitoring inventory (servers.json) drift apart over time. comm on the two sorted hostname lists tells you exactly what is in one but not the other. The script exits 1 when hosts are missing, so cron or CI can alert on it.

bash · inv_diff.sh
#!/usr/bin/env bash
# inv_diff.sh - compare the SSH inventory with the monitoring inventory
# usage: ./inv_diff.sh [servers.txt] [servers.json]
set -euo pipefail
export LC_ALL=C                     # comm and sort must agree on order

txt="${1:-datasets/servers.txt}"
json="${2:-datasets/servers.json}"

ssh_hosts=$(mktemp) mon_hosts=$(mktemp)
trap 'rm -f "$ssh_hosts" "$mon_hosts"' EXIT

grep -v '^#' "$txt" | awk 'NF { print $1 }' | sort -u > "$ssh_hosts"
jq -r '.servers[].hostname' "$json"            | sort -u > "$mon_hosts"

echo "In both inventories:"
comm -12 "$ssh_hosts" "$mon_hosts" | sed 's/^/  /'
echo "Monitored but missing from SSH inventory:"
comm -13 "$ssh_hosts" "$mon_hosts" | sed 's/^/  /'
echo "In SSH inventory but not monitored:"
comm -23 "$ssh_hosts" "$mon_hosts" | sed 's/^/  /'
missing=$(comm -13 "$ssh_hosts" "$mon_hosts" | wc -l)
exit $(( missing > 0 ? 1 : 0 ))
bash · run it
./inv_diff.sh; echo "exit=$?"
output
In both inventories:
  cache01
  db01
  mon01
  web01
  web02
Monitored but missing from SSH inventory:
  db02
  lb01
  web03
In SSH inventory but not monitored:
exit=1

Why this design. comm requires both inputs sorted with the same collation, hence export LC_ALL=C at the top. Temporary files plus trap … EXIT keep things tidy; you could also use comm -13 <(…) <(…). The three comm calls are intersection (-12), right-only (-13) and left-only (-23). Without jq installed, the hostnames could also come from grep -o '"hostname": *"[^"]*"'.

Gotchas

ProblemCause and fix
uniq -c shows every count as 1Input not sorted. Use sort | uniq -c.
10 sorts before 9Text compare. Add -n (or -h for 10K/2G, -V for versions).
sort -k2 gives odd tie orderKey runs to end of line. Use -k2,2.
Header line sorted into datatail -n +2, or { head -1 f; tail -n +2 f | sort; }.
CSV sorted on wrong columnForgot -t,. Default separator is blanks.
Quoted CSV fields with commassort -t, cannot parse quotes. Use a real CSV tool or awk with FPAT (gawk).
Different order on another machineLocale. Set LC_ALL=C in scripts.
comm output wrong or warns "not in sorted order"Inputs not sorted, or sorted under a different locale.
sort f > f empties the fileShell truncates first. Use sort -o f f.
Count width differsGNU uniq -c pads to 7 characters, BSD/macOS to 4. Use awk '{print $1}' rather than relying on columns.
uniq -w unknown optionGNU only. On BSD, cut the field first or use awk '!seen[$1]++'.
Tipawk '!seen[$0]++' file removes duplicates without sorting, keeping the first occurrence in original order. Use it when order matters.
