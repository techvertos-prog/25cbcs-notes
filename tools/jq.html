jq: the command-line JSON processor

APIs, cloud CLIs and config tools all speak JSON, and grep/awk cannot parse it safely. jq can: it selects values, filters arrays, reshapes objects, groups and aggregates, and prints JSON, CSV, TSV or raw text for the rest of your script. This page builds up from . to reduce, using a user list, a server inventory and a real-shaped Cloudflare DNS API response.

filters & pipesselect · map · group_by@csv · @tsv · --argjq 1.7Datasets: users.json, servers.json, cf_dns_records.json~90 min

Syntax

syntax
jq [OPTIONS] 'FILTER' [FILE...]
command | jq [OPTIONS] 'FILTER'

jq '.'            file.json      # pretty-print (identity filter)
jq '.servers[0]'  file.json      # navigate
jq -r '.[].email' file.json      # raw strings, one per line

Install with sudo apt install jq (Debian/Ubuntu), sudo dnf install jq (RHEL/Rocky) or brew install jq (macOS).

How it works: filters and streams

A jq program is a filter: it takes one JSON value as input and produces zero, one or many JSON values as output. Filters are combined with the pipe |, exactly like shell commands, the outputs of the left side become the inputs of the right side, one at a time.

mental model
input JSON ──► .servers ──► .[] ──► select(.status == "running") ──► .hostname ──► "web01"
  (1 value)    (1 array)    (8 objects,      (6 objects pass)          (6 strings)   "web03"
                             one at a time)                                          ...
  • . is the current input. .servers means "the servers key of the input".
  • .[] explodes an array into a stream of its elements. Most "for each" logic is just .[] | ....
  • To turn a stream back into an array, wrap it in brackets: [ .[] | ... ] (that is exactly what map(...) does).
  • The comma , runs two filters on the same input and outputs both results.

Basics: navigating JSON

.: identity / pretty-print

bash
echo '{"host":"web01","ports":[80,443],"tls":true}' | jq '.'
output
{
  "host": "web01",
  "ports": [
    80,
    443
  ],
  "tls": true
}
bash
echo '{"host":"web01","ports":[80,443],"tls":true}' | jq -c '.'     # compact
output
{"host":"web01","ports":[80,443],"tls":true}
bash
echo '{"host":"web01","ports":[80,443]}' | jq --tab '.'             # tab indentation
output
{
    "host": "web01",
    "ports": [
        80,
        443
    ]
}

(Tabs are shown as four spaces here.) jq . file.json is also the quickest JSON validator: invalid JSON gives a parse error and a non-zero exit status.

bash
echo '{"host": "web01",}' | jq '.'; echo "exit=$?"
output
jq: parse error: Expected another key-value pair at line 1, column 18
exit=5

Use case 1 User access audit report

Scenario: security wants a monthly audit of users.json (in real life the output of an identity API): a summary of how many accounts are active, who holds the admin role (and whether those accounts are active), accounts that have not logged in since a cut-off date, and a CSV export for the spreadsheet people.

bash · user_audit.sh
#!/usr/bin/env bash
# user_audit.sh - audit users.json: admins, stale accounts, CSV export
set -euo pipefail

users="${1:-datasets/users.json}"
cutoff="${2:-2026-11-05}"              # accounts with no login since this date are "stale"
out_csv="${3:-user_audit.csv}"

jq -e 'type == "array"' "$users" > /dev/null || { echo "error: $users is not a JSON array" >&2; exit 1; }

echo "== User audit ($users) =="
jq -r '"Accounts: \(length)  active: \(map(select(.active)) | length)  inactive: \(map(select(.active | not)) | length)"' "$users"

echo
echo "-- Accounts with the admin role --"
jq -r '.[] | select(.roles | index("admin"))
       | [.username, (if .active then "ACTIVE" else "disabled" end), (.roles | join("+"))] | @tsv' "$users" |
  column -t

echo
echo "-- Active accounts with no login since $cutoff --"
jq -r --arg cut "$cutoff" '
  .[] | select(.active and (.last_login[0:10] < $cut))
      | "\(.username)\tlast login \(.last_login[0:10])"' "$users"

echo
echo "-- Role membership --"
jq -r '[.[] | .roles[]] | group_by(.) | map("\(.[0]): \(length)") | join(", ")' "$users"

# CSV export: header row + one row per user
jq -r '["id","username","name","email","city","active","roles","storage_mb"],
       (.[] | [.id, .username, .name, .email, .address.city, .active, (.roles | join(";")), .storage_mb])
       | @csv' "$users" > "$out_csv"
echo
echo "CSV written to $out_csv ($(( $(wc -l < "$out_csv") - 1 )) rows)"

How it works:

  • jq -e 'type == "array"' validates the input up front: a parse error or wrong shape stops the script with a clear message.
  • select(.roles | index("admin")): index returns the position (0 is still "truthy" in jq; only null and false are falsy) or null if absent.

Use case 2 Server fleet health summary grouped by role

Scenario: your monitoring system exports servers.json every 5 minutes. Produce (1) a per-role summary with averages and the worst host, (2) a list of problems, anything not running, or with CPU, memory or disk over a threshold, and (3) a machine-readable JSON summary that another tool (or Lab 07's email alert) can consume. The thresholds come from the shell with --argjson.

jq · fleet_health.jq
# fleet_health.jq - summarise a server inventory
# usage: jq --argjson cpu 80 --argjson mem 85 --argjson disk 80 -f fleet_health.jq servers.json
def avg(f): (map(f) | add) / length | . * 10 | round / 10;

def problems:
  [ if .status != "running" then "status=\(.status)" else empty end,
    if .cpu_pct  > $cpu  then "cpu=\(.cpu_pct)%"   else empty end,
    if .mem_pct  > $mem  then "mem=\(.mem_pct)%"   else empty end,
    if .disk_pct > $disk then "disk=\(.disk_pct)%" else empty end ];

{
  datacenter: .datacenter,
  generated:  .generated,
  total:      (.servers | length),
  by_role: (.servers | group_by(.role) | map({
      role:     .[0].role,
      count:    length,
      running:  map(select(.status == "running")) | length,
      avg_cpu:  avg(.cpu_pct),
      avg_mem:  avg(.mem_pct),
      max_disk: (max_by(.disk_pct) | "\(.hostname) \(.disk_pct)%")
  })),
  alerts: [ .servers[] | {hostname, issues: problems} | select(.issues | length > 0) ]
}
bash · fleet_health.sh
#!/usr/bin/env bash
# fleet_health.sh - human report + JSON summary from servers.json
set -euo pipefail
inv="${1:-datasets/servers.json}"

summary=$(jq --argjson cpu 80 --argjson mem 85 --argjson disk 80 -f fleet_health.jq "$inv")
printf '%s\n' "$summary" > fleet_summary.json            # for other tools

jq -r '"Fleet \(.datacenter) at \(.generated): \(.total) servers\n"' <<< "$summary"

{
  echo -e "ROLE\tCOUNT\tRUNNING\tAVG_CPU\tAVG_MEM\tFULLEST_DISK"
  jq -r '.by_role[] | [.role, .count, .running, .avg_cpu, .avg_mem, .max_disk] | @tsv' <<< "$summary"
} | column -t -s $'\t'

echo
alerts=$(jq '.alerts | length' <<< "$summary")
echo "ALERTS ($alerts):"
jq -r '.alerts[] | "  \(.hostname): \(.issues | join(", "))"' <<< "$summary"

# non-zero exit when there are alerts, so cron/CI can react
(( alerts == 0 ))

Key ideas:

  • jq program file (-f fleet_health.jq): long filters are easier to read in a file with comments; $cpu, $mem, $disk come from --argjson as numbers.

  • The jq output is kept in a shell variable and queried several times with <<<, the inventory is processed once.

#!/usr/bin/env bash
# dns_export.sh - inspect and export a Cloudflare "list DNS records" response
set -euo pipefail
resp="${1:-datasets/cf_dns_records.json}"

# 1. Check the envelope: success must be true, otherwise print the API errors
if ! jq -e '.success == true' "$resp" > /dev/null; then
  jq -r '.errors[] | "API error \(.code): \(.message)"' "$resp" >&2
  exit 1
fi
jq -r '.result_info | "zone records: \(.count) of \(.total_count) (page \(.page)/\(.total_pages))"' "$resp"

# 2. Human-readable table, sorted by type then name
echo
jq -r '.result | sort_by(.type, .name)[]
       | [.type, .name, .content, (if .ttl == 1 then "auto" else (.ttl | tostring) end),
          (if .proxied then "proxied" else "DNS-only" end)] | @tsv' "$resp" | column -t -s $'\t'

# 3. Minimal backup that can be POSTed back to the API record by record
jq '[.result[] | {type, name, content, ttl, proxied}]' "$resp" > dns_backup.json
echo
echo "backup: $(jq length dns_backup.json) records -> dns_backup.json"

# 4. Proxiable A/AAAA/CNAME records that are NOT proxied (origin IP exposed)
echo
echo "Exposed (proxiable but DNS-only):"
jq -r '.result[] | select(.proxiable and (.proxied | not)) | "  \(.name) -> \(.content)"' "$resp"

# 5. Lookup index name -> {type: id}, used by update scripts
jq 'reduce .result[] as $r ({}; .[$r.name][$r.type] = $r.id)' "$resp" > dns_index.json
echo
echo "id of the example.com MX record: $(jq -r '."example.com".MX' dns_index.json)"

Explanation:

  • Envelope check first. On failure Cloudflare still returns a JSON body, with "success": false and an errors array (plus a 4xx status that curl -s silently accepts unless you add --fail). jq -e '.success == true' turns that into an exit status.
  • sort_by(.type, .name) sorts by type, then by name within a type.
  • {type, name, content, ttl, proxied}: the object shorthand keeps just those keys, giving exactly the body format the create DNS record endpoint accepts; replaying is jq -c '.[]' dns_backup.json | while read -r body; do curl ... --data "$body"; done.
  • select(.proxiable and (.proxied | not)): records that could hide the origin behind Cloudflare but do not; not is a filter in jq, so it is piped into.
  • .[$r.name][$r.type] = $r.id inside reduce creates nested objects on the fly; keys with dots must be quoted when read back: ."example.com".MX.

Viva / exam questions

What does .[] do?

It iterates: outputs each element of an array (or each value of an object) as a separate result in the stream.

Difference between map(f) and .[] | f?

.[] | f produces a stream of separate values; map(f) is [.[] | f] and collects them into one array.

Why use -r?

To output strings without JSON quotes, so they can be used directly as shell values or plain text.

How do you pass a shell variable into jq safely?

--arg name "$var" (string) or --argjson name "$var" (JSON value), then use $name inside a single-quoted filter.

How do you convert JSON to CSV?

Build an array of fields per record and pipe to @csv with -r: jq -r '.[] | [.id, .name] | @csv'.

What does // do?

It is the alternative operator: a // b returns a unless a is null, false or empty, in which case it returns b.

What is the difference between -s and -n?

-s reads all inputs into one array before running the filter; -n reads nothing automatically (input is null) and you pull values with input/inputs or build JSON from arguments.

How do you change a value inside a JSON file?

Use an update such as jq '.a.b = 5' f.json > tmp && mv tmp f.json; jq outputs the whole modified document.

What does group_by(.role) return?

An array of arrays: the input array sorted by .role and split into groups with equal role values.
