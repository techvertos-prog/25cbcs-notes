cut, tr, paste, wc, head, tail, tee

Small single-purpose filters that you chain in almost every pipeline: cut picks columns, tr translates or deletes characters, paste joins lines side by side, wc counts, head/tail take the start or end, tee saves a copy mid-pipe and column lines everything up.

Commands: cut, tr, paste, wc, head, tail, tee, columnGNU coreutils~40 min

Syntax and mental model

bash · syntax
cut  -d DELIM -f LIST [file...]     # fields      cut -c LIST [file...]   # characters
tr   [-d|-s|-c] SET1 [SET2]          # stdin only! no file argument
paste [-d DELIMS] [-s] file...      # "-" means stdin
wc   [-l|-w|-c|-m] [file...]
head [-n N|-c N] [file...]           tail [-n N|-n +N|-c N|-f|-F] [file...]
tee  [-a] file...                    # stdin -> stdout AND file(s)
column -t [-s SEP]                   # align into a table
  • cut splits every line on exactly one delimiter character (default TAB) and prints the fields you list. Two spaces in a row mean an empty field between them, which is why cut struggles with space-aligned text (use tr -s ' ' first, or awk).
  • tr works on single characters, not words. It maps the 1st char of SET1 to the 1st char of SET2, and so on. It only reads stdin: write tr a b < file, not tr a b file.
  • paste is the opposite of cut: it glues line 1 of each file together, then line 2, … With -s it glues all lines of one file into a single line.
  • tee is a T-junction in the pipe: data continues to stdout and is also written to a file.

cut: select columns

Fields from a CSV

bash
cut -d, -f2,5 datasets/employees.csv | head -4    # name and salary
output
name,salary
Aarav Kapoor,110000
Priya Sharma,135000
Rohan Mehta,84000

Fields come out in file order, joined by the same delimiter. -f5,2 prints the same as -f2,5: cut cannot reorder (use awk for that).

Ranges

bash
cut -d, -f2-4 datasets/employees.csv | head -3    # fields 2 to 4
cut -d, -f5-  datasets/employees.csv | head -3    # field 5 to the end
output
name,department,city
Aarav Kapoor,Engineering,Delhi
Priya Sharma,Engineering,Delhi
salary,join_date
110000,2023-08-11
135000,2023-02-27

--complement and --output-delimiter (GNU)

bash
cut -d, -f1,6 --complement datasets/employees.csv | head -3
cut -d, -f2,3 --output-delimiter=' | ' datasets/employees.csv | head -3
output
name,department,city,salary
Aarav Kapoor,Engineering,Delhi,110000
Priya Sharma,Engineering,Delhi,135000
name | department
Aarav Kapoor | Engineering
Priya Sharma | Engineering
GNU vs BSDmacOS cut has neither long option. Portable equivalents: cut -d, -f2-5 for the first, and cut -d, -f2,3 | sed 's/,/ | /' or awk -F, '{print $2" | "$3}' for the second.

Characters with -c

bash
cut -c1-15 datasets/access.log | head -2
cut -d, -f6 datasets/employees.csv | tail -n +2 | cut -c1-4 | sort | uniq -c | head -3   # join year
output
192.168.1.10 -

Space-separated data: cut's weak spot

bash
cut -d' ' -f2 datasets/servers.txt                 # empty! many spaces = many empty fields
tr -s ' ' < datasets/servers.txt | cut -d' ' -f1,2  # squeeze first, then cut

Complement with -c

-c inverts SET1. -cd = "delete everything except", -cs = "turn every run of non-matching chars into one":

bash
echo 'p@ss W0rd!#2026' | tr -cd '[:alnum:]'; echo        # keep letters+digits only
tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 16; echo      # random 16-char password

# one word per line -> word frequency
echo "The quick, brown fox; the LAZY dog... the end!" |
  tr -cs '[:alpha:]' '\n' | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -3
output
pssW0rd2026
kQ7ZpX2mVb9LwT4e
      3 the
      1 quick
      1 lazy

The password line is random and will differ every run. In the word count, ties keep the reverse whole-line order from sort -rn.

Use cases

Use case 1 Extract and reformat CSV columns for one department

HR wants a name/salary sheet for a single department. Instead of hard-coding field numbers, the script looks them up from the header with tr + grep -n + cut, so it keeps working if columns are re-ordered. tee saves the CSV while column prints a readable table.

bash · csv_extract.sh
#!/usr/bin/env bash
# csv_extract.sh - pull name and salary for one department out of employees.csv
# usage: ./csv_extract.sh [department] [csv] [outfile]
set -euo pipefail

dept="${1:-Engineering}"
csv="${2:-datasets/employees.csv}"
out="${3:-dept_salaries.csv}"
[[ -r "$csv" ]] || { echo "error: $csv not readable" >&2; exit 1; }

# look up a column number by its header name (survives column re-ordering)
header=$(head -n 1 "$csv")
col() { tr ',' '\n' <<< "$header" | grep -nx "$1" | cut -d: -f1; }
f_name=$(col name)
f_sal=$(col salary)

{
  echo "NAME,SALARY"
  tail -n +2 "$csv" |
    grep ",${dept}," |                  # rows for that department
    cut -d, -f"${f_name},${f_sal}"      # keep name + salary only
} | tee "$out" | column -t -s,          # save CSV, show aligned table

rows=$(( $(wc -l < "$out") - 1 ))
echo "----"
echo "$rows rows saved to $out (name=field $f_name, salary=field $f_sal)"
bash · run it
./csv_extract.sh Finance
cat dept_salaries.csv
output
NAME         SALARY
Arjun Nair   94000
Isha Das     93000
Tanvi Joshi  84000
----
3 rows saved to dept_salaries.csv (name=field 2, salary=field 5)
NAME,SALARY
Arjun Nair,94000
Isha Das,93000
Tanvi Joshi,84000

Tricky parts. col() turns the header into one name per line; grep -nx salary matches the whole line exactly and prefixes the line number (5:salary); cut -d: -f1 keeps the 5. The { …; } group sends the header and the data through one tee. grep ",Finance," with commas on both sides avoids matching a name that merely contains the word. For quoted CSV with embedded commas, switch to a CSV-aware tool.

Use case 2 Clean and normalise a messy list

A colleague emails a host list copied from Excel on Windows: CRLF line endings, mixed case, commas, semicolons, tabs, stray quotes and duplicates. Before you loop over it with ssh, normalise it to one clean hostname per line. Every step is a single tr.

bash · create the messy input
printf 'WEB01, web02 ;DB01\r\n\r\n  cache01\t\tWeb01\r\nmon01*, db01\r\n\r\nLB-01 ,"web03"\r\n' > messy.txt
cat -v messy.txt          # -v shows the CR characters as ^M
output
WEB01, web02 ;DB01^M
^M
  cache01		Web01^M
mon01*, db01^M
^M
LB-01 ,"web03"^M
bash · clean_hosts.sh
#!/usr/bin/env bash
# clean_hosts.sh - normalise a messy host list (from Excel/Windows/email) into
#                  one lowercase hostname per line, sorted, no duplicates
# usage: ./clean_hosts.sh messy.txt > hosts.txt     (or pipe into it)
set -euo pipefail

raw=$(cat -- "${1:--}")                 # read file (or stdin when no arg) once

printf '%s\n' "$raw" |
  tr -d '\r' |                          # 1. strip Windows CR characters
  tr ',;\t ' '\n' |                     # 2. commas, semicolons, tabs, spaces -> newlines
  tr '[:upper:]' '[:lower:]' |          # 3. lowercase
  tr -cd 'a-z0-9.\n-' |                 # 4. delete anything not valid in a hostname
  tr -s '\n' |                          # 5. squeeze runs of newlines (drops blank lines)
  grep -v '^$' |                        # 6. a leading empty line can survive step 5
  sort -u                               # 7. sort + de-duplicate
bash · run it
./clean_hosts.sh messy.txt | tee hosts.txt
wc -l < hosts.txt
output
cache01
db01
lb-01
mon01
web01
web02
web03
7

How it works. Step 2 maps four separator characters to newline, so every token lands on its own line. Step 4 is -c + -d: delete the complement of the allowed set, removing * and "; \n must be in the allowed set or all lines would merge, and - goes last so it is not read as a range. Steps 5–6 drop the empty lines created by consecutive separators. Nine raw tokens (with three duplicates of web01) become seven unique hosts.

Use case 3 Build a quick disk report with cut, paste and column

You want an aligned report of mount, size and usage with a status column, saved to a dated file for the record. The script slices columns with cut, generates a new column in a loop, glues them with paste, aligns with column and saves with tee.

bash · disk_report.sh
#!/usr/bin/env bash
# disk_report.sh - aligned disk usage report built from columns with cut/tr/paste/column
# usage: ./disk_report.sh [df-output-file] [warn%]
set -euo pipefail

src="${1:-datasets/df.txt}"   # on a live box: df -h > /tmp/df.txt; ./disk_report.sh /tmp/df.txt
warn="${2:-90}"
report="disk_report_$(date +%F).txt"

body=$(tail -n +2 "$src" | tr -s ' ')          # drop header, squeeze spaces -> cut works

mounts=$(cut -d' ' -f6 <<< "$body")
sizes=$(cut -d' ' -f2 <<< "$body")
pcts=$(cut -d' ' -f5 <<< "$body" | tr -d '%')  # "87%" -> "87"

# build a STATUS column, one line per filesystem
status=$(while read -r p; do
           if (( p >= warn )); then echo "CRITICAL"; else echo "ok"; fi
         done <<< "$pcts")

{
  echo "MOUNT SIZE USE% STATUS"
  paste -d' ' <(echo "$mounts") <(echo "$sizes") <(echo "$pcts") <(echo "$status")
} | column -t | tee "$report"

echo "----"
echo "$(grep -c CRITICAL "$report") of $(( $(wc -l < "$report") - 1 )) filesystems at or above ${warn}%"
bash · run it
./disk_report.sh datasets/df.txt 90
output
MOUNT    SIZE  USE%  STATUS
/        50G   87    ok
/var     200G  64    ok
/backup  500G  96    CRITICAL
/run     3.9G  1     ok
/home    100G  13    ok
/data    1.0T  92    CRITICAL
----
2 of 6 filesystems at or above 90%

Explanation. tr -s ' ' turns the aligned df output into single-space separated fields so cut -d' ' can index them. Each column is held in a variable with one value per line; <(echo "$var") (process substitution) presents each as a file to paste, which zips them line by line. column -t then pads everything. The report file is named disk_report_2026-11-16.txt on the day it runs. On real df output, a long device name can wrap onto its own line; use df -hP (POSIX format) to prevent that.

Gotchas

ProblemCause and fix
cut -d' ' returns empty fieldsMultiple spaces between columns. tr -s ' ' first, or use awk '{print $2}'.
cut -d', ' error "the delimiter must be a single character"cut only takes one character. Use awk -F', '.
cut -f3,1 did not reordercut always prints in input order. Use awk -F, -v OFS=, '{print $3,$1}'.
tr 'abc' 'xyz' file error "extra operand"tr reads stdin only: tr 'abc' 'xyz' < file.
tr 'hello' 'world' mangles texttr maps characters, not strings. Use sed 's/hello/world/g'.
tr a-z A-Z unquoted behaves oddlyUnquoted brackets/ranges can be glob-expanded by the shell. Always quote sets.
tr and UTF-8GNU tr works on bytes, so tr '[:lower:]' '[:upper:]' does not uppercase é. Use sed 's/.*/\U&/' or awk '{print toupper($0)}' in a UTF-8 locale.
wc -l one less than expectedLast line has no trailing newline.
head -n -5 fails on macOSNegative counts are GNU only. Portable: sed '$d' repeatedly, or awk with a buffer.
tail -f stops showing lines after rotationUse tail -F.
cmd > f | tee shows nothingOutput already went to the file. Put tee last: cmd | tee f.
