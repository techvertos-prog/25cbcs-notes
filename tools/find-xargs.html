find & xargs: locate files and act on them

find walks a directory tree and selects files by name, type, size, age, permissions or owner, then prints them or runs a command on each. xargs turns a list on stdin into command-line arguments, in batches or in parallel. Together they power every cleanup, backup-retention and bulk-edit script.

Commands: find, xargsGNU findutils~45 minUsed in Lab 11, Lab 07

Syntax and mental model

bash · syntax
find [start-dir...] [tests and actions...]
#     where to look   what to match and what to do (evaluated left to right per file)

some-command-producing-names | xargs [options] command [initial-args]

How find thinks. For every file under the start directory, find evaluates the expression left to right, like an if chain. Tests (-name, -mtime…) return true or false. Adjacent tests are joined with an implicit AND (-a); -o is OR, ! or -not is NOT, and \( … \) groups. Evaluation stops at the first false in an AND chain. Actions (-print, -exec, -delete) are also expressions; if you give no action, find adds -print around the whole expression.

How xargs thinks. It reads whitespace- or newline-separated words (or NUL-separated with -0) and appends as many as fit to the command, running it as few times as possible. Options change batch size (-n), placement (-I{}) and parallelism (-P).

Viva-exec cmd {} \; runs cmd once per file. -exec cmd {} + and xargs run it once per batch of files, which is much faster for thousands of files.

Practice tree (setup script)

find is about real files, so this page uses a throw-away tree with files of known ages and sizes. The script works on Linux and macOS: touch -t sets the modification time, and ago() computes "N days ago" with either GNU date -d or BSD date -v. Run it in a scratch directory, never in your home folder.

bash · make_practice_tree.sh
#!/usr/bin/env bash
# make_practice_tree.sh - build a throw-away directory tree for find/xargs practice
# usage: ./make_practice_tree.sh [dir]   (default dir: practice), then cd practice
set -euo pipefail

# "N days ago" as a touch -t timestamp (works with GNU date and BSD/macOS date)
ago() { date -d "-$1 days" +%Y%m%d%H%M 2>/dev/null || date -v-"$1"d +%Y%m%d%H%M; }
# make FILE AGE_DAYS [SIZE_KB]: create file with given age and size
mk() {
  local f="$1" age="$2" kb="${3:-1}"
  mkdir -p "$(dirname "$f")"
  dd if=/dev/zero of="$f" bs=1024 count="$kb" 2>/dev/null
  touch -t "$(ago "$age")" "$f"
}

root="${1:-practice}"
rm -rf "$root"; mkdir -p "$root"; cd "$root"

Security audits use find / -xdev -type f -perm -o+w (world-writable files) and find / -perm -4000 (setuid programs). -perm /u+x,g+x means "any of these bits".

Operators, grouping and -prune

AND, OR and why you need parentheses

bash
find . -name '*.log' -o -name '*.sql' | sort
output
./backups/db-daily.sql
./backups/db-monthly.sql
./logs/app.log

AND binds tighter than OR. Compare these two:

bash
find . -type f -name '*.log' -o -name '*.gz' -mtime +30 | sort         # WRONG grouping
echo ---
find . -type f \( -name '*.log' -o -name '*.gz' \) -mtime +30 | sort   # right
output
./logs/app.log
./logs/old/archive.log.gz
---
./logs/old/archive.log.gz

The first reads as (f AND *.log) OR (*.gz AND +30), so the brand-new app.log sneaks in. Parentheses must be escaped (\( \)) and separated by spaces, because they are separate arguments to find. In a -delete command this mistake deletes the wrong files.

NOT

bash
find . -type f -path './logs/*' ! -name '*.log' | sort    # everything in logs except *.log
output
./logs/app.log.1
./logs/app.log.2
./logs/app.log.3
./logs/error.LOG
./logs/old/archive.log.gz

Actions: -print0, -exec, -delete, -ls

-exec with \; versus +

bash
find . -type f -name '*.sh' -exec echo run: {} \;    # one echo per file
find . -type f -name '*.sh' -exec echo run: {} +     # one echo for all files
output
run: ./src/main.sh
run: ./src/util.sh
run: ./src/lib/helpers.sh
run: ./src/main.sh ./src/util.sh ./src/lib/helpers.sh

{} is replaced by the path. \; (escaped so the shell does not eat it) ends the command. With +, {} must be the last thing before +. (The order of files depends on the directory layout on disk and may differ on your machine.)

find . -type f -name '*.sql' -printf '%s %p\n'        # GNU: custom format, bytes + path

xargs

Batching

bash
printf '%s\n' a b c d e f | xargs          # default command is echo, one batch
printf '%s\n' a b c d e f | xargs -n 2     # at most 2 args per run
output
a b c d e f
a b
c d
e f

Why -print0 | xargs -0

By default xargs splits on any whitespace, and also treats quotes and backslashes specially. A file called My Notes.txt becomes two arguments:

bash
find . -type f -name '*.txt' | xargs wc -c                # broken
find . -type f -name '*.txt' -print0 | xargs -0 wc -c     # safe
output
wc: ./src/My: No such file or directory
wc: Notes.txt: No such file or directory
0 total
1024 ./src/My Notes.txt

A NUL byte is the only character that cannot appear in a Unix path, so -print0 + -0 is safe for spaces, quotes and even newlines in names. Other tools speak NUL too: sort -z, grep -z, tar --null -T -.

bash
find logs -type f -print0 | sort -z | xargs -0 -n 2 echo batch:
output
batch: logs/app.log logs/app.log.1
batch: logs/app.log.2 logs/app.log.3
batch: logs/error.LOG logs/old/archive.log.gz

-I{}: put the argument anywhere

bash
find src -name '*.sh' | sort | xargs -t -I{} cp {} {}.bak     # -t echoes each command
find . -name '*.bak' -print -delete | sort                     # clean up again
output
cp src/lib/helpers.sh src/lib/helpers.sh.bak
cp src/main.sh src/main.sh.bak
cp src/util.sh src/util.sh.bak
./src/lib/helpers.sh.bak
./src/main.sh.bak
./src/util.sh.bak

-I{} implies one command per input line and treats the whole line as one argument (leading blanks are stripped), so it is space-safe for names without newlines.

-r: do nothing on empty input

bash
printf '' | xargs echo "ran anyway:"       # GNU runs echo once with no file args
printf '' | xargs -r echo "ran anyway:"    # -r: skip when there is no input
output
ran anyway:

This matters for commands like xargs rm (prints a "missing operand" error) or xargs grep pattern (would wait for stdin). BSD/macOS xargs already skips empty input.

xargs vs -exec +

NeedUse
Simple: run a command on all matchesfind … -exec cmd {} + (no pipe, always space-safe)
Parallel executionfind … -print0 | xargs -0 -P N cmd
Filter the list between find and the command (sort, grep, head)find … -print0 | sort -z | xargs -0 cmd
Input not from find (a file of names, a command's output)xargs -a list.txt cmd or cat list | xargs cmd
Shell logic per file (variables, ${f%.x})-exec sh -c 'for f do …; done' sh {} +

Use cases

Use case 1 Clean up old logs safely (dry run first)

A retention policy says log files older than 30 days must go. The script selects files in exactly one function, shows what it would delete and how much space that frees, and only deletes when called with --delete. This is the pattern used in Lab 11.

bash · clean_old_logs.sh
#!/usr/bin/env bash
# clean_old_logs.sh - delete log files older than N days; DRY RUN unless --delete
# usage: ./clean_old_logs.sh [--delete] DIR [DAYS]
set -euo pipefail

mode="dry-run"
if [[ "${1:-}" == "--delete" ]]; then mode="delete"; shift; fi
dir="${1:?usage: $0 [--delete] DIR [DAYS]}"
days="${2:-30}"
[[ -d "$dir" ]] || { echo "error: $dir is not a directory" >&2; exit 1; }
[[ "$days" =~ ^[0-9]+$ ]] || { echo "error: DAYS must be a number" >&2; exit 2; }

# the selection, defined ONCE so dry-run and delete can never disagree
select_files() {
  find "$dir" -type f \( -name '*.log' -o -name '*.log.[0-9]*' -o -name '*.log.gz' \) \
       -mtime +"$days" -print0
}

count=$(( $(select_files | tr -cd '\0' | wc -c) ))   # count NUL terminators
if (( count == 0 )); then echo "nothing older than $days days in $dir"; exit 0; fi

echo "[$mode] $count file(s) older than $days days in $dir:"
select_files | sort -z | xargs -0 du -k | awk '{kb+=$1; print "  " $2} END {print "  total: " kb " KB"}'

if [[ "$mode" == "delete" ]]; then
  select_files | xargs -0 rm -f --
  echo "deleted."
else
  echo "dry run only - re-run with --delete to remove them"
fi

Key points. The \( … -o … \) group keeps -mtime applying to all three name patterns. Use case 2 Bulk rename and compress files

An application writes error.LOG with an upper-case extension and never compresses its rotated logs. Fix both in one pass: rename with shell parameter expansion inside -exec sh -c, and gzip rotated logs four at a time with xargs -P.

bash · tidy_logs.sh
#!/usr/bin/env bash
# tidy_logs.sh - bulk-rename *.LOG to *.log, then gzip rotated logs in parallel
# usage: ./tidy_logs.sh DIR
set -euo pipefail
dir="${1:?usage: $0 DIR}"

# 1. bulk rename: one sh process receives many files via {} +
find "$dir" -type f -name '*.LOG' -exec sh -c '
  for f do
    mv -v -- "$f" "${f%.LOG}.log"
  done' sh {} +

# 2. compress rotated logs (app.log.1, app.log.2 ...) that are not yet gzipped,
#    4 gzip processes at a time, 1 file each
find "$dir" -type f -name '*.log.[0-9]*' ! -name '*.gz' -print0 |
  xargs -0 -r -P 4 -n 1 gzip -9

# 3. show the result
find "$dir" -type f | sort

How it works. In sh -c '…' sh {} + the first word after the script (sh) becomes $0, and the file names become $1 $2 …, which for f do loops over. Using positional arguments, rather than pasting {} into the script text, is what keeps odd file names safe. ${f%.LOG} strips the suffix. The ! -name '*.gz' test prevents gzipping archive.log.gz again. gzip keeps the original timestamp, so later age-based cleanup still works.

Use case 3 Parallel checksums and search across many files

Before copying backups off-site you want a SHA-256 manifest you can verify on the other side. On a server with many large files, hashing in parallel uses all CPU cores. The same find/xargs pattern also searches many files at once.

bash · checksum_manifest.sh
#!/usr/bin/env bash
# checksum_manifest.sh - parallel SHA-256 manifest of a directory, then verify it
# usage: ./checksum_manifest.sh DIR [MANIFEST]
set -euo pipefail
export LC_ALL=C
dir="${1:?usage: $0 DIR [MANIFEST]}"
manifest="${2:-SHA256SUMS}"
jobs=$(nproc 2>/dev/null || echo 4)          # one sha256sum per CPU core

# -P runs several sha256sum at once; -n 4 hands each one 4 files.
# Parallel output arrives in random order, so sort by file name (field 2).
find "$dir" -type f -print0 |
  xargs -0 -r -P "$jobs" -n 4 sha256sum |
  sort -k2 > "$manifest"

echo "$(wc -l < "$manifest") files hashed with $jobs parallel jobs -> $manifest"

# verification: sha256sum -c re-reads every file and compares
if sha256sum --quiet -c "$manifest"; then
  echo "verify: all OK"
else
  echo "verify: MISMATCH found" >&2
  exit 1
fi

grep -l lists matching files; grep -c counts per file and grep -v ':0$' hides files with no hits. Dots are escaped because in a regex . matches any character. (Plain grep -rl also works; the find version lets you add -mtime, -size or -prune filters and run in parallel.)

Gotchas

ProblemCause and fix
find: paths must precede expressionUnquoted -name *.log was expanded by the shell. Quote it: -name '*.log'.
Wrong files matched with -oAND binds tighter than OR. Group with \( … \).
Everything deleted-delete placed before the tests. Tests first, action last; dry-run with -print.
-size -1M matches nothingRounding up to whole units. Use -size -1024k.
-mtime 1 misses a file from 30 hours ago... or notAge is truncated to whole days: 30 h is day 1. Use -mmin for precision.
xargs breaks on spaces / quotes ("unmatched single quote")Use -print0 | xargs -0.
-exec … {} \; is slowOne process per file. Use {} + or xargs.
missing argument to `-exec'Forgot \; or +, or did not escape ;.
"Permission denied" noisefind / … 2>/dev/null, and add -xdev to stay on one filesystem.
-maxdepth warningGNU wants global options like -maxdepth before tests.
BSD/macOS differencesNo -printf; find needs a start dir (find .); xargs -r is default; use -perm +mode on old BSD instead of /mode.

Practice exercises

Run these inside a fresh practice/ tree.

1. List all files bigger than 1 MiB OR older than 50 days, excluding directories.
bash
find . -type f \( -size +1M -o -mtime +50 \) | sort
output
./backups/db-daily.sql
./logs/app.log.3
./logs/old/archive.log.gz
2. Find all shell scripts that are NOT executable and make them executable in one chmod call.
bash
find . -type f -name '*.sh' ! -perm -u+x -print -exec chmod u+x {} + | sort
output
./src/lib/helpers.sh
./src/util.sh
3. Delete empty files and empty directories under tmp (show what you delete).
bash
find tmp -mindepth 1 -empty -print -delete | sort
output
tmp/cache.tmp
tmp/empty

-mindepth 1 protects tmp itself, which becomes empty after its contents go.

4. Total size in KB of all .sql files, using find + xargs + awk.
bash
find . -type f -name '*.sql' -print0 | xargs -0 du -k | awk '{s+=$1} END {print s " KB"}'
output
3072 KB
5. Copy every file changed in the last 7 days (skipping node_modules) into a directory ../recent, keeping names.
bash
mkdir -p ../recent
find . -name node_modules -prune -o -type f -mtime -7 -print0 | xargs -0 -r cp -t ../recent
ls ../recent
output
README.md
app.log
app.log.1
cache.tmp
db-daily.sql
main.sh
site.tar.gz

cp -t DIR (GNU) puts the target first so xargs can append the files at the end. On macOS use xargs -0 -J % cp % ../recent.
