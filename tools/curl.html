curl: HTTP from the shell

curl sends HTTP requests and prints the response. It is how shell scripts talk to REST APIs (Cloudflare, GitHub), check whether a website is up, measure latency and download files reliably. This page covers requests and headers, JSON bodies, authentication, status codes, timeouts and retries, and how to wire it all into scripts with proper error handling.

Command: curlcurl 7.82+ / 8.x~45 minUsed in Lab 05, Lab 12, Lab 04
Network examplesEverything on this page talks to public test services: httpbin.org (echoes back what you send), api.github.com and example.com. Outputs are labelled sample output because dates, timings, star counts and your IP will differ. Install with sudo apt install curl jq.

Syntax and mental model

bash · syntax
curl [options] URL
curl -X METHOD -H 'Header: value' -d 'body' URL

An HTTP exchange has two halves:

  1. Request = method (GET, POST, PUT, PATCH, DELETE) + URL + headers + optional body. curl builds this from your options.
  2. Response = status line (HTTP/2 200) + headers + body. By default curl prints only the body to stdout, and progress/errors to stderr.

The most important idea for scripting: curl's exit code is about the transfer, not the HTTP status. A 404 or 500 page is a successful transfer, so curl exits 0 unless you add -f. To make decisions, either use -f or capture the status code with -w '%{http_code}'.

Query strings

bash
curl -s -G --data-urlencode 'q=disk full' -d 'page=2' https://httpbin.org/get | jq -c '{args, url}'
sample output
{"args":{"page":"2","q":"disk full"},"url":"https://httpbin.org/get?q=disk+full&page=2"}

-G moves the data into the URL; --data-urlencode escapes the space. Writing the URL by hand works too, but quote it: an unquoted & sends curl to the background.

Status codes, -f and -w

Why -f matters

bash
curl -s https://httpbin.org/status/500; echo "exit=$?"     # transfer worked -> 0
curl -sf https://httpbin.org/status/500; echo "exit=$?"    # -f: HTTP error -> 22, silent
curl -sSf https://httpbin.org/status/500; echo "exit=$?"   # -S: still show the error
sample output
exit=0
exit=22
curl: (22) The requested URL returned error: 500
exit=22
Script defaultcurl -fsSL is the standard combination for scripts: fail on HTTP errors, no progress bar, but print error messages, and follow redirects.

Write-out variables (-w)

bash
curl -s -o /dev/null -w '%{http_code}\n' https://httpbin.org/status/404
curl -s -o /dev/null -w 'code=%{http_code} time=%{time_total}s size=%{size_download}B\n' https://example.com
curl -s -o /dev/null -w 'dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer} total=%{time_total}\n' https://example.com
sample output
404
code=200 time=0.332801s size=577B
dns=0.003820 connect=0.026330 tls=0.048280 ttfb=0.067062 total=0.067200
VariableValue
%{http_code}Status of the last response (000 if no response)
%{time_namelookup} … %{time_total}Seconds: DNS, TCP connect, TLS done, first byte, total (cumulative)
%{size_download}Body bytes downloaded
%{content_type}Content-Type of the response
%{url_effective} / %{num_redirects}Final URL after -L / number of redirects followed
%{remote_ip}IP address actually connected to

Body and status in one request

A common pattern: save the body to a file and capture the code in a variable, so you can print the body only on success:

bash
code=$(curl -s -o /tmp/body.json -w '%{http_code}' https://httpbin.org/status/404)
if [[ "$code" == 2* ]]; then jq . /tmp/body.json; else echo "request failed: HTTP $code" >&2; fi
sample output
request failed: HTTP 404

Redirects

bash
curl -sI https://httpbin.org/redirect/2 | head -1                 # without -L: the 302 itself
curl -sL -o /dev/null -w '%{http_code} after %{num_redirects} redirects -> %{url_effective}\n' \
     https://httpbin.org/redirect/2
sample output
HTTP/2 302
200 after 2 redirects -> https://httpbin.org/get

Sending data: forms, JSON, methods, uploads

Form data with -d (POST)

bash
curl -s -d 'name=asha&role=dev' https://httpbin.org/post | jq '{form, ct: .headers["Content-Type"]}'
sample output
{
  "form": {
    "name": "asha",
    "role": "dev"
  },
  "ct": "application/x-www-form-urlencoded"
}

-d implies POST and form encoding. For JSON you must change the Content-Type, or use --json.

JSON bodies

bash
# classic form (works with every curl version)
curl -s -H 'Content-Type: application/json' --data-raw '{"name":"asha","role":"dev"}' https://httpbin.org/post

# curl 7.82+: --json sets Content-Type AND Accept for you
curl -s --json '{"name":"asha","role":"dev"}' https://httpbin.org/post |
  jq '{json, ct: .headers["Content-Type"], accept: .headers.Accept}'
sample output
{
  "json": {
    "name": "asha",
    "role": "dev"
  },
  "ct": "application/json",
  "accept": "application/json"
}
Build JSON with jq, not string pastingIf values come from variables, let jq do the quoting so a name like O"Brien cannot break the JSON:
body=$(jq -n --arg n "$name" --arg r "$role" '{name:$n, role:$r}') then curl --json "$body" …. Use -d @file.json to send a file.

Other methods: -X

bash
curl -s -X PUT -H 'Content-Type: application/json' -d '{"role":"admin"}' https://httpbin.org/put | jq -c '{url, json}'
curl -s -X DELETE https://httpbin.org/delete | jq -r .url
sample output
{"url":"https://httpbin.org/put","json":{"role":"admin"}}
https://httpbin.org/delete

Do not use -X GET with -d or -X POST with -L unless you mean it: -X forces the method on every request, including the ones after a redirect.

File upload: -F (multipart)

bash
curl -s -F 'file=@report.csv' -F 'note=lab upload' https://httpbin.org/post |
  jq '{files: (.files | keys), form, ct: (.headers["Content-Type"] | .[0:30])}'
sample output
{
  "files": [
    "file"
  ],
  "form": {
    "note": "lab upload"
  },
  "ct": "multipart/form-data; boundary="
}

@ means "read this file". This is what an HTML <input type="file"> form sends. To send a file as the raw body instead, use --data-binary @file or -T file (PUT).

Authentication

Basic auth: -u

bash
curl -s -u student:s3cret https://httpbin.org/basic-auth/student/s3cret
curl -s -o /dev/null -w '%{http_code}\n' -u student:wrong https://httpbin.org/basic-auth/student/s3cret
sample output
{
  "authenticated": true,
  "user": "student",
  "authorized": true
}
401

-u user without a password makes curl prompt for it, which keeps it out of shell history. Basic auth is only Base64, not encryption: use it over HTTPS only.

Bearer tokens (API keys)

bash
export API_TOKEN='TEST_TOKEN_123'          # in real life: read from a file or a secret store
curl -s -H "Authorization: Bearer $API_TOKEN" https://httpbin.org/bearer
sample output
{
  "authenticated": true,
  "token": "TEST_TOKEN_123"
}

This is exactly how the Cloudflare API in Lab 05 works (Authorization: Bearer $CF_API_TOKEN). Double quotes are required so the variable expands. Keep tokens in environment variables or a chmod 600 file, never in the script or in git; note that command-line arguments are visible to other users in ps, so for shared machines prefer -H @headers.txt (curl 7.55+) or a .netrc file.

Cookies: -c and -b

bash
curl -s -c cookies.txt -o /dev/null https://httpbin.org/cookies/set/session/abc123   # server sets cookie, saved to jar
grep session cookies.txt | cut -f6,7
curl -s -b cookies.txt https://httpbin.org/cookies                                    # send it back
curl -s -b 'theme=dark' https://httpbin.org/cookies                                   # send an ad-hoc cookie
sample output
session	abc123
{
  "cookies": {
    "session": "abc123"
  }
}
{
  "cookies": {
    "theme": "dark"
  }
}

Log in once with -c jar, then reuse the session with -b jar on later requests. The jar is a tab-separated Netscape cookie file (field 6 = name, 7 = value).

Timeouts, retries and TLS

bash
curl -sS --max-time 2 https://httpbin.org/delay/5; echo "exit=$?"          # server too slow
curl -sS --connect-timeout 3 https://10.255.255.1/; echo "exit=$?"         # nothing answers
curl -sS https://no-such-host.invalid/; echo "exit=$?"                     # DNS failure
sample output
curl: (28) Operation timed out after 2005 milliseconds with 0 bytes received
exit=28
curl: (28) Failed to connect to 10.255.255.1 port 443 after 3005 ms: Timeout was reached
exit=28
curl: (6) Could not resolve host: no-such-host.invalid
exit=6

Without timeouts curl can hang for minutes (the default connect timeout is 300 s, total has no limit), freezing your cron job. Always set --connect-timeout and --max-time in scripts.

bash
curl -sS --retry 3 --retry-delay 2 --retry-max-time 30 -o data.json https://api.example.com/data

--retry repeats on timeouts and on HTTP 408, 429, 500, 502, 503 and 504 only, not on 404 or 401 (retrying those will not help). Add --retry-all-errors (curl 7.71+) to retry everything.

-k and why not

bash
curl -sS -o /dev/null https://expired.badssl.com/; echo "exit=$?"
curl -sSk -o /dev/null -w '%{http_code}\n' https://expired.badssl.com/
sample output
curl: (60) SSL certificate problem: certificate has expired
More details here: https://curl.se/docs/sslcerts.html
...
exit=60
200
Do not ship -k-k (--insecure) turns off certificate checking, so anyone in the network path can impersonate the server and read your API token. It is acceptable for a one-off test against your own lab box with a self-signed cert. In scripts, fix the cause instead: renew the certificate, install the CA (update-ca-certificates), or pin your own CA with --cacert my-ca.pem.

Piping to jq

bash
curl -fsS https://api.github.com/repos/jqlang/jq |
  jq '{name: .full_name, stars: .stargazers_count, lang: .language}'

curl -fsS 'https://api.github.com/repos/jqlang/jq/releases?per_page=3' |
  jq -r '.[] | [.tag_name, .published_at[:10]] | @tsv'
sample output
{
  "name": "jqlang/jq",
  "stars": 36153,
  "lang": "C"
}
jq-1.8.2	2026-06-20
jq-1.8.1	2025-07-01
jq-1.8.0	2025-06-01

Use -fsS before piping to jq: without -f, an error page (HTML or an error JSON) is fed to jq and you get a confusing parse error or wrong data instead of a clear failure. In a script with set -o pipefail, curl's failure then fails the whole pipeline. Unauthenticated GitHub API calls are limited to 60 per hour per IP.

Use cases

Use case 1 REST API CRUD script with error handling

Every API lab boils down to the same four calls: create, read, update, delete. Wrap curl in one function that adds auth, timeouts and retries, checks the HTTP status and returns non-zero on failure. Here BASE_URL defaults to httpbin's /anything endpoint, which echoes every request back, so the script runs without an account. Set BASE_URL and API_TOKEN to use a real API.

bash · api_crud.sh
#!/usr/bin/env bash
# api_crud.sh - create / read / update / delete a resource over a REST API
# Default BASE_URL is httpbin's /anything endpoint, which echoes back every request,
# so the script runs anywhere. Point BASE_URL at a real API to use it for real.
set -euo pipefail

BASE_URL="${BASE_URL:-https://httpbin.org/anything}"
API_TOKEN="${API_TOKEN:-dummy-token}"          # never hard-code real tokens

# api METHOD PATH [JSON_BODY]  -> prints response body on success, returns 1 on error
api() {
  local method="$1" path="$2" body="${3:-}"
  local tmp code
  tmp=$(mktemp)
  local args=(-sS -X "$method" -o "$tmp" -w '%{http_code}'
              --connect-timeout 5 --max-time 20 --retry 2
              -H "Authorization: Bearer $API_TOKEN"
              -H 'Accept: application/json')
  if [[ -n "$body" ]]; then
    args+=(-H 'Content-Type: application/json' --data-raw "$body")
  fi

  if ! code=$(curl "${args[@]}" "$BASE_URL$path"); then
    echo "ERROR: $method $path - network/curl failure" >&2
    rm -f "$tmp"; return 1
  fi
  if [[ "$code" != 2?? ]]; then
    echo "ERROR: $method $path - HTTP $code: $(head -c 200 "$tmp")" >&2
    rm -f "$tmp"; return 1
  fi
  cat "$tmp"; rm -f "$tmp"
}

# show what the server received (httpbin echoes method, url and JSON body)
summary() { jq -c '{method, url, json}'; }

echo "CREATE"; api POST   /users     '{"name":"Asha","role":"dev"}'  | summary
echo "READ";   api GET    /users/42                                  | summary
echo "UPDATE"; api PATCH  /users/42  '{"role":"admin"}'              | summary
echo "DELETE"; api DELETE /users/42                                  | summary

echo "ERROR HANDLING"
if ! BASE_URL="https://httpbin.org" api GET /status/404 >/dev/null; then
  echo "handled: request failed, script continues"
fi

chmod +x api_crud.sh
./api_crud.sh
# against a real API:
# BASE_URL=https://api.example.com/v1 API_TOKEN="$(cat ~/.config/myapi.token)" ./api_crud.sh
sample output
CREATE
{"method":"POST","url":"https://httpbin.org/anything/users","json":{"name":"Asha","role":"dev"}}
READ
{"method":"GET","url":"https://httpbin.org/anything/users/42","json":null}
UPDATE
{"method":"PATCH","url":"https://httpbin.org/anything/users/42","json":{"role":"admin"}}

{"method":"DELETE","url":"https://httpbin.org/anything/users/42","json":null}

ERROR: GET /status/404 - HTTP 404:

Design notes. The curl arguments are built in a Bash array, so headers with spaces stay single arguments and the JSON body is added only when present. Two separate failure paths: curl's own exit code (DNS, timeout, TLS) and the HTTP status from -w '%{http_code}'. [[ "$code" != 2?? ]] is a glob match: anything that is not 2xx is an error. The body goes to a temp file so the status code is the only thing on stdout. Because of set -o pipefail, a failing api … | summary stops the script, while the last call shows how to handle an expected failure with if !.

Use case 2 Uptime and latency checker

Read the http services from services.txt, request each with timeouts, compare the status with the expected code, flag slow responses, print a table and append a CSV line per check for history. Exit status 1 when anything failed, so cron or a monitoring wrapper can alert (see Lab 12).

bash · uptime_check.sh
#!/usr/bin/env bash
# uptime_check.sh - check every "http" service in services.txt: status code + latency
# usage: ./uptime_check.sh [services.txt] [slow-threshold-seconds]
set -uo pipefail                       # no -e: a failing check must not stop the loop

list="${1:-datasets/services.txt}"
slow="${2:-1.0}"
log="uptime_$(date +%Y%m%d).csv"
fails=0

printf '%-12s %-34s %5s %8s  %s\n' SERVICE URL CODE TIME RESULT
while read -r name type target expect; do
  [[ -z "$name" || "$name" == \#* || "$type" != "http" ]] && continue

  # -w prints "code seconds"; on network errors curl exits non-zero and code is 000
  out=$(curl -sS -o /dev/null -w '%{http_code} %{time_total}' \
             --connect-timeout 5 --max-time 10 -L "$target" 2>/tmp/curl_err.$$)
  rc=$?
  read -r code secs <<< "$out"

  if (( rc != 0 )); then
    result="DOWN (curl exit $rc: $(sed 's/^curl: ([0-9]*) //' /tmp/curl_err.$$))"
  elif [[ "$code" != "$expect" ]]; then
    result="FAIL (expected $expect)"
  elif awk -v t="$secs" -v s="$slow" 'BEGIN { exit !(t > s) }'; then
    result="SLOW"
  else
    result="OK"
  fi
  [[ "$result" == OK || "$result" == SLOW ]] || fails=$((fails + 1))

  printf '%-12s %-34s %5s %7.3fs  %s\n' "$name" "$target" "$code" "$secs" "$result"
  echo "$(date +%FT%T),$name,$code,$secs,${result%% *}" >> "$log"
done < "$list"
rm -f /tmp/curl_err.$$

echo "failures: $fails  (history appended to $log)"
exit $(( fails > 0 ? 1 : 0 ))

Tricky parts. set -e is deliberately off: one dead site must not abort the loop, so the script checks $? itself. Bash cannot compare decimals, so the latency check is delegated to awk, whose exit !(t > s) returns success when the response is slow. curl's error message is captured from stderr into a per-process temp file ($$ = PID) and trimmed with sed. ${result%% *} keeps only the first word (DOWN) for the CSV. Schedule it with */5 * * * * cd /opt/monitor && ./uptime_check.sh || ./alert.sh.

Use case 3 Download with resume and checksum verification

Downloading a release binary on a flaky connection: resume where it stopped instead of starting over, retry transient errors, and verify the SHA-256 against the checksum list the project publishes before trusting the file.

bash · download_verify.sh
#!/usr/bin/env bash
# download_verify.sh - resumable download + SHA-256 verification against a published list
# usage: ./download_verify.sh URL SHA256SUMS_URL
set -euo pipefail

url="${1:?usage: $0 URL SHA256SUMS_URL}"
sums_url="${2:?usage: $0 URL SHA256SUMS_URL}"
file="${url##*/}"                       # last path component = file name

# 1. download, resuming a partial file if one exists (-C -), retrying transient errors
if [[ -s "$file" ]]; then
  echo "partial file found ($(( $(wc -c < "$file") )) bytes) - resuming $file"
else
  echo "downloading $file"
fi
curl -fsSL --retry 5 --retry-delay 2 --connect-timeout 10 \
     -C - -o "$file" "$url" \
  || { echo "download failed (curl exit $?)" >&2; exit 1; }

# 2. fetch the published checksums and pick the line for our file
expected=$(curl -fsSL "$sums_url" | awk -v f="$file" '$2 == f { print $1 }')
[[ -n "$expected" ]] || { echo "no checksum for $file in $sums_url" >&2; exit 2; }

# 3. verify (sha256sum -c reads "HASH  FILENAME" lines from stdin)
if echo "$expected  $file" | sha256sum -c -; then
  echo "verified: $file ($(( $(wc -c < "$file") )) bytes)"
else
  echo "CHECKSUM MISMATCH - deleting $file" >&2
  rm -f -- "$file"
  exit 3
fi
bash · run it (simulating an interrupted download)
U=https://github.com/jqlang/jq/releases/download/jq-1.7.1
curl -sfL -r 0-999999 -o jq-linux-amd64 "$U/jq-linux-amd64"   # fetch only the first 1 MB
./download_verify.sh "$U/jq-linux-amd64" "$U/sha256sum.txt"; echo "exit=$?"
sample output
partial file found (1000000 bytes) - resuming jq-linux-amd64
jq-linux-amd64: OK
verified: jq-linux-amd64 (2319424 bytes)
exit=0

If the file is corrupted (here two bytes were overwritten after downloading), the check catches it:

sample output
partial file found (2319424 bytes) - resuming jq-linux-amd64
jq-linux-amd64: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
CHECKSUM MISMATCH - deleting jq-linux-amd64
exit=3

How it works. -C - tells curl to look at the existing file size and request only the remaining bytes with an HTTP Range header; if the file is already complete, curl recognises it and does nothing. -L is essential because GitHub release URLs redirect to a CDN. ${url##*/} strips everything up to the last slash to get the file name. The checksum list has the format HASH NAME, so awk '$2 == f' picks our line and sha256sum -c - verifies it. A resumed download on top of a corrupt partial file can never verify, which is why the script deletes the file on mismatch so the next run starts clean.

Gotchas

Practice exercises

1. Print only the HTTP status code of https://example.com and of https://httpbin.org/status/403, one per line.
bash
for u in https://example.com https://httpbin.org/status/403; do
  curl -s -o /dev/null -w '%{http_code}\n' "$u"
done
sample output
200
403
2. POST a JSON object built from shell variables (name, email) with jq and print what httpbin received.
bash
name='Asha Rao'; email='asha@example.com'
body=$(jq -n --arg n "$name" --arg e "$email" '{name: $n, email: $e}')
curl -s -H 'Content-Type: application/json' -d "$body" https://httpbin.org/post | jq -c .json
sample output
{"email":"asha@example.com","name":"Asha Rao"}

httpbin re-serialises the JSON, which is why the keys come back in a different order; JSON objects are unordered.

3. Write a one-liner that exits non-zero if https://httpbin.org/delay/3 takes longer than 2 seconds.
bash
curl -fsS --max-time 2 -o /dev/null https://httpbin.org/delay/3 && echo fast || echo "too slow (exit $?)"
sample output
curl: (28) Operation timed out after 2002 milliseconds with 0 bytes received
too slow (exit 28)
4. Print the total time and downloaded size for https://example.com three times and compute the average time.
bash
for i in 1 2 3; do
  curl -s -o /dev/null -w '%{time_total} %{size_download}\n' https://example.com
done | awk '{t+=$1; print} END {printf "avg %.3f s\n", t/NR}'
sample output
0.071233 577
0.052110 577
0.049876 577
avg 0.058 s
5. List the names of the 5 most recently pushed public repositories of the GitHub user "torvalds".
bash
curl -fsS 'https://api.github.com/users/torvalds/repos?sort=pushed&per_page=5' | jq -r '.[].name'
sample output
linux
GuitarPedal
subsurface-for-dirk
uemacs
ScrollWheel

Note the single quotes around the URL because of &.
