Lab 06: Web server access log analysis

Every time someone opens a page, the web server (Apache or Nginx) writes one line into its access log. With awk, sort, uniq and grep you can answer questions like "who visits most?", "which pages are missing?" and "is someone attacking us?". All outputs on this page are real, made from datasets/access.log.

Commands: awk, sort, uniq, grep, wcDifficulty: beginner~45 min

Aim and objectives

Aim: analyse a web server access log with shell commands and simple scripts.

  • Know which column of a log line holds the IP, path, status code and size.
  • Count things with the sort | uniq -c | sort -rn pipeline.
  • Find errors (404, 5xx) and signs of attacks.
  • Write short report scripts.

Prerequisites

All tools are preinstalled on Linux. On a real server the logs are in /var/log/apache2/access.log or /var/log/nginx/access.log (read them with sudo). Here we use the practice file. Basic awk helps.

Start here: simple scripts

Save each script, then run it with chmod +x name.sh and ./name.sh (or bash name.sh) from the wiki folder.

Step 1: print one column

bash · l1_ips.sh
#!/bin/bash
# Step 1: print the first column (the client IP) of the first 5 lines
# awk splits every line on spaces; $1 is the first field
awk '{print $1}' datasets/access.log | head -5
bash · run
chmod +x l1_ips.sh
./l1_ips.sh
output
192.168.1.10
192.168.1.10
192.168.1.10
192.168.1.10
203.0.113.7
  • awk splits each line at the spaces into fields $1, $2, $3 …
  • $1 is the client's IP address.
  • head -5 shows only the first 5 lines of output.

Step 2: count and rank (the most useful pipeline)

bash · l2_top_ips.sh
#!/bin/bash
# Step 2: which IPs sent the most requests?
awk '{print $1}' datasets/access.log |   # 1. take the IP column
    sort |                               # 2. put equal IPs next to each other
    uniq -c |                            # 3. count each group
    sort -rn |                           # 4. biggest count first
    head -5                              # 5. keep the top 5
bash · run
./l2_top_ips.sh
output
     18 192.168.1.10
     14 192.168.1.15
     13 10.0.0.5
     11 203.0.113.7
      8 185.220.101.3
  • uniq -c counts lines that are the same, but only when they are next to each other. That is why we sort first.
  • sort -rn sorts by number (-n), biggest first (-r).
  • Change $1 to another field and the same pipeline counts something else.

Step 3: status codes

bash · l3_status.sh
#!/bin/bash
# Step 3: how many responses of each status code? ($9 = status)
awk '{print $9}' datasets/access.log | sort | uniq -c | sort -rn
bash · run
./l3_status.sh
output
     55 200
      9 403
      8 404
      6 500
      1 302
      1 301
  • $9 is the HTTP status code: 200 = OK, 301/302 = redirect, 403 = forbidden, 404 = not found, 500 = server error.
  • 55 of 80 requests were OK; the 6 server errors (500) need a closer look.

Step 4: which pages were not found?

bash · l4_404.sh
#!/bin/bash
# Step 4: which pages were not found?
# The pattern $9 == 404 keeps only lines whose status is 404; then print the path ($7)
awk '$9 == 404 {print $7}' datasets/access.log | sort | uniq -c | sort -rn
bash · run
./l4_404.sh
output
      5 /.env
      3 /missing.html
  • In awk, condition {action} runs the action only on lines where the condition is true.
  • /missing.html is probably a broken link. /.env is a secret config file that attackers look for.

Concepts

The fields of a log line

Most servers use the combined log format. Take this line from the dataset:

one log line
185.220.101.3 - - [16/Nov/2026:12:01:51 +0530] "POST /wp-login.php HTTP/1.1" 200 32921 "-" "sqlmap/1.7.11#stable"
awk fieldValueMeaning
$1185.220.101.3client IP address
$4[16/Nov/2026:12:01:51date and time
$6"POSTmethod (with a leading quote)
$7/wp-login.phprequested page (path)
$9200status code
$1032921bytes sent
-F'"' then $6sqlmap/1.7.11#stableuser agent (browser or tool name)

The user agent contains spaces, so normal fields cut it into pieces. Splitting the line at the double quote (-F'"') puts the whole user agent into field 6:

bash · check the fields of the first line
head -1 datasets/access.log | awk '{print "ip=" $1, "page=" $7, "status=" $9, "bytes=" $10}'
head -1 datasets/access.log | awk -F'"' '{print "agent=" $6}'
output
ip=192.168.1.10 page=/api/v1/users status=200 bytes=16949
agent=Mozilla/5.0 (Macintosh; Intel Mac OS X 14_1) Safari/605.1

Use cases

Use case 1 Daily traffic report

Scenario: the website owner wants a short summary of the day: number of requests, visitors, data sent, top visitors, status codes and most popular pages.

bash · daily_report.sh
#!/bin/bash
# daily_report.sh - short traffic report for an access log
# usage: ./daily_report.sh [logfile]
log="${1:-datasets/access.log}"

if [ ! -f "$log" ]; then
    echo "Error: $log not found"
    exit 1
fi

echo "===== Traffic report: $log ====="
echo "Total requests : $(wc -l < "$log")"
echo "Unique IPs     : $(awk '{print $1}' "$log" | sort -u | wc -l)"
echo "Data sent (KB) : $(awk '{sum += $10} END {print int(sum / 1024)}' "$log")"

echo "--- Top 3 IPs ---"
awk '{print $1}' "$log" | sort | uniq -c | sort -rn | head -3

echo "--- Status codes ---"
awk '{print $9}' "$log" | sort | uniq -c | sort -rn

echo "--- Top 3 pages ---"
awk '{print $7}' "$log" | sort | uniq -c | sort -rn | head -3
bash · run
chmod +x daily_report.sh
./daily_report.sh
output
===== Traffic report: datasets/access.log =====
Total requests : 80
Unique IPs     : 10
Data sent (KB) : 1300
--- Top 3 IPs ---
     18 192.168.1.10
     14 192.168.1.15
     13 10.0.0.5
--- Status codes ---
     55 200
      9 403
      8 404
      6 500
      1 302
      1 301
--- Top 3 pages ---
     10 /api/v1/users
      8 /index.php
      7 /images/logo.png

How it works:

  • $(…) runs a command and puts its output into the echo line.
  • sort -u | wc -l counts how many different IPs there are.
  • {sum += $10} END {print …} adds the bytes of every line, then prints once at the end. int(sum / 1024) converts to whole kilobytes.
  • The rest is the count-and-rank pipeline from Step 2 on different columns.

Use case 2 Attack detection

Scenario: you suspect someone is scanning the website. Look for a known attack tool (sqlmap), requests for secret files, WordPress login attempts, and IPs that collect many "forbidden" or "not found" errors.

bash · attack_check.sh
#!/bin/bash
# attack_check.sh - look for common attack patterns in an access log
# usage: ./attack_check.sh [logfile]
log="${1:-datasets/access.log}"

echo "Requests from the sqlmap attack tool:"
grep -c "sqlmap" "$log"

echo "Requests for secret files (/.env):"
grep -c "/.env" "$log"

echo "Login attempts (POST /wp-login.php) per IP:"
grep "POST /wp-login.php" "$log" | awk '{print $1}' | sort | uniq -c

echo "IPs that got 3 or more 403/404 errors:"
awk '$9 == 403 || $9 == 404 {print $1}' "$log" | sort | uniq -c | sort -rn |
    while read -r count ip; do
        if [ "$count" -ge 3 ]; then
            echo "  SUSPICIOUS: $ip ($count errors)"
        fi
    done
bash · run
chmod +x attack_check.sh
./attack_check.sh
output
Requests from the sqlmap attack tool:
8
Requests for secret files (/.env):
5
Login attempts (POST /wp-login.php) per IP:
      1 185.220.101.3
      1 192.168.1.10
IPs that got 3 or more 403/404 errors:
  SUSPICIOUS: 185.220.101.3 (7 errors)
  SUSPICIOUS: 192.168.1.10 (5 errors)

How it works:

  • grep -c counts matching lines instead of printing them.
  • $9 == 403 || $9 == 404 means "status is 403 OR 404".
  • while read -r count ip reads the two columns of uniq -c into two variables, and if [ "$count" -ge 3 ] keeps only IPs with 3 or more errors.
  • 185.220.101.3 uses sqlmap and asks for /.env and /xmlrpc.php: clearly a scanner. 192.168.1.10 is an internal address, maybe an admin, so check before blocking.

Use case 3 Error-rate monitor

Scenario: users say the site "sometimes fails". Compute what percent of requests got a server error (5xx) and print an alert above a limit.

bash · error_monitor.sh
#!/bin/bash
# error_monitor.sh - alert if too many requests failed with a 5xx server error
# usage: ./error_monitor.sh [logfile] [max_percent]
log="${1:-datasets/access.log}"
max="${2:-5}"

total=$(wc -l < "$log")
errors=$(awk '$9 >= 500' "$log" | wc -l)
percent=$((errors * 100 / total))          # whole numbers only in Bash

echo "Requests: $total, server errors: $errors ($percent%)"

if [ "$percent" -gt "$max" ]; then
    echo "ALERT: error rate is above $max%"
    echo "Failing pages:"
    awk '$9 >= 500 {print $7}' "$log" | sort | uniq -c
    exit 1
else
    echo "OK: error rate is fine"
fi
bash · run with the default limit (5%), then with 10%
./error_monitor.sh; echo "exit code: $?"
./error_monitor.sh datasets/access.log 10; echo "exit code: $?"
output
Requests: 80, server errors: 6 (7%)
ALERT: error rate is above 5%
Failing pages:
      6 /api/v1/report
exit code: 1
Requests: 80, server errors: 6 (7%)
OK: error rate is fine
exit code: 0

How it works:

  • awk '$9 >= 500' "$log" | wc -l counts the lines with status 500 or more.
  • $((errors * 100 / total)) is Bash arithmetic. It only does whole numbers, so 6 × 100 / 80 = 7 (not 7.5). Multiply before dividing, or you get 0.
  • exit 1 on alert lets another script or cron job notice the problem; echo $? shows the exit code.
Optional: going further (live monitoring with tail -f)

tail -f keeps a file open and prints new lines as the server writes them. Piped into awk, it shows every error the moment it happens. Press Ctrl+C to stop.

bash · watch_errors.sh
#!/bin/bash
# show every 4xx/5xx response as it is written to the log
tail -f /var/log/nginx/access.log | awk '$9 >= 400 {print $4, $1, $9, $7; fflush()}'
sample output
[16/Nov/2026:14:02:17 185.220.101.3 404 /.env
[16/Nov/2026:14:11:11 185.220.101.3 403 /xmlrpc.php
[16/Nov/2026:14:28:32 185.220.101.3 404 /.env

fflush() makes awk print each line immediately instead of collecting output in a buffer.

MistakeWhat happensFix
uniq -c without sortThe same IP appears many times with small countsAlways sort | uniq -c.
sort -r instead of sort -rn9 is placed above 18 (text order)Add -n for numbers.
Double quotes around the awk programBash replaces $1 before awk sees itUse single quotes: awk '{print $1}'
Wrong field numberEmpty or strange outputPrint the fields of one line first (see Concepts).
[ $count -ge 3]missing ] errorSpaces are required: [ "$count" -ge 3 ]
[ "$a" = 5 ] vs -eq= compares text, -eq compares numbersUse -eq -gt -lt for numbers.

Viva / exam questions

What is an access log?

A file where the web server writes one line for every request: who asked (IP), when, which page, the status code, the size and the browser.

Which awk fields hold the IP, page and status code?

$1 is the IP, $7 the page (path), $9 the status code. $10 is the size in bytes.

Why must you sort before uniq -c?

uniq only joins identical lines that are next to each other. Sorting puts identical lines together.

Write a command to show the top 5 IPs.

awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5

What do status codes 200, 404 and 500 mean?

200: OK. 404: page not found. 500: internal server error (a problem on the server).

How do you get the user agent from a log line?

Split on double quotes: awk -F'"' '{print $6}', because the user agent contains spaces.

Name two signs of an attack in an access log.

Attack tool names in the user agent (sqlmap, nikto) and requests for files that should never be public, like /.env or /wp-login.php hit many times by one IP.

What does tail -f do?

It keeps printing new lines as they are added to a file, so you can watch a log live.
