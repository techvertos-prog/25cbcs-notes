Lab 03: Remote script execution

Run commands on other Linux machines from your own terminal with ssh. Start with one command, then send several lines at once, then loop over a list of servers, and copy files with scp.

Commands: ssh, ssh-keygen, ssh-copy-id, scp Difficulty: beginner ~45 min
About the outputs on this pageRemote commands need real servers, so most outputs are labelled sample output. Your names and numbers will differ. Outputs that only read datasets/ are real. To practise, two Linux virtual machines on the same network are enough; replace the IP addresses with yours.

Aim and objectives

Aim: run commands and scripts on remote Linux machines from a shell script.

  • Log in with an SSH key instead of a password.
  • Run one command on a server, and several commands with a heredoc.
  • Run the same command on several servers with a for loop.
  • Run a local script on a server, and copy files with scp.

Prerequisites

bash · install
sudo apt install openssh-client      # on your machine (usually already there)
sudo apt install openssh-server      # on each server you want to reach
sudo systemctl enable --now ssh      # start the SSH service on the server

You need a user account on each server. Our server list uses the users deploy, dbadmin and ops.

One-time setup: SSH keys

Scripts cannot type passwords, so we use a key pair. The private key stays on your machine. The public key is copied to the server.

  1. Create a key pair (press Enter to accept the defaults):
    bash
    ssh-keygen -t ed25519
  2. Copy the public key to the server (you type the password one last time):
    bash
    ssh-copy-id deploy@10.0.1.11
  3. Test it. You should get in without a password:
    bash
    ssh deploy@10.0.1.11

Start here: simple scripts

Step 1: one command on a server

bash · one.sh
#!/bin/bash
# one.sh: run ONE command on a remote server

server="deploy@10.0.1.11"          # user@address of the remote machine

ssh "$server" uptime               # runs "uptime" on the server, prints here
echo "ssh finished with exit code $?"
bash · run it
chmod +x one.sh
./one.sh
sample output
 10:42:17 up 3 days,  2:11,  1 user,  load average: 0.08, 0.05, 0.01
ssh finished with exit code 0
  • ssh user@address command logs in, runs the command, prints its output on your screen and logs out.
  • $? after ssh is the exit code of the remote command. If ssh could not connect at all, it is 255.

Step 2: several commands with a heredoc

bash · heredoc.sh
#!/bin/bash
# heredoc.sh: send several commands to the server in one go

ssh deploy@10.0.1.11 bash <<'EOF'      # bash on the server reads the lines below
echo "Logged in to: $(hostname)"
echo "Today is: $(date +%d-%m-%Y)"
df -h / | tail -n 1
EOF
sample output
Logged in to: web01
Today is: 17-11-2026
/dev/sda2        49G   20G   27G  43% /
  • Everything between <<'EOF' and the line EOF is sent to the server as input. bash on the server reads it and runs it line by line.
  • The quotes in 'EOF' mean "do not change anything here". So $(hostname) runs on the server and prints web01.
  • The closing EOF must be alone on its line, with no spaces before it.

Step 3: a for loop over several servers

bash · loop.sh
#!/bin/bash
# loop.sh: run the same command on several servers

for host in 10.0.1.11 10.0.1.12 10.0.1.16; do
  echo "=== $host ==="
  ssh deploy@"$host" hostname        # ask each server for its name
done
sample output
=== 10.0.1.11 ===
web01
=== 10.0.1.12 ===
web02
=== 10.0.1.16 ===
cache01
  • The loop variable host takes each address in turn.
  • deploy@"$host" builds the login, e.g. deploy@10.0.1.11.
  • The servers are done one after another. A slow server makes the whole loop wait.

Step 4: build the server list from a file

Typing addresses into the script is fine for 3 servers. For more, keep them in a file. Here is our inventory:

datasets/servers.txt
# hostname        ip            user     role
web01             10.0.1.11     deploy   web
web02             10.0.1.12     deploy   web
db01              10.0.1.14     dbadmin  database
cache01           10.0.1.16     deploy   cache
mon01             10.0.1.18     ops      monitoring
bash · dryrun.sh
#!/bin/bash
# dryrun.sh: read servers.txt and PRINT the ssh command for each host
# (safe to run anywhere: nothing connects)

grep -v '^#' datasets/servers.txt | while read -r name ip user role; do
  echo "ssh $user@$ip   # $name ($role)"
done
output · bash dryrun.sh
ssh deploy@10.0.1.11   # web01 (web)
ssh deploy@10.0.1.12   # web02 (web)
ssh dbadmin@10.0.1.14   # db01 (database)
ssh deploy@10.0.1.16   # cache01 (cache)
ssh ops@10.0.1.18   # mon01 (monitoring)
  • grep -v '^#' removes the comment line (the header).
  • read -r name ip user role splits each line into four variables at the spaces.
  • This script only prints the commands, so you can check them safely. Use case 1 runs them for real.

Step 5: copy files with scp

bash · copy.sh
#!/bin/bash
# copy.sh: copy files to and from a server with scp

scp datasets/app.conf deploy@10.0.1.11:/tmp/       # local -> server
scp deploy@10.0.1.11:/etc/hostname ./web01-hostname.txt   # server -> local
cat web01-hostname.txt
sample output
app.conf                                      100%  498    61.2KB/s   00:00
hostname                                      100%    6     0.9KB/s   00:00
web01
  • scp SOURCE DESTINATION works like cp. A remote path is written user@address:/path.
  • Use scp -r to copy a whole folder.

Concepts

Ways to run things remotely

CommandWhat it does
ssh user@hostInteractive login (type exit to leave)
ssh user@host 'cmd'Run one command and come back
ssh user@host 'cmd1; cmd2'Several commands in one string
ssh user@host bash <<'EOF' ... EOFSend several lines written inside your script
ssh user@host 'bash -s' < script.shRun a script file from your machine on the server
scp file user@host:/path/Copy a file to the server
scp user@host:/path/file .Copy a file from the server to here

Single or double quotes?

Your own shell reads the command first, then the server reads it again.

bash
ssh deploy@10.0.1.11 "echo $HOSTNAME"   # double quotes: YOUR machine fills in $HOSTNAME
ssh deploy@10.0.1.11 'echo $HOSTNAME'   # single quotes: the SERVER fills it in
sample output
student-laptop
web01

The same rule applies to heredocs: <<'EOF' (quoted) leaves $ for the server, while <<EOF (unquoted) fills in variables on your machine first.

Useful ssh options for scripts

OptionWhy
-o BatchMode=yesNever ask for a password. If the key does not work, fail at once instead of waiting
-o ConnectTimeout=5Give up after 5 seconds if the server is down
-nDo not read keyboard input. Needed inside while read loops (see use case 1)
-p 2222Connect to a different port (scp uses capital -P)

Short names with ~/.ssh/config

Instead of deploy@10.0.1.11 you can write ssh web01 after adding entries to ~/.ssh/config. This command makes the entries from our server list:

bash
awk '!/^#/ && NF { print "Host " $1; print "    HostName " $2; print "    User " $3; print "" }' datasets/servers.txt
output
Host web01
    HostName 10.0.1.11
    User deploy

Host web02
    HostName 10.0.1.12
    User deploy

Host db01
    HostName 10.0.1.14
    User dbadmin

Host cache01
    HostName 10.0.1.16
    User deploy

Host mon01
    HostName 10.0.1.18
    User ops

Add them with >> ~/.ssh/config. scp understands the short names too, as use case 3 shows.

Use cases

All three use cases use the servers from datasets/servers.txt shown in Step 4.

Use case 1 Health check of every server

What and why: each morning, check that every server answers and see its uptime and disk usage. Servers that are down are reported instead of stopping the script.

bash · check-all.sh
#!/bin/bash
# check-all.sh: check every server in datasets/servers.txt
# prints uptime and root disk usage, or UNREACHABLE

file="datasets/servers.txt"

grep -v '^#' "$file" | while read -r name ip user role; do
  echo "=== $name ($ip) ==="
  # -n: do not read our host list; BatchMode: never ask for a password
  if ssh -n -o BatchMode=yes -o ConnectTimeout=5 "$user@$ip" "uptime -p; df -h / | tail -n 1"; then
    echo "status: OK"
  else
    echo "status: UNREACHABLE"
  fi
done
sample output
=== web01 (10.0.1.11) ===
up 3 days, 2 hours, 11 minutes
/dev/sda2        49G   20G   27G  43% /
status: OK
=== web02 (10.0.1.12) ===
up 3 days, 2 hours, 9 minutes
/dev/sda2        49G   19G   28G  41% /
status: OK
=== db01 (10.0.1.14) ===
up 12 days, 5 hours, 40 minutes
/dev/sdb1       196G  168G   19G  90% /
status: OK
=== cache01 (10.0.1.16) ===
ssh: connect to host 10.0.1.16 port 22: Connection timed out
status: UNREACHABLE
=== mon01 (10.0.1.18) ===
up 21 hours, 4 minutes
/dev/sda2        29G   16G   12G  57% /
status: OK

How it works:

  • Each line of the file gives name ip user role, so each server is reached with its own user.
  • if ssh ...; then checks ssh's exit code: 0 means the commands ran, anything else means a problem.
  • -n is important. Without it, the first ssh reads the rest of the server list as its own input, and the loop stops after the first server.
  • BatchMode and ConnectTimeout stop the script from hanging on a password prompt or a dead server.

Use case 2 Run a local script on the web servers

What and why: you have a script on your machine and want its result from each server, without copying the file to every server first.

bash · info.sh (runs on the server)
#!/bin/bash
# info.sh: this script will run ON the remote server
echo "Host     : $(hostname)"
echo "Kernel   : $(uname -r)"
echo "Users on : $(who | wc -l)"
echo "Memory   : $(free -m | awk 'NR==2 {print $3 " MB used of " $2 " MB"}')"
bash · run-script.sh (runs on your machine)
#!/bin/bash
# run-script.sh: run the local file info.sh on each web server
# (the script is sent over ssh, it is NOT copied to the server)

for ip in 10.0.1.11 10.0.1.12; do
  echo "----- deploy@$ip -----"
  ssh deploy@"$ip" 'bash -s' < info.sh
done
sample output · ./run-script.sh
----- deploy@10.0.1.11 -----
Host     : web01
Kernel   : 6.8.0-45-generic
Users on : 1
Memory   : 1873 MB used of 7951 MB
----- deploy@10.0.1.12 -----
Host     : web02
Kernel   : 6.8.0-45-generic
Users on : 0
Memory   : 2210 MB used of 7951 MB

How it works:

  • < info.sh feeds the file into ssh. On the server, bash -s reads commands from that input and runs them.
  • The file is never saved on the server, so there is nothing to clean up and only one copy to maintain.
  • Change info.sh and the next run uses the new version on every server.

Use case 3 Collect log files from the web servers

What and why: copy each web server's access log into a local logs/ folder, named with the server and the date, so you can analyse them later (see Lab 06).

bash · collect-logs.sh
#!/bin/bash
# collect-logs.sh: copy the nginx access log from each web server
# into a local folder called logs/, one file per server

mkdir -p logs                                  # make the folder if needed
today=$(date +%Y-%m-%d)

for host in web01 web02; do                    # names from ~/.ssh/config
  echo "Copying from $host ..."
  if scp "$host":/var/log/nginx/access.log "logs/$host-$today.log"; then
    echo "  saved logs/$host-$today.log"
  else
    echo "  FAILED to copy from $host"
  fi
done

ls -l logs/
sample output
Copying from web01 ...
access.log                                    100%  842KB  12.1MB/s   00:00
  saved logs/web01-2026-11-17.log
Copying from web02 ...
scp: /var/log/nginx/access.log: Permission denied
  FAILED to copy from web02
total 848
-rw-r--r-- 1 student student 862144 Nov 17 10:51 web01-2026-11-17.log

How it works:

  • web01 and web02 are short names from ~/.ssh/config (see Concepts).
  • mkdir -p creates the folder, and does nothing if it already exists.
  • if scp ...; then reports each copy separately, so one failure does not hide the others.
  • "Permission denied" usually means the user cannot read the log. Add the user to the adm group on that server.
Optional: going further (rsync instead of scp)

rsync copies only the files that changed, which is much faster for folders you copy again and again. It must be installed on both machines.

bash
rsync -av website/ deploy@10.0.1.11:/var/www/html/      # copy changed files only
rsync -avn website/ deploy@10.0.1.11:/var/www/html/     # -n: dry run, just show what would change
sample output
sending incremental file list
index.html
css/style.css

sent 2,413 bytes  received 57 bytes  4,940.00 bytes/sec
total size is 18,204  speedup is 7.37

The slash after website/ means "the contents of the folder". Without it, rsync creates /var/www/html/website.

Viva / exam questions

What is SSH?

Secure Shell: a protocol and program for logging in to and running commands on a remote machine over an encrypted connection. It uses port 22 by default.

Why use SSH keys instead of passwords in scripts?

Scripts cannot type passwords. With a key pair, the server checks your private key against the public key you copied with ssh-copy-id, so no password is needed. Keys are also much harder to guess than passwords.

Which key do you copy to the server, and which do you keep secret?

Copy the public key (.pub). Keep the private key secret on your own machine.

How do you run a single command on a remote machine?

ssh user@host command, for example ssh deploy@10.0.1.11 uptime.

How do you run a local script on a remote machine?

ssh user@host 'bash -s' < script.sh. The script is sent over the connection and run there without being copied.

What is the difference between <<EOF and <<'EOF'?

With <<EOF, your own shell fills in variables first. With <<'EOF', the text is sent exactly as written and the server fills in variables.

Why does a while read loop with ssh stop after the first server?

ssh reads input, so it swallows the remaining lines of the server list. ssh -n stops it from reading input.

What does exit code 255 from ssh mean?

ssh itself failed, for example the server is down, the connection timed out or login was refused. Other codes come from the remote command.

What does scp do?

It copies files between machines over SSH, like cp. A remote path is written as user@host:/path.
