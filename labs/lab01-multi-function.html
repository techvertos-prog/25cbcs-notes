Lab 01: Multi-function scripting

Split a script into small named functions. You will write a function, give it arguments, get a value back, check its exit code, and share functions between scripts with source.

Concepts: functions, $1 $2 $#, echo vs return, $?, local, source Difficulty: beginner ~45 min

Aim and objectives

Aim: write a shell script made of several functions, each doing one small job.

  • Define a function and call it.
  • Pass arguments to a function ($1, $2, $#).
  • Get a value out of a function with echo, and a yes/no answer with return.
  • Check exit codes with $? and if.
  • Keep variables inside a function with local, and reuse functions with source.

Start here: simple scripts

Type each script into a file, then run it. Each one adds one new idea.

Step 1: a function that prints hello

bash · hello.sh
#!/bin/bash
# hello.sh: the smallest possible function

say_hello() {            # define a function called say_hello
  echo "Hello from a function!"
}

say_hello                # call it (just write its name)
say_hello                # call it again: functions are reusable
bash · run it
chmod +x hello.sh     # make it executable (only needed once)
./hello.sh
output
Hello from a function!
Hello from a function!
  • say_hello() { ... } defines the function. Nothing runs yet.
  • Writing say_hello on its own line calls it, like any command.
  • The function must be defined above the line that calls it.

Step 2: give the function an argument

bash · greet.sh
#!/bin/bash
# greet.sh: a function that takes an argument

greet() {
  echo "Hello, $1!"      # $1 = first argument given to the function
}

greet "Aarav"            # $1 is Aarav
greet "Priya Sharma"     # quotes keep the two words together as $1
output · bash greet.sh
Hello, Aarav!
Hello, Priya Sharma!
  • Words written after the function name are its arguments.
  • Inside the function, $1 is the first argument, $2 the second, and so on.
  • Quotes turn "Priya Sharma" into one argument instead of two.

Step 3: return a value with echo

bash · add.sh
#!/bin/bash
# add.sh: get a value OUT of a function with echo

add() {
  total=$(( $1 + $2 ))   # do the arithmetic
  echo "$total"          # "return" the answer by printing it
}

result=$(add 7 35)       # $( ) captures what the function printed
echo "7 + 35 = $result"
output · bash add.sh
7 + 35 = 42
  • A Bash function cannot "return" a number or text the way Python does.
  • Instead it prints the answer with echo.
  • result=$(add 7 35) runs the function and stores what it printed in result.

Step 4: check the exit code

bash · check.sh
#!/bin/bash
# check.sh: a function that answers yes/no with an exit code

is_even() {
  if [ $(( $1 % 2 )) -eq 0 ]; then
    return 0             # 0 means success / true
  else
    return 1             # non-zero means failure / false
  fi
}

is_even 4
echo "is_even 4 -> exit code $?"     # $? = exit code of the last command

if is_even 7; then echo "7 is even"; else echo "7 is odd"; fi
output · bash check.sh
is_even 4 -> exit code 0
7 is odd
  • return 0 means "yes / success", return 1 means "no / failure".
  • $? holds the exit code of the command that just finished.
  • if is_even 7; then runs the function and checks its exit code directly.

Step 5: local variables

bash · scope.sh
#!/bin/bash
# scope.sh: local keeps a variable inside the function

name="outside"

change_global() { name="changed"; }        # no local: overwrites the script's variable
use_local()     { local name="inside"; echo "in function: $name"; }

use_local
echo "after use_local:     $name"
change_global
echo "after change_global: $name"
output · bash scope.sh
in function: inside
after use_local:     outside
after change_global: changed
  • In Bash, every variable is global by default, even when set inside a function.
  • local name=... creates a separate variable that exists only inside that function.
  • Use local for every variable inside a function. That way two functions cannot overwrite each other's variables.

Concepts

Function syntax

bash · two ways to write a function
greet() {            # common style
  echo "Hi $1"
}

function greet {     # Bash keyword style, works the same
  echo "Hi $1"
}

Special variables inside a function

VariableMeaning
$1, $2, ...First, second, ... argument
$#How many arguments were given
"$@"All arguments, each kept separate (use this to pass them on)
$?Exit code of the last command (0 = success)
$0Name of the script (not the function)

echo vs return

echoreturn N
Sends backAny text or numberOnly a number from 0 to 255
Caller reads it withx=$(func)$? or if func; then
Use it forResults (sums, names, lists)Yes/no answers (success or failure)
Exam hintreturn does not send data back. It only sets the exit code. To get a value from a function, echo it and capture it with $( ).

return vs exit

  • return leaves the function. The script carries on.
  • exit stops the whole script, even if it is called inside a function.

Sharing functions with source

Put functions you use often in one file, for example lib.sh. Any script can load them with source ./lib.sh (or the short form . ./lib.sh). source runs the file inside the current script, so its functions become available. Use case 3 shows this.

Use cases

Use case 1 System information toolkit

What and why: a script that prints basic information about the computer. Each piece of information has its own function, so you can reorder, remove or reuse them easily.

bash · sysinfo.sh
#!/bin/bash
# sysinfo.sh: a small system-information toolkit, one function per job

line() {
  echo "------------------------------"
}

show_user() {
  echo "User     : $(whoami)"
  echo "Hostname : $(hostname)"
}

show_time() {
  echo "Date     : $(date '+%d-%m-%Y %H:%M')"
  echo "Uptime   : $(uptime -p)"
}

show_disk() {
  echo "Root disk usage:"
  df -h / | tail -n 1      # tail skips the header line
}

# main part: call the functions in the order we want
line; show_user; line; show_time; line; show_disk; line
bash · run it
chmod +x sysinfo.sh
./sysinfo.sh
sample output (your values will differ)
------------------------------
User     : student
Hostname : lab-pc
------------------------------
Date     : 17-11-2026 10:42
Uptime   : up 2 hours, 14 minutes
------------------------------
Root disk usage:
/dev/sda2        49G   30G   17G  64% /
------------------------------

How it works:

  • line is a tiny helper used four times. Change the dashes once and every separator changes.
  • $(whoami) inside echo runs a command and puts its output into the text.
  • The last line is the "main" part: it calls the functions in order. Several commands on one line are separated by ;.

Use case 2 Employee report with simple commands

What and why: one script that answers three questions about employees.csv. The first argument ($1) chooses which function runs, using case.

bash · emp-report.sh
#!/bin/bash
# emp-report.sh: report tool for datasets/employees.csv
# usage: ./emp-report.sh count | dept NAME | top

file="datasets/employees.csv"

count_staff() {
  echo "Total employees: $(tail -n +2 "$file" | wc -l)"
}

list_dept() {
  echo "Employees in $1:"
  grep ",$1," "$file" | cut -d, -f2,5
}

top_earners() {
  echo "Top 3 salaries:"
  tail -n +2 "$file" | sort -t, -k5 -nr | head -n 3 | cut -d, -f2,5
}

case "$1" in
  count) count_staff ;;
  dept)  list_dept "$2" ;;
  top)   top_earners ;;
  *)     echo "usage: $0 count | dept NAME | top"; exit 1 ;;
esac

Run it from the wiki folder:

output
$ ./emp-report.sh count
Total employees: 25
$ ./emp-report.sh dept Finance
Employees in Finance:
Arjun Nair,94000
Isha Das,93000
Tanvi Joshi,84000
$ ./emp-report.sh top
Top 3 salaries:
Priya Sharma,135000
Ananya Iyer,131000
Pooja Nair,127000
$ ./emp-report.sh
usage: ./emp-report.sh count | dept NAME | top

How it works:

  • tail -n +2 skips the header line, so only employees are counted.
  • list_dept "$2" passes the script's second argument (Finance) to the function, where it becomes $1.
  • grep ",$1," matches the department between two commas, and cut -d, -f2,5 keeps the name and salary columns.
  • sort -t, -k5 -nr sorts by column 5 (salary), numerically (n), biggest first (r).
  • The *) branch catches anything else, prints usage and exits with code 1.

Use case 3 A shared lib.sh loaded with source

What and why: many scripts need the same helpers: print a message, stop with an error, check that input is a number. We write them once in lib.sh and load them into another script with source.

bash · lib.sh
# lib.sh: shared helper functions (no need to run it, we "source" it)

log() {
  echo "[INFO] $1"
}

die() {
  echo "[ERROR] $1"
  exit 1                       # stop the whole script
}

is_number() {
  case "$1" in
    ''|*[!0-9]*) return 1 ;;   # empty, or has a non-digit: not a number
    *) return 0 ;;
  esac
}
bash · salary-check.sh
#!/bin/bash
# salary-check.sh: list employees earning more than a given amount
# usage: ./salary-check.sh AMOUNT

source ./lib.sh                 # load log, die and is_number from lib.sh

file="datasets/employees.csv"
amount="$1"

[ -f "$file" ] || die "file $file not found"
is_number "$amount" || die "please give a number, e.g. ./salary-check.sh 100000"

log "Employees earning more than $amount:"
awk -F, -v min="$amount" 'NR > 1 && $5 > min { print $2, $5 }' "$file"
log "done"

Run it with lib.sh and salary-check.sh both saved in the wiki folder:

output
$ ./salary-check.sh 120000; echo "exit code: $?"
[INFO] Employees earning more than 120000:
Priya Sharma 135000
Ananya Iyer 131000
Pooja Nair 127000
[INFO] done
exit code: 0
$ ./salary-check.sh abc; echo "exit code: $?"
[ERROR] please give a number, e.g. ./salary-check.sh 100000
exit code: 1
$ ./salary-check.sh; echo "exit code: $?"
[ERROR] please give a number, e.g. ./salary-check.sh 100000
exit code: 1

How it works:

  • source ./lib.sh reads lib.sh into this script, so log, die and is_number can be used here.
  • [ -f "$file" ] || die "..." means "if the file does not exist, call die". || runs the right side only when the left side fails.
  • is_number uses case: an empty value, or one containing any non-digit, returns 1 (not a number).
  • die calls exit 1, which stops the whole script. That is why "done" is not printed for bad input.
  • awk -v min="$amount" passes the shell variable into awk. NR > 1 skips the header.
Optional: going further (reading options with getopts)

Real commands accept options like -n NAME. The getopts builtin reads them one at a time in a while loop.

bash · opts.sh
#!/bin/bash
# opts.sh: read options like -n NAME and -h with getopts
name="world"
while getopts "n:h" opt; do          # n: means -n needs a value
  case "$opt" in
    n) name="$OPTARG" ;;             # the value after -n
    h) echo "usage: $0 [-n NAME]"; exit 0 ;;
    *) echo "unknown option"; exit 1 ;;
  esac
done
echo "Hello, $name"
output
$ ./opts.sh
Hello, world
$ ./opts.sh -n Priya
Hello, Priya
$ ./opts.sh -h
usage: ./opts.sh [-n NAME]
$ ./opts.sh -x
./opts.sh: illegal option -- x
unknown option

In "n:h", the colon after n means -n needs a value, which arrives in $OPTARG. An unknown option such as -x makes Bash print its own error, and opt becomes ?, so the *) branch runs.

Viva / exam questions

What is a function in a shell script?

A named group of commands. You define it once and call it by name as often as you need, like a small command of your own.

How do you pass arguments to a function?

Write them after the function name: greet Aarav. Inside the function they are $1, $2, and so on. $# gives how many there are.

How do you get a value back from a function?

The function prints it with echo, and the caller captures it: result=$(add 3 4).

What does return do in a function?

It ends the function and sets its exit code (0 to 255). 0 means success. It does not send back text.

What is $??

The exit code of the last command or function that ran. 0 means success, anything else means failure.

Difference between return and exit?

return leaves only the function. exit stops the whole script.

Why use local?

Variables are global by default. local keeps a variable inside its function so it cannot overwrite a variable with the same name elsewhere.

What does source lib.sh do?

It runs lib.sh inside the current shell, so the functions and variables defined in it become available to the current script.
