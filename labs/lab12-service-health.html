Lab 12: Service health monitoring

Write scripts that check whether services such as nginx and MySQL are running, restart them when they stop, check that a website answers, and print a coloured status list. These are the basic building blocks of every monitoring tool.

Commands: systemctl, curl, journalctl, jq, cronDifficulty: beginner~45 min

Aim and objectives

  • Check if a service is running with systemctl is-active.
  • Restart a stopped service from a script.
  • Check a website's HTTP status code with curl.
  • Check many services with a for loop or from a list file.
  • Run the checks automatically every few minutes with cron.

Prerequisites

  • A Linux VM with systemd (Ubuntu) and a service to watch: sudo apt install -y nginx curl jq.
  • Basic Bash: variables, if, for, while read.
  • The parts that read datasets/ (the service list and the server inventory) run on any computer.

Start here: simple scripts

1. Is the service running?

bash · is_active.sh
#!/bin/bash
# is_active.sh: ask systemd whether nginx is running

systemctl is-active nginx             # prints active, inactive or failed
echo "exit code: $?"                  # 0 = active, anything else = not active
bash · run it
chmod +x is_active.sh
./is_active.sh
sudo systemctl stop nginx
./is_active.sh
sample output
active
exit code: 0
inactive
exit code: 3
  • systemctl is-active NAME prints the state of a service.
  • It also sets the exit code: 0 when active, non-zero when not. Scripts use this exit code in if.
  • $? holds the exit code of the last command.

2. Restart it if it is down

bash · restart_if_down.sh
#!/bin/bash
# restart_if_down.sh: start nginx again if it has stopped

if systemctl is-active --quiet nginx; then     # --quiet: no text, only the exit code
    echo "nginx is running"
else
    echo "nginx is DOWN, restarting..."
    systemctl restart nginx
    systemctl is-active nginx                  # show the new state
fi
bash · run it
sudo systemctl stop nginx
sudo ./restart_if_down.sh
sudo ./restart_if_down.sh
sample output
nginx is DOWN, restarting...
active
nginx is running
  • if command; then runs the command and checks its exit code: 0 means "true".
  • --quiet stops systemctl printing, so only our own messages appear.
  • Restarting needs root, so run the script with sudo.

3. Is the website answering?

bash · check_url.sh
#!/bin/bash
# check_url.sh: is the website answering with HTTP 200?

url="https://example.com"
code=$(curl -s -o /dev/null -w "%{http_code}" --max-time 10 "$url")

if [ "$code" = "200" ]; then
    echo "$url is UP ($code)"
else
    echo "$url is DOWN ($code)"
fi
bash · run it
bash check_url.sh
sample output
https://example.com is UP (200)
  • -s = silent, -o /dev/null = throw the page away, -w "%{http_code}" = print only the status code.
  • --max-time 10 gives up after 10 seconds, so the script never hangs.
  • If the server cannot be reached at all, curl prints 000.

4. Check several services with a loop

bash · loop_services.sh
#!/bin/bash
# loop_services.sh: check several services with a for loop

for service in nginx mysql cron; do
    status=$(systemctl is-active $service)
    echo "$service: $status"
done
bash · run it
bash loop_services.sh
sample output
nginx: active
mysql: inactive
cron: active
  • The for loop runs the same two lines once for each name in the list.
  • status=$(…) saves the command's output in a variable.
  • To watch another service, just add its name to the list.

Concepts

What does "healthy" mean?

CheckQuestionCommand
ServiceIs it running?systemctl is-active nginx
WebsiteDoes it answer with 200?curl -s -o /dev/null -w "%{http_code}" URL
PortIs anything listening on port 22?nc -z 127.0.0.1 22
ProcessIs the program in memory?pgrep nginx
DiskIs the disk almost full?df -h

A service can be "active" but still not answer (for example if it is stuck), so a website check is a useful extra.

systemctl and journalctl commands

CommandWhat it does
systemctl status nginxshow the state and the last log lines (for humans)
systemctl is-active nginxprint active/inactive/failed (for scripts)
systemctl is-enabled nginxwill it start at boot? enabled/disabled
sudo systemctl start | stop | restart nginxcontrol the service
journalctl -u nginx -n 20last 20 log lines of the service: shows why it stopped

Add %{time_total} to also get the response time in seconds:

bash
curl -s -o /dev/null -w "%{http_code} %{time_total}\n" --max-time 10 https://example.com

Datasets: the list of checks

Instead of writing service names inside the script, we keep them in a text file. Each line has four columns: a name, the check type (systemd, http or port), what to check, and the expected result. To watch something new, you add a line; the script stays the same.

datasets/services.txt
# service     type     target                        expect
nginx         systemd  nginx                         active
mysql         systemd  mysql                         active
php-fpm       systemd  php8.3-fpm                    active
redis         systemd  redis-server                  active
website       http     https://example.com           200
api-health    http     https://api.example.com/health 200
ssh           port     127.0.0.1:22                  open
mysql-port    port     127.0.0.1:3306                open

Read the file line by line. while read puts the four columns into four variables:

bash
grep "systemd" datasets/services.txt | while read name type unit expect; do
    echo "will check the service $unit (expect: $expect)"
done

will check the service nginx (expect: active)
will check the service mysql (expect: active)
will check the service php8.3-fpm (expect: active)
will check the service redis-server (expect: active)

Use cases

Use case 1 Service watchdog

Goal. Read every systemd line from services.txt, check each service, restart the ones that are down, and write what happened to a log file. Run it from cron every 5 minutes.

bash · watchdog.sh
#!/bin/bash
# watchdog.sh: check every systemd service in services.txt, restart the ones that are down
# usage: sudo ./watchdog.sh

LIST="datasets/services.txt"
LOG="watchdog.log"

grep "systemd" "$LIST" | while read name type unit expect; do
    if systemctl is-active --quiet "$unit"; then
        echo "OK      $name"
    else
        echo "DOWN    $name, restarting $unit"
        systemctl restart "$unit"
        sleep 5                                   # give it time to start
        if systemctl is-active --quiet "$unit"; then
            echo "FIXED   $name"
            echo "$(date '+%F %T') $name was down, restarted OK" >> "$LOG"
        else
            echo "FAILED  $name is still down!"
            echo "$(date '+%F %T') $name restart FAILED" >> "$LOG"
        fi
    fi
done
bash · run it
chmod +x watchdog.sh
sudo systemctl stop redis-server       # break something on purpose
sudo ./watchdog.sh
cat watchdog.log
sample output
OK      nginx
OK      mysql
OK      php-fpm
DOWN    redis, restarting redis-server
FIXED   redis
2026-11-17 10:05:12 redis was down, restarted OK

How it works

  • grep "systemd" keeps only the service lines; while read splits each line into name type unit expect.
  • sleep 5 waits a little after the restart, then the script checks again to see if the restart really worked.
  • Only problems are written to the log, so it stays short. >> appends.
  • If a service stays down, look at journalctl -u redis-server -n 20 to see why. You could also send an email here (see Lab 07).

Use case 2 Website checker that saves results to CSV

Goal. Check every http line of services.txt, show UP or DOWN with the response time, and add one line per website to uptime.csv. Run every minute from cron and you get a history you can open in a spreadsheet.

bash · website_check.sh
#!/bin/bash
# website_check.sh: check each website in services.txt and save the results in a CSV file

LIST="datasets/services.txt"
CSV="uptime.csv"

if [ ! -f "$CSV" ]; then                          # first run: write the header line
    echo "time,name,url,code,seconds" > "$CSV"
fi

now=$(date '+%F %T')
grep " http " "$LIST" | while read name type url expect; do
    result=$(curl -s -o /dev/null -w "%{http_code} %{time_total}" --max-time 10 "$url")
    code=$(echo "$result" | cut -d' ' -f1)        # first word: status code
    secs=$(echo "$result" | cut -d' ' -f2)        # second word: time in seconds
    if [ "$code" = "$expect" ]; then
        echo "UP    $name  $code  ${secs}s"
    else
        echo "DOWN  $name  $code  ${secs}s"
    fi
    echo "$now,$name,$url,$code,$secs" >> "$CSV"
done
bash · run it
bash website_check.sh
cat uptime.csv
sample output
UP    website  200  0.284113s
DOWN  api-health  000  10.001342s
time,name,url,code,seconds
2026-11-17 10:05:01,website,https://example.com,200,0.284113
2026-11-17 10:05:01,api-health,https://api.example.com/health,000,10.001342

How it works

  • [ ! -f "$CSV" ] is true when the file does not exist yet; only then is the header line written.
  • curl prints two values, like 200 0.284113. cut -d' ' -f1 takes the first word, -f2 the second.
  • The status code is compared with the 4th column of the list (expect), so different sites can expect different codes.
  • 000 with about 10 seconds means the site did not answer before --max-time 10.

Later you can count the DOWN results per site from the CSV, for example with awk -F, '$4 != 200 {print $2}' uptime.csv | sort | uniq -c.

Use case 3 Coloured status list (optional)

Goal. Print every server from servers.json with its status in colour: green for running, yellow for degraded, red for anything else. This one runs on any computer.

bash · status_list.sh
#!/bin/bash
# status_list.sh: coloured status list of all servers in servers.json

GREEN="\033[32m"; RED="\033[31m"; YELLOW="\033[33m"; RESET="\033[0m"
if [ ! -t 1 ]; then                       # not a terminal (a file or a pipe)?
    GREEN=""; RED=""; YELLOW=""; RESET="" # then do not print colour codes
fi

jq -r '.servers[] | "\(.hostname) \(.status) \(.cpu_pct)"' datasets/servers.json |
while read host status cpu; do
    if [ "$status" = "running" ]; then
        color=$GREEN
    elif [ "$status" = "degraded" ]; then
        color=$YELLOW
    else
        color=$RED
    fi
    printf "%-8s ${color}%-9s${RESET} cpu %s%%\n" "$host" "$status" "$cpu"
done
bash · run it
chmod +x status_list.sh
./status_list.sh
output
web01    running   cpu 52%
web02    stopped   cpu 8%
web03    running   cpu 64%
db01     running   cpu 43%
db02     stopped   cpu 63%
cache01  running   cpu 17%
lb01     running   cpu 61%
mon01    degraded  cpu 87%

The output above has no colours because it was saved to this page. In a terminal, running is green, degraded yellow and stopped red.

How it works

  • \033[32m is the "switch to green" code; \033[0m switches back to normal. printf turns \033 into the escape character.
  • [ ! -t 1 ] is true when the output is not a terminal (a file or a pipe). Then the colour codes are emptied, so no strange characters end up in files.
  • jq -r prints one line per server with three words, and while read host status cpu splits them.
  • %-8s pads the host name to 8 characters so the columns line up.
Optional: going further (check a port without nc)

Bash can open a network connection by itself through the special path /dev/tcp/HOST/PORT. This checks the port lines of services.txt:

bash · port_check.sh
#!/bin/bash
# port_check.sh: is something listening on each host:port in services.txt?
grep " port " datasets/services.txt | while read name type target expect; do
    host=$(echo "$target" | cut -d: -f1)      # 127.0.0.1
    port=$(echo "$target" | cut -d: -f2)      # 22
    if timeout 2 bash -c "echo > /dev/tcp/$host/$port" 2>/dev/null; then
        echo "$name: port $port open"
    else
        echo "$name: port $port CLOSED"
    fi
done
sample output
ssh: port 22 open
mysql-port: port 3306 open

timeout 2 stops the attempt after 2 seconds, so a blocked port does not make the script hang.

Viva / exam questions

How do you check from a script whether nginx is running?

systemctl is-active --quiet nginx and test its exit code with if: 0 means running.

What is the difference between is-active and is-enabled?

is-active: is it running now. is-enabled: will it start automatically at boot.

How do you get only the HTTP status code with curl?

curl -s -o /dev/null -w "%{http_code}" URL.

What does status code 000 mean in curl?

There was no HTTP answer at all: the host could not be reached, refused the connection, or the request timed out.

Why use --max-time?

So a slow or dead server cannot make the monitoring script wait forever.

How do you see why a service stopped?

journalctl -u NAME -n 20 shows its last 20 log lines; systemctl status NAME also shows a few.

Why keep the services in a separate file?

You can add or remove checks without changing the script, and the same script works on different servers.

How do you run a check every 5 minutes?

With cron: */5 * * * * /path/to/watchdog.sh in crontab -e (root's crontab if it must restart services).
