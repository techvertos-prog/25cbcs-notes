Lab 11: Backup and retention scripts

Write scripts that back up a website folder and its database into files with the date in the name, check what is inside them, copy them to another machine, and delete old backups automatically so the disk never fills up.

Commands: tar, date, mysqldump, find, rsync, cronDifficulty: beginner~45 min

Aim and objectives

  • Create, list and extract .tar.gz backups with tar.
  • Put the date in a file name with date +%F.
  • Save a MySQL database with mysqldump.
  • Delete old backups with find -mtime +N -delete (the retention policy).
  • Copy backups to another server with rsync and run the script every night with cron.

Prerequisites

  • Any Linux machine (or macOS) for the tar and find parts. tar, gzip and find are already installed.
  • For the database and remote-copy parts: sudo apt install -y mysql-client rsync and a second machine reachable with ssh (Lab 03).
  • The scripts back up a small practice folder called website. Make it first:
bash · create a practice folder
mkdir -p website/css
echo "<h1>Home</h1>"  > website/index.html
echo "<h1>About</h1>" > website/about.html
echo "body { font-family: sans-serif; }" > website/css/style.css

Start here: simple scripts

1. Make a backup with the date in its name

bash · backup_tar.sh
#!/bin/bash
# backup_tar.sh: pack the "website" folder into a .tar.gz with today's date

today=$(date +%F)                     # today's date, e.g. 2026-11-17
file="website_$today.tar.gz"          # the backup file name

tar -czf "$file" website              # c = create, z = gzip, f = file name
echo "Created $file"
bash · run it
chmod +x backup_tar.sh
./backup_tar.sh
output
Created website_2026-11-17.tar.gz
  • date +%F prints today's date as YEAR-MONTH-DAY.
  • tar -czf NAME folder packs the folder into one compressed file.
  • The date in the name means each day's backup gets a new file instead of overwriting yesterday's.

2. Look inside a backup

bash · list_backup.sh
#!/bin/bash
# list_backup.sh: show what is inside a backup, without unpacking it
# usage: ./list_backup.sh FILE.tar.gz

echo "Files in $1:"
tar -tzf "$1"                         # t = list the contents
count=$(tar -tzf "$1" | wc -l)        # count the lines
echo "Total entries: $count"
bash · run it
chmod +x list_backup.sh
./list_backup.sh website_$(date +%F).tar.gz
output
Files in website_2026-11-17.tar.gz:
website/
website/index.html
website/about.html
website/css/
website/css/style.css
Total entries: 5
  • tar -tzf lists the files inside without unpacking anything.
  • $1 is the file name you give after the script name.
  • Piping the list into wc -l counts the lines, so you can quickly see whether the backup is empty.

3. Back up a database

bash · db_dump.sh
#!/bin/bash
# db_dump.sh: save the "wordpress" database to a compressed .sql.gz file

file="db_$(date +%F).sql.gz"
mysqldump --single-transaction wordpress | gzip > "$file"
echo "Saved database to $file"
bash · run it
sudo bash db_dump.sh
sample output
Saved database to db_2026-11-17.sql.gz
  • mysqldump wordpress prints the whole database as SQL commands.
  • | gzip > file compresses that text and saves it.
  • --single-transaction takes a consistent copy without stopping the website.
  • To restore: gunzip -c db_2026-11-17.sql.gz | sudo mysql wordpress.

(Run on 2026-11-17. On a later day, more files will be listed.)

Concepts

Why back up, and what is retention?

  • A backup is a copy you can use if the original is deleted, broken or hacked.
  • Retention is the rule for how long to keep backups, for example "keep 7 days". Without it, the disk fills up.
  • 3-2-1 rule: keep 3 copies, on 2 different kinds of storage, with 1 copy in another place. A backup on the same disk as the website is lost if that disk fails.

tar options

CommandMeaning
tar -czf backup.tar.gz foldercreate a gzip archive, file name follows
tar -tzf backup.tar.gzlist the contents
tar -xzf backup.tar.gzextract into the current folder
tar -xzf backup.tar.gz -C /tmp/restoreextract into another folder (-C = change to folder first)
tar -czf b.tar.gz --exclude="*.log" folderskip files matching a pattern

Restore one backup into a test folder and compare it with the original:

bash
mkdir -p restore_test
tar -xzf website_$(date +%F).tar.gz -C restore_test
diff -r website restore_test/website && echo "Restore matches the original"
output
Restore matches the original

Dates in file names

CommandExample output
date +%F2026-11-17
date +%F_%H%M2026-11-17_0200 (date and time)
date '+%F %T'2026-11-17 02:00:01 (good for log lines)

Always use year-month-day order. Then sorting the names alphabetically also sorts them by date. 17-11-2026 would sort in the wrong order.

Checking a backup with a checksum

A checksum is a fingerprint of a file. If even one byte changes, the fingerprint changes.

bash
sha256sum datasets/app.conf datasets/services.txt > SHA256SUMS
sha256sum -c SHA256SUMS
output
datasets/app.conf: OK
datasets/services.txt: OK

-c recomputes every fingerprint and prints OK or FAILED. (On macOS use shasum -a 256.)

Running it every night with cron

Open the schedule with crontab -e and add a line. The five fields are minute, hour, day of month, month, day of week.

crontab -e
# every night at 02:00, run the backup and keep its output in a log
0 2 * * * /home/student/daily_backup.sh >> /home/student/cron.log 2>&1
# every night at 02:30, delete backups older than 7 days
30 2 * * * /home/student/cleanup_backups.sh 7 >> /home/student/cron.log 2>&1

Use full paths in cron: cron does not start in your home folder.

Use cases

Use case 1 Daily backup script with a log

Goal. One script that cron can run every night: it creates the backup folder if needed, makes a dated backup, checks that tar worked, and writes one line to a log file either way.

bash · daily_backup.sh
#!/bin/bash
# daily_backup.sh: back up a folder into a backups folder, with a log
# usage: ./daily_backup.sh

SOURCE="website"                      # what to back up
DEST="backups"                        # where to keep the backups
LOG="backup.log"                      # where to write what happened

mkdir -p "$DEST"                      # create the folder if it is missing
file="$DEST/website_$(date +%F_%H%M).tar.gz"

echo "Backing up $SOURCE ..."
tar -czf "$file" "$SOURCE"

if [ $? -eq 0 ]; then                 # $? = exit code of tar (0 = success)
    size=$(du -h "$file" | cut -f1)
    echo "OK: $file ($size)"
    echo "$(date '+%F %T') OK $file" >> "$LOG"
else
    echo "ERROR: backup failed"
    echo "$(date '+%F %T') FAILED $file" >> "$LOG"
    exit 1
fi
bash · run it
chmod +x daily_backup.sh
./daily_backup.sh
cat backup.log
output
Backing up website ...
OK: backups/website_2026-11-17_0009.tar.gz (4.0K)
2026-11-17 00:09:50 OK backups/website_2026-11-17_0009.tar.gz

How it works

  • The settings are variables at the top, so you can change what is backed up without touching the rest.
  • mkdir -p creates the folder and gives no error if it already exists.
  • $? holds the exit code of the last command: 0 means success. The if uses it to decide what to print and log.
  • du -h file | cut -f1 gives the size in a human-friendly form, like 4.0K.
  • >> appends to the log, so old entries are kept.

Use case 2 Cleanup script with a dry-run mode

Goal. Delete backups older than a number of days given on the command line. Because deleting is dangerous, the word dry makes it only show what it would delete.

bash
# test files: two old backups and two new ones
rm -rf backups && mkdir backups
touch -t 202611010200 backups/website_2026-11-01_0200.tar.gz
touch -t 202611050200 backups/website_2026-11-05_0200.tar.gz
touch -t 202611120200 backups/website_2026-11-12_0200.tar.gz
touch -t 202611160200 backups/website_2026-11-16_0200.tar.gz
ls backups
output
website_2026-11-01_0200.tar.gz
website_2026-11-05_0200.tar.gz
website_2026-11-12_0200.tar.gz
website_2026-11-16_0200.tar.gz
bash · cleanup_backups.sh
#!/bin/bash
# cleanup_backups.sh: delete backups older than N days
# usage: ./cleanup_backups.sh DAYS [dry]      "dry" = only show, delete nothing

DIR="backups"
DAYS=${1:-7}                          # first argument, or 7 if none given
MODE=$2

old=$(find "$DIR" -name "*.tar.gz" -mtime +$DAYS)
count=$(echo "$old" | grep -c "tar.gz")

if [ "$count" -eq 0 ]; then
    echo "Nothing older than $DAYS days."
    exit 0
fi

for file in $old; do
    if [ "$MODE" = "dry" ]; then
        echo "would delete: $file"
    else
        rm "$file"
        echo "deleted: $file"
    fi
done
echo "$count file(s) older than $DAYS days"
bash · run it
chmod +x cleanup_backups.sh
./cleanup_backups.sh 7 dry
./cleanup_backups.sh 7
./cleanup_backups.sh 7
ls backups
output
would delete: backups/website_2026-11-01_0200.tar.gz
would delete: backups/website_2026-11-05_0200.tar.gz
2 file(s) older than 7 days
deleted: backups/website_2026-11-01_0200.tar.gz
deleted: backups/website_2026-11-05_0200.tar.gz
2 file(s) older than 7 days
Nothing older than 7 days.
website_2026-11-12_0200.tar.gz
website_2026-11-16_0200.tar.gz

How it works

  • ${1:-7} uses the first argument, or 7 if you did not give one.
  • The find result is stored in the variable old; grep -c counts how many file names it holds.
  • If there is nothing to do, the script says so and exits with 0 (success).
  • The for loop goes through the files. [ "$MODE" = "dry" ] compares two strings: in dry mode it only prints.
  • The third run shows that the script is safe to repeat: the old files are already gone.
File namesfor file in $old splits on spaces. That is fine here because our own script makes the names and they never contain spaces.

Use case 3 Copy backups to another server with rsync

Goal. Follow the 3-2-1 rule: after the nightly backup, copy the whole backups folder to a second machine. rsync only sends files that are new or changed, so it is fast after the first time.

bash · copy_remote.sh
#!/bin/bash
# copy_remote.sh: copy the backups folder to another server with rsync

SERVER="backup@192.0.2.50"            # user@host of the backup server
REMOTE_DIR="/srv/backups/web01/"

rsync -av backups/ "$SERVER:$REMOTE_DIR"

if [ $? -eq 0 ]; then
    echo "Copy finished"
else
    echo "Copy FAILED"
    exit 1
fi
bash · run it
bash copy_remote.sh
sample output
sending incremental file list
website_2026-11-17_0200.tar.gz

sent 1,284 bytes  received 35 bytes  2,638.00 bytes/sec
total size is 4,610  speedup is 3.50
Copy finished

How it works

  • -a (archive) copies folders and keeps dates and permissions; -v lists each file sent.
  • Only the new backup was sent: the older ones were already on the server.
  • The trailing / in backups/ means "the contents of backups". Without it, rsync creates backups/backups on the server.
  • It needs ssh keys (Lab 03) so it can run from cron without asking for a password.
Optional: going further (keep only the newest N backups)

Instead of "older than 7 days", you can keep a fixed number of backups. ls -t lists newest first and tail -n +4 prints from line 4 onward, so everything except the newest 3:

bash
rm -rf backups && mkdir backups
touch -t 202611010200 backups/website_2026-11-01_0200.tar.gz
touch -t 202611050200 backups/website_2026-11-05_0200.tar.gz
touch -t 202611120200 backups/website_2026-11-12_0200.tar.gz
touch -t 202611160200 backups/website_2026-11-16_0200.tar.gz
touch -t 202611170200 backups/website_2026-11-17_0200.tar.gz
ls -t backups | tail -n +4
output
website_2026-11-05_0200.tar.gz
website_2026-11-01_0200.tar.gz

To delete them: cd backups && ls -t | tail -n +4 | xargs rm. The advantage: if backups stop working for a month, you still keep the last 3 good ones, while an "older than 7 days" rule would eventually delete everything.

Viva / exam questions

What do the letters in tar -czf mean?

c = create, z = compress with gzip, f = the next word is the archive file name.

How do you list a tar file without extracting it?

tar -tzf file.tar.gz.

Why put date +%F in the backup name?

Each backup gets a unique name, so it does not overwrite the previous one, and the year-month-day format sorts in date order.

What does find /backups -mtime +7 -delete do?

Finds files last modified more than 7 days ago in /backups and deletes them. Run it with -print first to check.

What is a retention policy?

A rule saying how long backups are kept, for example 7 daily backups. It stops backups from filling the disk.

What is the 3-2-1 rule?

3 copies of the data, on 2 different types of storage, 1 copy off-site.

Which command backs up a MySQL database?

mysqldump dbname > file.sql, usually piped through gzip. Restore with mysql dbname < file.sql.

Why use rsync instead of scp for repeated copies?

rsync only sends new or changed files, so later copies are much faster.

What does $? contain?

The exit code of the last command. 0 means success, anything else means an error.
