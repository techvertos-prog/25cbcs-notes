Lab 05: Managing DNS with the Cloudflare API (curl + jq)

Cloudflare runs DNS for millions of websites. Everything you can click in its dashboard can also be done from a script, by sending HTTP requests to its API. In this lab you use curl to talk to the API and jq to read the JSON answers, and you write small scripts that list, add and update DNS records.

Commands: curl, jqDifficulty: beginner~45 minCloudflare API v4
Offline vs onlineAPI calls need a Cloudflare account, a domain and a token, so their outputs here are labelled sample output and use example.com with made-up IDs. The jq examples marked "offline" read datasets/cf_dns_records.json, a saved API answer, so you can run them anywhere and get exactly the output shown.

Aim and objectives

Aim: manage DNS records of a domain from Bash using the Cloudflare API.

  • Create an API token and keep it safe.
  • Send API requests with curl and an Authorization: Bearer header.
  • Read the JSON answers with jq and check whether a request succeeded.
  • Write scripts to list, add and update DNS records.

Prerequisites

bash · install
sudo apt install -y curl jq      # Ubuntu / Debian
  • A free Cloudflare account with a test domain. These scripts change real DNS, so do not use an important domain.
  • Basic jq from Lab 04.

Create an API token (one time)

  1. In the Cloudflare dashboard click your profile icon, then My Profile, then API Tokens.
  2. Click Create Token and use the Edit zone DNS template.
  3. Permissions: Zone · DNS · Edit. Also add Zone · Zone · Read so scripts can list zones.
  4. Zone Resources: Include · Specific zone · your domain.
  5. Click Continue to summary, then Create Token. Copy the token now: Cloudflare shows it only once.

Keep the token out of your scripts. Put it in a file called .env that only you can read:

bash · .env
# .env  (never share this file or upload it to GitHub)
export CF_API_TOKEN="paste-your-token-here"
export ZONE_ID="paste-your-zone-id-here"
bash · protect and load it
chmod 600 .env        # only the owner can read and write it
source .env           # load the variables into this terminal
echo "${CF_API_TOKEN:0:4}..."   # print only the first 4 characters to check

Start here: simple scripts

Run source .env first, then each script with chmod +x name.sh and ./name.sh.

Step 1: check that the token works

bash · cf1_verify.sh
#!/bin/bash
# Step 1: check that your API token works
# The token is read from the environment variable CF_API_TOKEN
curl -s "https://api.cloudflare.com/client/v4/user/tokens/verify" \
     -H "Authorization: Bearer $CF_API_TOKEN" | jq '.'

Step 2: list your zones

bash · cf2_zones.sh
#!/bin/bash
# Step 2: list your zones (domains) and their IDs
api="https://api.cloudflare.com/client/v4"
curl -s "$api/zones" -H "Authorization: Bearer $CF_API_TOKEN" |
    jq -r '.result[] | .name + "  " + .id'     # one line per zone: name and id
bash · run
./cf2_zones.sh

Step 3: list the DNS records

Concepts

What is a REST API?

A REST API is a web address that a program (not a person) talks to. You send an HTTP request with a method (what to do) to a URL (what to do it to), and get JSON back. All Cloudflare URLs start with https://api.cloudflare.com/client/v4.

TaskMethodURL (after /client/v4)
Check tokenGET/user/tokens/verify
List zonesGET/zones
List DNS recordsGET/zones/{zone_id}/dns_records
Add a recordPOST/zones/{zone_id}/dns_records
Change a recordPATCH/zones/{zone_id}/dns_records/{record_id}
Delete a recordDELETE/zones/{zone_id}/dns_records/{record_id}

curl options used here

OptionMeaning
-ssilent: no progress bar
-X POSTHTTP method (GET is the default)
-H "Name: value"add a header (token, content type)
--data '…'send a request body (the JSON for a new record)

Every answer has the same shape

Cloudflare always answers with success, errors and result. If success is false, the reason is in errors. Here is a saved failed answer:

datasets/cf_error.json
{
  "result": null,
  "success": false,
  "errors": [
    {
      "code": 81058,
      "message": "An identical record already exists."
    }
  ],
  "messages": []
}
bash · offline: print the error message
jq '.success' datasets/cf_error.json
jq -r '.errors[0].message' datasets/cf_error.json
output

An identical record already exists.
Tipcurl's own exit code only tells you that a reply arrived, not that the API did what you asked. Always check .success with jq.

Use cases

Use case 1 List DNS records (with an optional type filter)

Scenario: you want a quick command to see all records, or only the A records, and a clear message if the token is wrong.

bash · list_records.sh
#!/bin/bash
# list_records.sh - show the DNS records of a zone, optionally only one type
# usage: ./list_records.sh [TYPE]      e.g. ./list_records.sh A
api="https://api.cloudflare.com/client/v4"
type="$1"

if [ -z "$CF_API_TOKEN" ] || [ -z "$ZONE_ID" ]; then
    echo "Please set CF_API_TOKEN and ZONE_ID first (source .env)"
    exit 1
fi

url="$api/zones/$ZONE_ID/dns_records"
if [ -n "$type" ]; then
    url="$url?type=$type"              # add a filter if a type was given
fi

response=$(curl -s "$url" -H "Authorization: Bearer $CF_API_TOKEN")

# Cloudflare answers "success": true or false in every response
if [ "$(echo "$response" | jq '.success')" != "true" ]; then
    echo "API error:"
    echo "$response" | jq -r '.errors[] | .message'
    exit 1
fi
echo "$response" | jq -r '.result[] | "\(.type)\t\(.name)\t\(.content)"'
bash · run
./list_records.sh A
sample output
A	example.com	203.0.113.10
A	www.example.com	203.0.113.10
A	api.example.com	203.0.113.20
A	staging.example.com	198.51.100.5
A	vpn.example.com	198.51.100.77
bash · with a wrong token
CF_API_TOKEN=wrong ./list_records.sh
sample output
API error:
Invalid API Token

How it works:

  • [ -z "$CF_API_TOKEN" ] is true when the variable is empty, so the script stops early with a helpful message.
  • If a type was given, ?type=A is added to the URL. The API then returns only A records.
  • The answer is saved in $response, so we can check .success and then print the records without calling the API twice.

Use case 2 Add one A record

Scenario: a new test server at 203.0.113.50 needs the name test.example.com.

bash · add_record.sh
#!/bin/bash
# add_record.sh - create one A record
# usage: ./add_record.sh NAME IP      e.g. ./add_record.sh test.example.com 203.0.113.50
api="https://api.cloudflare.com/client/v4"
name="$1"
ip="$2"

if [ -z "$name" ] || [ -z "$ip" ]; then
    echo "Usage: ./add_record.sh NAME IP"
    exit 1
fi

# Build the JSON body with jq, so the quotes are always correct
body=$(jq -n --arg n "$name" --arg ip "$ip" \
          '{type: "A", name: $n, content: $ip, ttl: 3600, proxied: false}')

response=$(curl -s -X POST "$api/zones/$ZONE_ID/dns_records" \
     -H "Authorization: Bearer $CF_API_TOKEN" \
     -H "Content-Type: application/json" \
     --data "$body")

if [ "$(echo "$response" | jq '.success')" = "true" ]; then
    echo "Created $name -> $ip"
else
    echo "Failed: $(echo "$response" | jq -r '.errors[0].message')"
fi
bash · run
./add_record.sh test.example.com 203.0.113.50
./add_record.sh www.example.com 203.0.113.10
./add_record.sh
sample output
Created test.example.com -> 203.0.113.50
Failed: An identical record already exists.
Usage: ./add_record.sh NAME IP

How it works:

  • -X POST means "create". The new record is sent as JSON with --data, and Content-Type: application/json tells the API it is JSON.
  • jq -n --arg builds that JSON from the Bash variables (see Lab 04).
  • The second run fails because www.example.com already exists; the script prints Cloudflare's error message.

Use case 3 Update the IP of an existing record

Scenario: the staging server moved to a new IP. Find the record by name, then change only its IP.

bash · update_record.sh
#!/bin/bash
# update_record.sh - change the IP address of an existing A record
# usage: ./update_record.sh NAME NEW_IP
api="https://api.cloudflare.com/client/v4"
name="$1"
new_ip="$2"
auth="Authorization: Bearer $CF_API_TOKEN"

# 1. find the record id by its name
id=$(curl -s "$api/zones/$ZONE_ID/dns_records?type=A&name=$name" -H "$auth" |
     jq -r '.result[0].id')

if [ "$id" = "null" ] || [ -z "$id" ]; then
    echo "No A record called $name"
    exit 1
fi
echo "Record id: $id"

# 2. PATCH changes only the fields we send (here: content)
curl -s -X PATCH "$api/zones/$ZONE_ID/dns_records/$id" \
     -H "$auth" -H "Content-Type: application/json" \
     --data "{\"content\": \"$new_ip\"}" |
     jq -r 'if .success then "Updated \(.result.name) -> \(.result.content)" else .errors[0].message end'
bash · run
./update_record.sh staging.example.com 198.51.100.6
./update_record.sh nothere.example.com 203.0.113.9
sample output
Record id: 3748967f961d33ba350843f08de08fc2
Updated staging.example.com -> 198.51.100.6
No A record called nothere.example.com

How it works:

  • Step 1 asks the API for the A record with that name and takes its id. If nothing matches, jq prints null and the script stops.
  • Step 2 uses PATCH, which changes only the fields you send (here content, the IP). The name, TTL and proxy setting stay the same.
  • An IP address has no quotes or spaces, so building the small JSON body as a string is fine here. For any text value use jq -n --arg as in Use case 2.
  • jq's if … then … else … end prints either the new value or the error message.
Optional: going further (dynamic DNS)

Home internet connections often get a new public IP. This script asks api.ipify.org for the current IP and updates vpn.example.com only when it changed. Run it every 5 minutes with cron: */5 * * * * cd /home/user/ddns && . ./.env && ./ddns.sh >> ddns.log

bash · ddns.sh
#!/bin/bash
# ddns.sh - point vpn.example.com at this machine's public IP (run from cron)
api="https://api.cloudflare.com/client/v4"
name="vpn.example.com"
auth="Authorization: Bearer $CF_API_TOKEN"

my_ip=$(curl -s https://api.ipify.org)                       # what is my public IP?
record=$(curl -s "$api/zones/$ZONE_ID/dns_records?type=A&name=$name" -H "$auth")
id=$(echo "$record" | jq -r '.result[0].id')
old_ip=$(echo "$record" | jq -r '.result[0].content')

if [ "$my_ip" = "$old_ip" ]; then
    echo "$(date '+%F %T') no change ($my_ip)"
else
    curl -s -X PATCH "$api/zones/$ZONE_ID/dns_records/$id" -H "$auth" \
         -H "Content-Type: application/json" --data "{\"content\": \"$my_ip\"}" > /dev/null
    echo "$(date '+%F %T') updated $name: $old_ip -> $my_ip"
fi
bash · run
./ddns.sh
sample output
2026-11-16 10:05:01 updated vpn.example.com: 198.51.100.77 -> 198.51.100.84

Viva / exam questions

What is an API token and why use it instead of your password?

A secret key that lets a script use the API. It can be limited to certain permissions (only DNS) and certain domains, and it can be deleted at any time without changing your password.

How does curl send the token?

In an HTTP header: -H "Authorization: Bearer $CF_API_TOKEN".

What is a zone id and how do you find it?

The unique id of a domain in Cloudflare. Get it with GET /zones and jq -r '.result[] | .name + " " + .id', or from the domain's Overview page.

Which HTTP methods create, change and delete a record?

POST creates, PATCH changes some fields, DELETE removes. GET only reads.

How do you know if an API call worked?

Check the success field of the JSON answer with jq '.success'. If it is false, print .errors[0].message.

Why do we store the token in .env with chmod 600?

So it is not written inside scripts that others may see, and so only the owner can read the file.

What does -X POST and --data do in curl?

-X POST sets the HTTP method; --data sends a request body, here the JSON describing the new record.
