Lab 07: Automated email alerts

Make the server tell you when something is wrong. You will read a number from a command (like disk usage), compare it with a limit using if, send an email with mail, and run the script automatically with cron.

Commands: df, awk, grep, if, mail, cronDifficulty: beginner~45 min

Aim and objectives

Aim: write a shell script that checks the server and sends an email alert when a limit is crossed, then schedule it with cron.

  • Get a number out of command output (disk Use%, count of failed logins).
  • Compare numbers with if [ … -ge … ].
  • Send an email from the command line with mail.
  • Run a script every few minutes or every morning with crontab.

Step 1: get the disk usage as a number

bash · disk_percent.sh
#!/bin/bash
# disk_percent.sh: get the Use% of the / filesystem as a plain number
# On a real server use:  df -h /   Here we read a saved copy of df -h.
line=$(grep ' /$' datasets/df.txt)          # the line that ends with " /"
echo "Line   : $line"
usage=$(echo "$line" | awk '{print $5}')     # column 5 is Use%, e.g. 87%
echo "Use%   : $usage"
usage=$(echo "$usage" | tr -d '%')           # remove the % sign
echo "Number : $usage"
bash · run it
chmod +x disk_percent.sh      # make it executable (only once)
./disk_percent.sh
output
Line   : /dev/sda1        50G   41G  6.5G  87% /
Use%   : 87%
Number : 87
  • grep ' /$' picks the line that ends ($) with a space and /, which is the root filesystem.
  • awk '{print $5}' prints the 5th column (columns are separated by spaces).
  • tr -d '%' deletes the % sign. We need a plain number like 87 because if cannot compare 87%.
  • usage=$( … ) saves the output of a command in a variable. There must be no spaces around =.

Step 2: compare with a limit

bash · disk_check.sh
#!/bin/bash
# disk_check.sh: compare disk usage with a limit
limit=80                                      # alert when usage >= 80
usage=$(grep ' /$' datasets/df.txt | awk '{print $5}' | tr -d '%')

if [ "$usage" -ge "$limit" ]; then            # -ge means "greater or equal"
  echo "WARNING: / is ${usage}% full (limit ${limit}%)"
else
  echo "OK: / is ${usage}% full"
fi
bash · run it
bash disk_check.sh
output
WARNING: / is 87% full (limit 80%)
  • [ "$usage" -ge "$limit" ] is true when usage is greater than or equal to the limit. The spaces inside [ ] are required.
  • ${usage}%: the braces show where the variable name ends, so the % is printed after it.
  • Change limit=80 to limit=90 and run it again: you get the OK line.

Step 3: check every disk with a loop

bash · all_disks.sh
#!/bin/bash
# all_disks.sh: check every filesystem, not only /
limit=85
while read -r fs size used avail pct mount; do   # split each line into 6 words
  if [ "$fs" = "Filesystem" ]; then              # skip the header line
    continue
  fi
  num=$(echo "$pct" | tr -d '%')                 # 87% -> 87
  if [ "$num" -ge "$limit" ]; then
    echo "ALERT: $mount is at $pct, only $avail free"
  fi
done < datasets/df.txt
output
ALERT: / is at 87%, only 6.5G free
ALERT: /backup is at 96%, only 22G free
ALERT: /data is at 92%, only 90G free
  • while read -r fs size used avail pct mount reads one line at a time and splits it into six variables.
  • done < datasets/df.txt feeds the file into the loop.
  • continue jumps to the next line, so the header is skipped.

Step 4: send the alert by email

This one uses the real df and the real mail command, so run it on your Linux machine after setting up mail (see Concepts).

bash · disk_mail.sh
#!/bin/bash
# disk_mail.sh: send an email when / is too full
to="admin@example.com"                        # who gets the alert
limit=80
usage=$(df -P / | awk 'NR==2 {print $5}' | tr -d '%')   # real df this time

if [ "$usage" -ge "$limit" ]; then
  echo "Disk / on $(hostname) is ${usage}% full." | mail -s "Disk alert" "$to"
  echo "Alert mailed to $to"
else
  echo "Disk OK (${usage}%), no mail sent"
fi
sample output
Alert mailed to admin@example.com
  • df -P / prints a header line and one line for /; awk 'NR==2' takes line number 2.
  • echo "text" | mail -s "subject" address: the text you pipe in becomes the body of the email.
  • The mail arrives with subject Disk alert and body Disk / on web01 is 87% full.

Concepts

How the mail is sent

mail builds the message (subject, body). It hands it to msmtp, which logs in to Gmail's SMTP server and delivers it.

ProgramJob
mail (mailutils)Builds the email: mail -s "subject" to@example.com
msmtpSends it to an SMTP server such as smtp.gmail.com
~/.msmtprcmsmtp settings: server, username, password

For Gmail, turn on 2-Step Verification and create an app password (Google Account → Security → App passwords). Your normal password will not work.

Comparing numbers and text

TestTrue when
[ "$a" -eq "$b" ]numbers are equal
[ "$a" -ne "$b" ]numbers are not equal
[ "$a" -gt "$b" ] / -gea greater than / greater or equal to b
[ "$a" -lt "$b" ] / -lea less than / less or equal to b
[ "$a" = "$b" ]text is the same
[ -s file ]file exists and is not empty
Viva-gt, -ge and friends work only with whole numbers. [ 87% -gt 80 ] gives integer expression expected, which is why we remove the % first.

Use cases

Each use case is a short, complete script. Mail sending is switched off with send_mail="no" so you can test it safely; change it to "yes" on a server where mail works.

Use case 1 Disk usage alert

What: check every filesystem and send one email that lists all disks above 85%. Why: a full disk stops databases and logs; you want to know before it happens.

bash · disk_alert.sh
#!/bin/bash
# disk_alert.sh: email one report listing every disk above the limit
limit=85
to="admin@example.com"
send_mail="no"                           # change to "yes" on a real server
report="/tmp/disk_report.txt"
disks="datasets/df.txt"             # on a server: df -hP > /tmp/df.txt, then use /tmp/df.txt

echo "Disk alert for $(hostname) (limit ${limit}%)" > "$report"   # > starts a new file
problems=0
while read -r fs size used avail pct mount; do
  if [ "$fs" = "Filesystem" ]; then continue; fi                 # skip header
  num=$(echo "$pct" | tr -d '%')
  if [ "$num" -ge "$limit" ]; then
    echo "  $mount is at $pct ($avail free of $size)" >> "$report"   # >> adds a line
    problems=$((problems + 1))
  fi
done < "$disks"

cat "$report"
if [ "$problems" -eq 0 ]; then
  echo "All disks OK, nothing to send."
elif [ "$send_mail" = "yes" ]; then
  mail -s "Disk alert: $problems disk(s) above ${limit}%" "$to" < "$report"
  echo "Mail sent to $to"
else
  echo "($problems problem(s) found, mail not sent because send_mail=no)"
fi
bash · run it
chmod +x disk_alert.sh
./disk_alert.sh
output (your host name will differ)
Disk alert for web01 (limit 85%)
  / is at 87% (6.5G free of 50G)
  /backup is at 96% (22G free of 500G)
  /data is at 92% (90G free of 1.0T)
(3 problem(s) found, mail not sent because send_mail=no)

How it works

  • The first echo … > "$report" creates a fresh report file; every >> afterwards adds one line.
  • problems=$((problems + 1)) counts how many disks are over the limit.
  • if / elif / else decides: nothing wrong, send the mail, or only report.
  • mail … < "$report" uses the report file as the email body.

Use case 2 SSH brute-force alert

What: find IP addresses that typed a wrong SSH password 5 or more times and email the list with a command to block each one. Why: bots try thousands of passwords; one mail per failed login would be useless.

bash · ssh_alert.sh
#!/bin/bash
# ssh_alert.sh: list IPs with many failed SSH logins and mail the list
log="$1"                                 # first argument = log file
if [ -z "$log" ]; then log="datasets/auth.log"; fi
limit=5
to="security@example.com"
send_mail="no"                           # "yes" on a real server

# count failed logins per IP: the IP is 4th word from the end of the line
grep 'Failed password' "$log" | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn > /tmp/ssh_counts.txt
echo "Failed logins per IP:"
cat /tmp/ssh_counts.txt

> /tmp/ssh_report.txt                    # empty the report file
while read -r count ip; do
  if [ "$count" -ge "$limit" ]; then
    echo "$ip failed $count times, block with: sudo ufw deny from $ip" >> /tmp/ssh_report.txt
  fi
done < /tmp/ssh_counts.txt

echo "IPs at or above $limit failures:"
cat /tmp/ssh_report.txt
if [ -s /tmp/ssh_report.txt ] && [ "$send_mail" = "yes" ]; then   # -s = file is not empty
  mail -s "SSH brute-force report" "$to" < /tmp/ssh_report.txt
fi
bash · run it
./ssh_alert.sh datasets/auth.log
output
Failed logins per IP:
     12 45.33.32.156
      7 103.21.244.9
      5 91.240.118.172

How it works

  • A failed line ends with from 45.33.32.156 port 62399 ssh2. $NF is the last word, so $(NF-3) is the IP.
  • sort | uniq -c | sort -rn is the classic "count and rank" pipeline.
  • while read -r count ip reads each count ip pair back from the saved file.
  • > /tmp/ssh_report.txt on its own empties the file; [ -s file ] checks it is not empty before mailing.

Use case 3 Daily server report by email

What: every morning at 07:30, mail a short report: full disks, top web clients and failed SSH logins. Why: one quick look tells the admin whether the server is healthy.

bash · daily_report.sh
#!/bin/bash
# daily_report.sh: a short plain-text server report, run every morning by cron
to="admin@example.com"
send_mail="no"                           # "yes" on a real server
out="/tmp/daily_report.txt"

echo "Daily report for $(hostname), $(date +%F)" > "$out"
echo "" >> "$out"
echo "Disks above 85%:" >> "$out"
awk 'NR > 1 && $5+0 >= 85 {print "  " $6, $5}' datasets/df.txt >> "$out"
echo "Top 3 web clients:" >> "$out"
awk '{print $1}' datasets/access.log | sort | uniq -c | sort -rn | head -3 >> "$out"
echo "Failed SSH logins: $(grep -c 'Failed password' datasets/auth.log)" >> "$out"

cat "$out"
if [ "$send_mail" = "yes" ]; then
  mail -s "Daily report $(hostname)" "$to" < "$out"
fi
output (host name and date will differ)
Daily report for web01, 2026-11-17

Disks above 85%:
  / 87%
  /backup 96%
  /data 92%
Top 3 web clients:
     18 192.168.1.10
     14 192.168.1.15
     13 10.0.0.5
Failed SSH logins: 27
bash · schedule it with crontab -e
30 7 * * *  cd /home/student/CBCS-UNIT4-STUDY-GUIDE && ./daily_report.sh >> /tmp/daily_report.log 2>&1

How it works

  • Each section appends to the same file with >>, then the whole file is mailed.
  • $5+0 in awk turns 87% into the number 87, so $5+0 >= 85 works without tr.
  • $(grep -c …) inside the echo text puts the count straight into the sentence.
  • The cron line does cd first, because the script uses the relative path datasets/.
Optional: going further (stop repeated alerts)

If cron runs disk_alert.sh every 10 minutes, a full disk sends 144 mails a day. Save the time of the last mail in a file and only mail again after one hour:

bash · cooldown.sh
#!/bin/bash
stamp=/tmp/disk_alert.last              # file that holds the time of the last mail
now=$(date +%s)                         # seconds since 1970
last=0
if [ -f "$stamp" ]; then last=$(cat "$stamp"); fi

if [ $((now - last)) -ge 3600 ]; then   # 3600 seconds = 1 hour
  echo "Disk alert!" | mail -s "Disk alert" admin@example.com
  echo "$now" > "$stamp"                # remember when we sent it
else
  echo "Alert already sent less than an hour ago, skipping"
fi
sample output (second run within an hour)
Alert already sent less than an hour ago, skipping

Viva / exam questions

What does mail -s "Disk alert" admin@example.com do?

It sends an email with the subject "Disk alert" to admin@example.com. The body is read from standard input, for example from echo "text" | or < file.

What is msmtp and why do we need it?

msmtp is a small SMTP client. It takes the message built by mail and delivers it to a real mail server such as smtp.gmail.com, logging in with the account in ~/.msmtprc.

Why must ~/.msmtprc have permission 600?

It contains the mail password. 600 means only the owner can read and write it. msmtp refuses to start if other users can read the file.

How do you get the disk usage of / as a number in a script?

df -P / | awk 'NR==2 {print $5}' | tr -d '%'. awk picks column 5 of line 2 (for example 87%), and tr removes the % sign.

What is the difference between -gt and > inside [ ]?

-gt compares numbers. Inside [ ], > is treated as output redirection and creates a file, so it must not be used for numbers.

Explain the five time fields of a crontab line.

Minute, hour, day of month, month, day of week, followed by the command. 30 7 * * * means 07:30 every day; */10 * * * * means every 10 minutes.

What does MAILTO do in a crontab?

Cron emails anything a job prints to the address in MAILTO. MAILTO="" switches this off.

Why does a script that works in the terminal sometimes fail in cron?

Cron runs it with a minimal environment: a short PATH, the home directory as the current folder, and no terminal. Use full paths and redirect output to a log file to see errors.
