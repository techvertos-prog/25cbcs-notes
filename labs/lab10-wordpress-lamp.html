Lab 10: Automated WordPress on LAMP

Write a Bash script that installs a complete WordPress website on Ubuntu: the Apache web server, the MySQL database, PHP, and the WordPress files. Instead of typing twenty commands by hand, you run one script.

Commands: apt, systemctl, mysql, wget, tar, sedDifficulty: beginner~45 minUbuntu 24.04

Aim and objectives

  • Understand what LAMP means: Linux, Apache, MySQL, PHP.
  • Install packages from a script with apt install -y.
  • Create a database and a user by sending SQL to mysql with a heredoc.
  • Download and unpack WordPress with wget and tar.
  • Edit the WordPress config file automatically with sed.

Prerequisites

  • An Ubuntu 24.04 virtual machine (VirtualBox or a cloud VM) where you can use sudo, with internet access. Do not practise on your own laptop's operating system.
  • Basic Bash: variables, if, for. The sed examples in this lab also run on any computer using the files in datasets/.

Start here: simple scripts

Five small scripts, each doing one step. Use case 1 later joins them into one installer.

1. Check that you are root

Installing software needs administrator (root) rights. A good install script checks this first.

bash · check_root.sh
#!/bin/bash
# check_root.sh: installing software needs root, so check first

if [ "$(id -u)" -ne 0 ]; then        # id -u prints 0 for root
    echo "Please run this script with sudo"
    exit 1                           # stop with an error code
fi
echo "OK, running as root"
bash · run it
chmod +x check_root.sh
./check_root.sh
output
Please run this script with sudo

That was run as a normal user. With sudo ./check_root.sh it prints OK, running as root.

  • id -u prints your user ID number. Root is always 0.
  • $( … ) runs a command and puts its output in that place.
  • -ne means "not equal" for numbers. exit 1 stops the script and reports an error.

2. Install the apache2 package

bash · install_apache.sh
#!/bin/bash
# install_apache.sh: install and start the Apache web server

echo "Updating package list..."
apt update -y                        # refresh the list of packages

echo "Installing apache2..."
apt install -y apache2               # -y answers "yes" automatically

systemctl enable --now apache2       # start now and at every boot
systemctl is-active apache2          # prints "active" if it is running
bash · run it
chmod +x install_apache.sh
sudo ./install_apache.sh
sample output
Updating package list...
...
Installing apache2...
...
active
  • apt install -y: the -y answers "yes" to the question "Do you want to continue?", so the script never stops to wait for you.
  • systemctl enable --now apache2 starts Apache now and also every time the machine boots.
  • Open http://localhost/ (or the VM's IP) in a browser: you should see the "Apache2 Default Page".

3. Build SQL with a heredoc

A heredoc (<<SQL … SQL) feeds several lines of text into a command. Here we send it to cat so you can see the text, with the variables already filled in.

bash · show_sql.sh
#!/bin/bash
# show_sql.sh: build SQL commands with a heredoc and print them

DB_NAME="wordpress"
DB_USER="wpuser"
DB_PASS="Lab10Pass"

cat <<SQL
CREATE DATABASE $DB_NAME;
CREATE USER '$DB_USER'@'localhost' IDENTIFIED BY '$DB_PASS';
GRANT ALL PRIVILEGES ON $DB_NAME.* TO '$DB_USER'@'localhost';
FLUSH PRIVILEGES;
SQL
bash · run it
bash show_sql.sh
output
CREATE DATABASE wordpress;
CREATE USER 'wpuser'@'localhost' IDENTIFIED BY 'Lab10Pass';
GRANT ALL PRIVILEGES ON wordpress.* TO 'wpuser'@'localhost';
FLUSH PRIVILEGES;
  • Everything between <<SQL and the line SQL becomes the input of cat.
  • $DB_NAME, $DB_USER and $DB_PASS are replaced by their values.
  • The end word (SQL) must be alone on its line, with no spaces before it.

4. Create the database

Same heredoc, but now the input goes to mysql, which runs the SQL.

bash · create_db.sh
#!/bin/bash
# create_db.sh: the same heredoc, but sent to mysql instead of the screen

DB_NAME="wordpress"
DB_USER="wpuser"
DB_PASS="Lab10Pass"

mysql <<SQL
CREATE DATABASE $DB_NAME;
CREATE USER '$DB_USER'@'localhost' IDENTIFIED BY '$DB_PASS';
GRANT ALL PRIVILEGES ON $DB_NAME.* TO '$DB_USER'@'localhost';
FLUSH PRIVILEGES;
SQL
echo "Database $DB_NAME and user $DB_USER created"
bash · run it
sudo bash create_db.sh
sudo mysql -e "SHOW DATABASES;"
sample output
Database wordpress and user wpuser created
+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
| wordpress          |
+--------------------+
  • On Ubuntu, the Linux root user can open mysql without a password, so sudo is enough.
  • The new user wpuser gets rights on the wordpress database only. WordPress never needs the MySQL root account.
  • Running it a second time fails with "database exists". Use case 1 adds IF NOT EXISTS to avoid that.

5. Download and unpack WordPress

bash · get_wordpress.sh
#!/bin/bash
# get_wordpress.sh: download WordPress and unpack it into the web folder

cd /tmp                                            # work in a temporary folder
wget -q https://wordpress.org/latest.tar.gz        # -q = quiet download
tar -xzf latest.tar.gz                             # creates the folder "wordpress"
cp -r wordpress/* /var/www/html/                   # copy the files to Apache's folder
rm /var/www/html/index.html                        # remove Apache's default page
chown -R www-data:www-data /var/www/html           # Apache runs as user www-data
echo "WordPress files copied to /var/www/html"
bash · run it
sudo bash get_wordpress.sh
ls /var/www/html | head -5
sample output
WordPress files copied to /var/www/html
index.php
license.txt
readme.html
wp-activate.php
wp-admin
  • wget downloads a file from a URL. latest.tar.gz always holds the newest WordPress.
  • tar -xzf: extract, gzip-compressed, file name follows.
  • /var/www/html is the folder Apache serves by default. Apache runs as the user www-data, so that user must own the files (chown).

Concepts

How a WordPress page is served

The browser talks only to Apache. Apache gives .php files to PHP, and the WordPress PHP code reads its posts from MySQL using the database name, user and password written in wp-config.php.

PartPackageJob
Web serverapache2answers browser requests on port 80
Databasemysql-serverstores posts, users and settings
PHPphp, libapache2-mod-php, php-mysqlruns the WordPress code; php-mysql lets PHP talk to MySQL
WordPressdownload from wordpress.orgthe website software itself

Editing wp-config.php with sed

WordPress ships a sample config file with placeholders like database_name_here. Our script copies it to wp-config.php and replaces each placeholder with sed. You can practise on these two files on any computer.

datasets/wp-config-sample.php
<?php
/**
 * The base configuration for WordPress (excerpt of wp-config-sample.php)
 */

// ** Database settings - You can get this info from your web host ** //
/** The name of the database for WordPress */
define( 'DB_NAME', 'database_name_here' );

/** Database username */
define( 'DB_USER', 'username_here' );

/** Database password */
define( 'DB_PASSWORD', 'password_here' );

/** Database hostname */
define( 'DB_HOST', 'localhost' );

/** Database charset to use in creating database tables. */
define( 'DB_CHARSET', 'utf8' );

/**#@+
 * Authentication unique keys and salts.
 */
define( 'AUTH_KEY',         'put your unique phrase here' );
define( 'SECURE_AUTH_KEY',  'put your unique phrase here' );
define( 'LOGGED_IN_KEY',    'put your unique phrase here' );
define( 'NONCE_KEY',        'put your unique phrase here' );
define( 'AUTH_SALT',        'put your unique phrase here' );
define( 'SECURE_AUTH_SALT', 'put your unique phrase here' );
define( 'LOGGED_IN_SALT',   'put your unique phrase here' );
define( 'NONCE_SALT',       'put your unique phrase here' );
/**#@-*/

$table_prefix = 'wp_';

define( 'WP_DEBUG', false );

/* That's all, stop editing! Happy publishing. */
datasets/app.conf
# ===== Application configuration =====
APP_NAME=inventory-api
APP_ENV=development
APP_DEBUG=true
APP_PORT=8080

# Database
DB_HOST=localhost
DB_PORT=3306
DB_NAME=inventory
DB_USER=root
DB_PASS=changeme

# Logging
LOG_LEVEL=debug
LOG_FILE=/var/log/inventory/app.log
#LOG_ROTATE=daily

# Features

FEATURE_EMAIL=on
MAX_UPLOAD_MB=10

Replace one placeholder: s/old/new/ means "substitute old with new".

bash
sed "s/database_name_here/wordpress/" datasets/wp-config-sample.php | grep DB_NAME
output
define( 'DB_NAME', 'wordpress' );

Replace three at once: each -e adds one more substitution.

bash
sed -e "s/database_name_here/wordpress/" \
    -e "s/username_here/wpuser/" \
    -e "s/password_here/Lab10Pass/" datasets/wp-config-sample.php | grep "DB_"
output
define( 'DB_NAME', 'wordpress' );
define( 'DB_USER', 'wpuser' );
define( 'DB_PASSWORD', 'Lab10Pass' );
define( 'DB_HOST', 'localhost' );
define( 'DB_CHARSET', 'utf8' );

Change a KEY=value line: ^ means "start of line" and .* means "the rest of the line".

bash
sed "s/^APP_ENV=.*/APP_ENV=production/" datasets/app.conf | grep APP_ENV
output
APP_ENV=production
Linux vs macOSThe commands above print the result and leave the file unchanged. To change the file itself on Linux, add -i: sed -i "s/old/new/" file. On macOS you must write sed -i '' "s/old/new/" file.
Secret keysThe sample file also has eight lines saying put your unique phrase here. They are secret keys for login cookies. For a lab site they can stay, but for a real site replace them with the lines from https://api.wordpress.org/secret-key/1.1/salt/ (open it in a browser: it gives new random keys every time).

Use cases

Use case 1 One script that installs WordPress

Goal. Put the five start-here steps into one script, so a fresh Ubuntu VM becomes a WordPress site with one command. Each step prints a message, so you can see where it is.

bash · install_wordpress.sh
#!/bin/bash
# install_wordpress.sh: install WordPress on Ubuntu (Apache + MySQL + PHP)
# usage: sudo ./install_wordpress.sh

DB_NAME="wordpress"
DB_USER="wpuser"
DB_PASS="Lab10Pass"                  # change this for a real site

if [ "$(id -u)" -ne 0 ]; then
    echo "Please run with sudo"
    exit 1
fi

echo "Step 1: installing Apache, MySQL and PHP..."
apt update -y
apt install -y apache2 mysql-server php libapache2-mod-php php-mysql

echo "Step 2: creating the database..."
mysql <<SQL
CREATE DATABASE IF NOT EXISTS $DB_NAME;
CREATE USER IF NOT EXISTS '$DB_USER'@'localhost' IDENTIFIED BY '$DB_PASS';
GRANT ALL PRIVILEGES ON $DB_NAME.* TO '$DB_USER'@'localhost';
FLUSH PRIVILEGES;
SQL

echo "Step 3: downloading WordPress..."
cd /tmp
wget -q https://wordpress.org/latest.tar.gz
tar -xzf latest.tar.gz
cp -r wordpress/* /var/www/html/
rm -f /var/www/html/index.html

echo "Step 4: writing wp-config.php..."
cd /var/www/html
cp wp-config-sample.php wp-config.php
sed -i "s/database_name_here/$DB_NAME/" wp-config.php
sed -i "s/username_here/$DB_USER/" wp-config.php
sed -i "s/password_here/$DB_PASS/" wp-config.php

echo "Step 5: setting the owner and restarting Apache..."
chown -R www-data:www-data /var/www/html
systemctl restart apache2

echo "Done! Open http://localhost/ in a browser to finish the setup."
bash · run it
chmod +x install_wordpress.sh
sudo ./install_wordpress.sh
sample output
Step 1: installing Apache, MySQL and PHP...
...
Step 2: creating the database...
Step 3: downloading WordPress...
Step 4: writing wp-config.php...
Step 5: setting the owner and restarting Apache...
Done! Open http://localhost/ in a browser to finish the setup.

Now open the site in a browser: WordPress asks for a site title and an admin password, and the site is ready.

How it works

  • The three variables at the top are used in two places (the SQL and wp-config.php), so they always match.
  • IF NOT EXISTS means the script does not fail if you run it a second time.
  • libapache2-mod-php lets Apache run PHP; php-mysql lets PHP connect to MySQL. Without them WordPress cannot work.
  • Step 4 uses sed -i (edit in place), exactly like the practice commands above.
  • rm -f removes Apache's default index.html, otherwise Apache would show it instead of WordPress. -f means no error if it is already gone.

Use case 2 Fill in wp-config.php from arguments

Goal. A small tool you can run anywhere: give it the database name, user and password, and it writes a ready wp-config.php. It also checks that you gave exactly three arguments.

bash · configure_wp.sh
#!/bin/bash
# configure_wp.sh: fill in the database settings of a WordPress config file
# usage: ./configure_wp.sh DB_NAME DB_USER DB_PASS

if [ $# -ne 3 ]; then                    # $# = number of arguments
    echo "usage: $0 DB_NAME DB_USER DB_PASS"
    exit 1
fi

sample="datasets/wp-config-sample.php"   # the file we start from
output="wp-config.php"                   # the file we create

sed -e "s/database_name_here/$1/" \
    -e "s/username_here/$2/" \
    -e "s/password_here/$3/" "$sample" > "$output"

echo "Created $output. Database settings:"
grep "DB_" "$output"
bash · run it
chmod +x configure_wp.sh
./configure_wp.sh
./configure_wp.sh wordpress wpuser Lab10Pass
output
usage: ./configure_wp.sh DB_NAME DB_USER DB_PASS
Created wp-config.php. Database settings:
define( 'DB_NAME', 'wordpress' );
define( 'DB_USER', 'wpuser' );
define( 'DB_PASSWORD', 'Lab10Pass' );
define( 'DB_HOST', 'localhost' );
define( 'DB_CHARSET', 'utf8' );

How it works

  • $# is the number of arguments. If it is not 3, the script prints how to use it and stops.
  • $1, $2, $3 are the first, second and third arguments.
  • > "$output" saves sed's result into a new file, so the sample file is never changed.
  • grep "DB_" shows the lines we care about, as a quick check.

Use case 3 Check that the site works

Goal. After the install, check the important parts in one go: are Apache and MySQL running, does the config file exist, and does the web server answer?

bash · check_site.sh
#!/bin/bash
# check_site.sh: quick health check after installing WordPress

for service in apache2 mysql; do
    status=$(systemctl is-active $service)     # active / inactive / failed
    echo "$service: $status"
done

if [ -f /var/www/html/wp-config.php ]; then
    echo "wp-config.php: found"
else
    echo "wp-config.php: MISSING"
fi

code=$(curl -s -o /dev/null -w "%{http_code}" http://localhost/)
echo "Web page HTTP code: $code"              # 200 or 302 is good
bash · run it
bash check_site.sh
sample output
apache2: active
mysql: active
wp-config.php: found
Web page HTTP code: 302

How it works

  • The for loop runs systemctl is-active for both services and prints the answer.
  • [ -f file ] is true if the file exists.
  • curl -s -o /dev/null -w "%{http_code}" asks for the page, throws the page away and prints only the HTTP status code.
  • 302 is normal for a new install: WordPress redirects you to its setup page. 200 is also good.
Optional: going further (your own domain with a virtual host)

Use cases 1 to 3 use Apache's default site in /var/www/html. To host a site under a name such as blog.example.com, create a virtual host file with a heredoc and enable it:

bash · add_vhost.sh
#!/bin/bash
# add_vhost.sh: serve /var/www/html under a domain name
# usage: sudo ./add_vhost.sh blog.example.com
domain=$1

cat > /etc/apache2/sites-available/$domain.conf <<CONF
<VirtualHost *:80>
    ServerName $domain
    DocumentRoot /var/www/html
    <Directory /var/www/html>
        AllowOverride All
    </Directory>
</VirtualHost>
CONF

a2ensite $domain.conf          # enable the new site
a2enmod rewrite                # needed for WordPress "pretty" links
apache2ctl configtest          # check for mistakes: should print "Syntax OK"
systemctl restart apache2

a2ensite links the file from sites-available into sites-enabled; only enabled sites are loaded. Always run apache2ctl configtest before restarting.

Viva / exam questions

What does LAMP stand for?

Linux (operating system), Apache (web server), MySQL (database), PHP (programming language WordPress is written in).

Why do we use -y with apt install in a script?

It answers "yes" automatically. Without it, apt waits for the user to type Y and the script would stop.

What is a heredoc?

A way to give several lines of text as input to a command: command <<WORD, then the lines, then WORD alone on a line. We use it to send SQL to mysql.

Why does the script check for root?

Installing packages, writing to /var/www and managing services need root rights. Checking first gives a clear message instead of many confusing errors.

What is in wp-config.php?

The database name, user, password and host that WordPress uses to connect to MySQL, plus secret keys and other settings.

What does sed "s/old/new/" file do? What does -i add?

It prints the file with the first "old" on each line replaced by "new". With -i it changes the file itself instead of printing.

Why must the WordPress files be owned by www-data?

Apache and PHP run as the user www-data. WordPress needs to write files (uploads, updates), which only works if that user owns them.

What does systemctl enable --now apache2 do?

enable makes Apache start at boot; --now also starts it immediately.
