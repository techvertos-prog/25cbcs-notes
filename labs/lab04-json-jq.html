Lab 04: Working with JSON in Bash scripts using jq

Many tools and web APIs send their data as JSON. Bash cannot read JSON by itself, so we use a small helper program called jq. In this lab you learn to print JSON, pick values out of it, filter it, and use those values in simple Bash scripts. For the full jq language see the jq tutorial.

Commands: jq, read, whileDifficulty: beginner~45 minjq 1.7

Aim and objectives

Aim: read and use JSON data in Bash scripts with jq.

  • Print a JSON file and pick single values out of it.
  • Print one value from every item of a list, and filter items with select.
  • Use jq's output inside a Bash while read loop.
  • Save JSON data as a CSV file, and change a value in a JSON file safely.

Prerequisites

bash · install jq
sudo apt install -y jq     # Ubuntu / Debian   (sudo dnf install -y jq on Fedora / Rocky)
jq --version               # should print jq-1.6 or newer

Open a terminal in the wiki folder, so that the path datasets/ works. Basic Bash (variables, if, while) is enough.

Start here: simple scripts

Each script below adds one new idea. Save it as the given file name, then run it with chmod +x name.sh and ./name.sh (or simply bash name.sh).

Step 1: print a JSON file

bash · j1_pretty.sh
#!/bin/bash
# Step 1: print a JSON file in a nice, coloured, indented layout
# '.' is the simplest jq filter: it means "the whole input, unchanged"
jq '.' datasets/servers.json | head -15     # head: show only the first 15 lines

Step 2: pick single values

bash · j2_first.sh
#!/bin/bash
# Step 2: pick single values out of the first user
file="datasets/users.json"
jq '.[0].name' "$file"              # .[0] = first item of the array, .name = its name
jq -r '.[0].name' "$file"           # -r = raw: print it without the quotes
jq -r '.[0].address.city' "$file"   # go deeper: address -> city
jq 'length' "$file"                 # how many users are in the array?
bash · run
./j2_first.sh
output
"Aarav Verma"
Aarav Verma
Mumbai
12
  • users.json is an array (a list). .[0] is the first item; counting starts at 0.
  • .name picks a key from an object; you can chain keys: .address.city.
  • Without -r strings keep their quotes. Use -r (raw) whenever the value goes into a Bash variable.

Step 3: one value from every item

bash · j3_all_names.sh
#!/bin/bash
# Step 3: print one value from EVERY user
# .[] means "each item of the array", | passes each item to .username
jq -r '.[] | .username' datasets/users.json | head -5
bash · run
./j3_all_names.sh
output
averma
psharma
rmehta
adas
vdas
  • .[] walks through the array and outputs each user one by one.
  • The pipe | inside jq sends each user to the next filter, .username.
  • Result: one username per line, which is easy to use in Bash. head -5 just shortens the output.

Step 4: filter with select

bash · j4_select.sh
#!/bin/bash
# Step 4: keep only the items that match a condition
file="datasets/users.json"
echo "Inactive users:"
jq -r '.[] | select(.active == false) | .username' "$file"
echo "Users in Pune:"
jq -r '.[] | select(.address.city == "Pune") | .name' "$file"
bash · run
./j4_select.sh
output
Inactive users:
averma
psharma
rsingh
Users in Pune:
Rohan Mehta
Isha Nair
  • select(condition) keeps an item only if the condition is true, like if for JSON.
  • Compare with ==, !=, >, <. Text values need double quotes inside the filter: "Pune".

Step 5: use jq output in a Bash loop

bash · j5_loop.sh
#!/bin/bash
# Step 5: use jq's output inside a Bash loop
count=0
jq -r '.[] | .username' datasets/users.json | while read -r user; do
    count=$((count + 1))               # add 1 for each user
    echo "$count. Hello, $user"        # use the value like any Bash variable
done
bash · run
./j5_loop.sh
output

2. Hello, psharma
3. Hello, rmehta
4. Hello, adas
5. Hello, vdas
6. Hello, sdas
7. Hello, akapoor

10. Hello, inair

  • jq -r prints one username per line; while read -r user reads one line per loop turn.
  • Inside the loop, $user is a normal Bash variable.
  • Use while read, not for x in $(jq …): the for version splits "Aarav Verma" into two words.

Concepts

JSON in one minute

JSON has objects {"key": value}, arrays [1, 2, 3], strings in double quotes, numbers, true/false and null. Objects and arrays can be nested inside each other.

Saving jq results in Bash variables

bash · command substitution
total=$(jq 'length' datasets/users.json)
dc=$(jq -r '.datacenter' datasets/servers.json)
echo "There are $total users. Datacenter: $dc"
output
There are 12 users. Datacenter: blr-1

Passing a Bash variable into jq

Do not paste Bash variables into the filter text. Give them to jq with --arg, then use them as $name inside the filter:

bash · --arg
city="Delhi"
jq -r --arg c "$city" '.[] | select(.address.city == $c) | .username' datasets/users.json
output
psharma
akapoor
knair

Building JSON with jq -n

To create new JSON from Bash variables, let jq do it. jq adds the quotes and escaping for you, so the result is always valid JSON, even when a value contains a quote:

bash · jq -n --arg
name='Ravi "RK" Kumar'
city="Pune"
jq -n --arg n "$name" --arg c "$city" '{name: $n, city: $c, active: true}'
output
{
  "name": "Ravi \"RK\" Kumar",
  "city": "Pune",
  "active": true
}

Missing keys

If a key does not exist, jq prints null instead of an error. Use // to give a default value:

bash · null and default
jq -r '.[0].phone' datasets/users.json
jq -r '.[0].phone // "no phone"' datasets/users.json
output
null
no phone

Use cases

Use case 1 User report with CSV export

Scenario: your manager wants a quick summary of the user list: how many users are active, who the admins are, and a CSV file to open in a spreadsheet.

bash · user_report.sh
#!/bin/bash
# user_report.sh - simple report about the users in a JSON file
# usage: ./user_report.sh [file]
file="${1:-datasets/users.json}"      # use $1, or the dataset if no argument

if [ ! -f "$file" ]; then             # stop if the file does not exist
    echo "Error: $file not found"
    exit 1
fi

total=$(jq 'length' "$file")
active=$(jq '[.[] | select(.active == true)] | length' "$file")
echo "Total users : $total"
echo "Active      : $active"
echo "Inactive    : $((total - active))"

echo "--- Admins ---"
jq -r '.[] | select(.roles | index("admin")) | .username + " (" + .email + ")"' "$file"

# Save a CSV file that opens in Excel / LibreOffice
jq -r '.[] | [.username, .name, .address.city, .storage_mb] | @csv' "$file" > users.csv
echo "Saved users.csv ($(wc -l < users.csv) rows)"

chmod +x user_report.sh
./user_report.sh

How it works:

  • ${1:-datasets/users.json} means "use the first argument, or this file if none was given".
  • [.[] | select(.active == true)] | length collects the active users into an array and counts it.
  • .roles | index("admin") finds "admin" inside the roles list (no match gives null, which counts as false).
  • [ … ] | @csv turns each user into one CSV line with correct quotes.

Use case 2 Server health check

Scenario: a monitoring tool saves servers.json every few minutes. Write a script that prints OK, WARN or CRIT for every server, using a limit you can change.

bash · server_check.sh
#!/bin/bash
# server_check.sh - warn about servers with high disk or CPU usage
# usage: ./server_check.sh [limit]      (default limit: 80 percent)
limit="${1:-80}"
file="datasets/servers.json"
problems=0

# jq prints one line per server: name disk cpu status
jq -r '.servers[] | "\(.hostname) \(.disk_pct) \(.cpu_pct) \(.status)"' "$file" > servers.tmp

while read -r name disk cpu status; do
    if [ "$status" != "running" ]; then
        echo "CRIT  $name is $status"
        problems=$((problems + 1))
    elif [ "$disk" -gt "$limit" ] || [ "$cpu" -gt "$limit" ]; then
        echo "WARN  $name disk=${disk}% cpu=${cpu}%"
        problems=$((problems + 1))
    else
        echo "OK    $name"
    fi
done < servers.tmp

rm servers.tmp
echo "Servers with problems: $problems"
bash · run with the default limit (80), then with 60
./server_check.sh
echo "-----"
./server_check.sh 60 | tail -4
output
OK    web01
CRIT  web02 is stopped
WARN  web03 disk=82% cpu=64%
OK    db01
CRIT  db02 is stopped
WARN  cache01 disk=82% cpu=17%
OK    lb01
CRIT  mon01 is degraded
Servers with problems: 5
-----
WARN  cache01 disk=82% cpu=17%
WARN  lb01 disk=60% cpu=61%
CRIT  mon01 is degraded
Servers with problems: 7

How it works:

  • jq prints name disk cpu status on one line per server; \(.hostname) inserts a value into a string.
  • The lines are saved in servers.tmp and read with while read -r name disk cpu status: read splits each line into four variables.
  • We read from a file (done < servers.tmp) instead of a pipe, so the problems counter still has its value after the loop.
  • -gt compares numbers, != compares text.

Use case 3 Changing a value in a JSON file

Scenario: server web02 was repaired. Mark it as running in the JSON file. We practise on a copy, servers.copy.json.

bash · set_status.sh
#!/bin/bash
# set_status.sh - change the status of one server inside a JSON file
# usage: ./set_status.sh HOST STATUS [file]
host="$1"
status="$2"
file="${3:-servers.copy.json}"

if [ -z "$host" ] || [ -z "$status" ]; then
    echo "Usage: $0 HOST STATUS [file]"
    exit 1
fi

# --arg passes the Bash variables into jq safely as $h and $s
# jq cannot edit a file in place, so write to a temp file first ...
jq --arg h "$host" --arg s "$status" \
   '(.servers[] | select(.hostname == $h) | .status) = $s' "$file" > temp.json

# ... and replace the original only if jq succeeded
if [ $? -eq 0 ]; then
    mv temp.json "$file"
    echo "Updated $host -> $status"
else
    rm -f temp.json
    echo "jq failed, $file was not changed"
fi
bash · run
cp datasets/servers.json servers.copy.json
./set_status.sh web02 running
jq -r '.servers[] | select(.hostname == "web02") | .status' servers.copy.json
./set_status.sh
output
Updated web02 -> running
running
Usage: ./set_status.sh HOST STATUS [file]

How it works:

  • (… | .status) = $s finds web02's status and sets it to the new value.
  • jq has no "edit in place" option. jq … file > file would empty the file, because Bash clears it before jq reads it. So we write to temp.json and then mv it over the original.
  • $? holds the exit code of the last command: 0 means jq worked.

Viva / exam questions

What is jq?

A command-line program that reads JSON, lets you pick, filter and change parts of it, and prints the result. Bash has no JSON support, so scripts use jq for this job.

What does jq '.' do?

It prints the whole input unchanged but nicely formatted. It also checks that the input is valid JSON.

What is the difference between .[0] and .[]?

.[0] gives only the first item of an array. .[] gives every item, one after another.

Why do we use -r?

Raw output prints strings without the double quotes, which is what Bash variables and other commands expect.

What does select() do?

It keeps an item only when the condition inside is true, for example select(.active == true).

How do you pass a Bash variable into a jq filter?

With --arg: jq --arg c "$city" '.[] | select(.address.city == $c)'. Inside the filter the variable is $c.

Why is jq -n --arg better than building JSON with echo?

jq adds the correct quotes and escapes special characters, so the JSON is always valid. With echo, a value containing a quote breaks the JSON.

How do you change a value in a JSON file?

Run jq with an assignment and write to a temporary file, then move it over the original: jq '.a = 1' f.json > temp.json && mv temp.json f.json.

What does jq print for a key that does not exist?

null. Use .key // "default" to print a default value instead.
